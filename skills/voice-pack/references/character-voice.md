# A character's voice: best practices for making and using a pack

This is a reference for the base part of the voice pack. `SKILL.md` gives only the flow; the way to write what the flow asks for, and the reasons, are here. The format (five sections, and the items in each section) is specified in `references/make-pack.md`「The five sections of the dubbing guidance」; this file says only how to fill it in.

## One voice per character

A voice pack is one voice of one character, not split by scene. The audition line, a line in a dialogue, a multi-person scene, and long text are all uses; they go through the same pack, and no separate pack is made for each use.

The acting of each line comes from the emotion and style cues in the script. Which reference segment is used follows `references/dub.md`「How a line becomes synthesis」step 3 (the reference tag specified by the caller → the setup's `referenceTag` → the default segment for this line's language).

## Order of choosing a voice

When making a character's voice, go in this order and stop at the first one that applies:

1. The user supplied a recording of this character (spoken by the character's own voice, clean, at least 5 seconds): make the pack from it (how to use a recording: see "The character's materials" below).
2. The library has this character's own voice (same name, and it is the character's voice): do not design another; make the pack from it, and put it through the acted passage like a designed voice: make a temporary pack from this voice, dub an acted passage with it, and that passage is the reference segment (end of `references/make-pack.md`「Making a pack from a designed voice」). An entry the library labels with this character's name and this character's work, with high confidence, and whose gender and age do not contradict the character, is the character's own voice: what its recording happens to say or how it is delivered (a narration, an advertisement) is not a reason to pass it over. If it only has the same name and you are not sure it is this character, do not treat it as the character's own; go on.
3. Neither: design a voice (write the description with features that can be heard, and lock the audition). The locked audition is used only as raw material: dub an acted passage with it, that passage is the reference segment, and then clone from it (`SKILL.md` section 2「Voice design」).

If the library only has someone else with similar tags (language, gender and age match, but not this character), that also goes to item 3: the step of borrowing someone else's voice by tag is paused, because a borrowed recording mostly carries the original speaker's way of speaking (inference; on the first page one person listened to one character).

## The character's materials

- The character's text (novel, script, setup) and recordings (the original dubbing, or sample audio of the same person).
- With a recording, take the clone path: pick the reference from the recording, and the verbatim transcript comes from the recording, not written from memory.
- With only text, take the design path: write the description as below; the locked audition is used only as raw material, and the reference is an acted passage dubbed to match it ("Default segment").
- Extract the acting style and the lines from the materials, and after each one put its source: the original sentence or narrative passage in the materials, written as in the original; copy line originals as they are. What is not in the materials and is inferred from the type of person is written as "inference" and is not treated as a fact about the character. When written into the pack, each item of the acting style has only its content, with no source and no "inference" (the acting style is for the person writing the script to write cues from); lines still carry their source. A quoted original sentence inside a line must be findable in the materials.
- Language of the recording: when a recording is received and the user said what language it is in (or the source shows it, for example the original Japanese dubbing), and the character is wanted in another language (the audition line, or the lines to dub, are in another language), do not ask whether an accent is wanted and do not add another reference; dub as in "Language and accent" below. Do not guess what was not said: the make-pack and dubbing reports will say (same section).
- With only recordings and no text of the character: do not ask the user for the pack name; take it in this order: the character name the user gave when handing over the recording, the name of that voice in the library, the file name of the recording (without extension). When delivering, say where the pack name came from; to change it, give a new `--name` when issuing a new version. The dubbing guidance has only the `### 音色` (voice) section; the acting style and the lines have to be extracted from the character's text, and with no material they are not written. The recording's language and the reference tag are given when making the pack (`references/make-pack.md`「Segment tags」: for a segment with no tag given, the model names it when making the pack, and if it cannot, the segment name is used).

## Who the script is addressed to: words spoken face to face to the listener

Every script an agent writes for a voice is written as words this character says face to face to the listener: the design audition text, the acted passage dubbed to match it ("Default segment"), the audition line ("Audition line"), and the passage written when adding another language ("Add a reference segment in this language"). When making a new pack from an existing one (clean room), the design audition text, that default segment and the audition line are not included: the design audition text and the default segment are taken from the example lines, and the audition line is the one the clean-room writing session, which has not read the source pack, wrote into `output/card-line.txt` (`references/clean-room.md` steps 2 and 3). The example lines in the dubbing guidance are also not written by this section (the paragraph in `references/make-pack.md` about example lines). It is like a mascot character on the home screen of an anime-style game talking to the player: speak directly to the listener, with this character's personality, catchphrases and world. Who the listener is is told by the person who gave you the task (for example "the listener is the person who writes this character and is making the voice for it"); if not told, follow the item "the materials do not say who the listener is" below. Source: requirement, put forward by the author of `models/scene3.md`「Good examples」 on 2026-11-07, original words "You have to imitate what the character would say on meeting its creator. Something like the voice lines of those anime-game mascot characters." and "The form of address has to be inferred from the other in-world context and from the character card. So does who it is talking to." (The "creator" in the original words is the listener here.)

- Who the listener is in this character's eyes and how it addresses them are inferred from the materials: before writing, read all of the character's materials (the full text, and look at the images if there are any; the setup and world; the people it mentions and the materials that mention it).
- If the materials say who the protagonist, the player or "you" is (identity, name, gender, relationship with this character, for example its new intern, partner, master), the listener is that person, and the form of address follows how this character calls this kind of person, using the original words in the materials. Gendered forms of address (calling a man 「老弟」, "little brother", and a woman 「老妹儿」, "little sister") are used only when the materials make the gender clear.
- If the materials do not say who the listener is: treat them as someone it knows who has come to see it again (「又来啦」 "here again", 「回来了」 "you're back"), and use a form of address that does not need to know who the other is: 「你」 ("you"), or the form the materials show it uses for everyone (it calls all young people 「幺儿」, a Sichuan-style "kid"). Do not invent a title (commander, master, boss). Source: requirement, said on 2026-11-09 ("Q6 is right", answering exactly this item).
- The situation in the materials is background: where the character is and what it is busy with (a barbecue stall that is busiest at night, a meeting room at eleven o'clock). A passer-by in the situation (a customer who has just sat down) is not the one spoken to, unless the materials make the listener that person.
- Its world shows up as one concrete thing (the mutton that arrived today, tomorrow morning's deadline, the person it looks after), touched on and not explained; do not summarise who it is or what its world is like.
- Do not introduce itself (giving its name, age, what it does, where it is from), do not list what it can do, and do not speak to a third person, a group, or itself.
- Write words a real person would say at that moment. Example sentences quoted in the materials (the character's lines, dialogue samples) are used only for speaking habits (how it refers to itself, sentence endings, catchphrases, word choice); do not copy the sentences, and do not write procedures or steps into the lines (「按流程，接下来该听你说。」, roughly "By procedure, next it's time to listen to you.", is not something a person says). Source: requirement, said on 2026-11-10 after hearing such a line, original words "What is this script writing? 'By procedure, next it's time to listen to you.' Is that something a real person says?"
- If the materials say how this character relates to others (people it cares about, partner, rival) and the finished script mentions none of them: mention it in one sentence in the report handed back; do not block, and do not rewrite for it. Source: requirement, the item "relationship check changed to a reminder only" ticked on 2026-11-08.
- If there is only a description and no other materials: write from the description and the name, and for the listener follow the item "the materials do not say who the listener is" above.

## Default segment: a passage the character says naturally, with acting

The default segment is how this voice "normally speaks": if the character speaks several languages, each language has one passage; when neither the caller nor the setup specifies a reference, dubbing uses the passage in the language of the line (`references/dub.md`「How a line becomes synthesis」step 3), so it sounds like this character. For the audition on the pack's preview card, both voices made from recordings and designed voices use a separately written line ("Audition line" below); if that line is not handed in, the card plays the recording of the main language's default segment, only as a fallback. How it is decided: see `references/make-pack.md`「Default segment and audition line」.

- **Voice made from recordings**：the default segment is a passage in the recording where the character speaks naturally and with acting; when making the pack, pick one per language: if the environment has a model that can listen to audio, ask it to pick, and the author can also name them with `--default-segment` (one per language, for several languages). The card plays a separately written line ("Audition line"); the recording of the main language's default segment is only a fallback when that line is not handed in. The default segment can be a regenerated one (marked `synthetic`), and when falling back, the card plays its recording too.
- **Voice made by design**：the default segment is an acted passage dubbed to match the locked audition (`SKILL.md` section 2「Voice design」step 5), and the pack that is handed over has only this one as its reference. The audition read out during design is used only as raw material and does not go into the pack that is handed over: a designed voice is dry audio that has not been processed and is mostly read flat, and if it is used as the reference, every line afterwards would mostly be acted flat too (inference: the only voice listened to was one character in the first page's audition, listened to by one person, `models/scene3.md`「Reference segments」). This passage is written in the language the character will speak, the same one as the design audition text and the audition line ("Design audition text when designing"); write it following "Who the script is addressed to" above, like a few voice lines in a row on a home screen: a line said on seeing the listener, then a small matter of its own (what it is busy with, its craft, the person it worries about, in the way it normally talks about them), then a reaction (being stared at, being teased, the other person refusing to leave; it can respond as if the other really did that: `你瞅啥？`, a Northeastern Mandarin "what are you looking at?") or its own kind of concern; three or four moods, each with a different sentence length and ending, not one emotion from start to end. This passage must fit this character and act out what is most distinctive about it to the full (pick, from the character's materials, its most prominent temper, tone and what it cares about), and must not be a passage any character could read (requirement, put forward by the author of `models/scene3.md`「Good examples」 on 2026-11-10). The wording follows the dubbing guidance's `### 台词` (lines) section; the catchphrase appears once or twice in the whole passage, not in every sentence. Cues describe the way of speaking and the attitude, and do not use words for the texture of the voice or for an accent (husky, rough, Northeastern accent): this passage is the reference for every later line; on 2026-11-07, when these words were written into every cue, the voices of different characters actually became a little more alike (measured voiceprint), and the model's judgment also found no benefit (lead) (`models/scene3.md`「What to write」, the item on fine acting style). If there is only a description and no other materials, write from the description, the name and the dubbing guidance (same as "Audition line"); for making a new pack from an existing one (clean room), this passage is not written as above but is taken from the example lines already written, see `references/clean-room.md` step 3. Estimate the words to be read by speaking rate: ordinary speech at about 5 characters per second (one time on 2026-11-06: 57 characters dubbed to 11.3 seconds); where the acting style in the dubbing guidance has a slow speaking rate and uses `……`, estimate about 3 characters per second and write less, about 50 characters or fewer (one time on 2026-11-07, with a description saying the speaking rate is slow and cues that had slow cues and `……`: 67 characters dubbed to 21.0 seconds, over 20 seconds; shortened to 52 characters, it skipped the sentence after `……`, and the 35 characters actually read took 11.5 seconds). The readings are only these three from these two voices. Write cues where the way of speaking changes, each short and exact, following `models/scene3.md`「Good examples」; use every form the vendor documentation lists, in the right place (a laugh is written where the laugh is, one word to be stressed uses a paired tag, `models/scene3.md`「Cues」). The reference is a flat-read audition, so the acting in this passage is brought out by these cues: the state and cue of each clause are written following `models/scene3.md`「Where a cue is written and how far it reaches」›「Set the state first, then write the cue.」. How well the dubbed result acts has not been measured (`models/scene3.md`「What it accepts and what it does not」). The card does not play it; it plays the separately written line ("Audition line").
- **Voice from the voice library**：like a designed voice, the default segment is an acted passage dubbed with this voice from the library, and the script and the expressiveness are the same as above (end of `references/make-pack.md`「Making a pack from a designed voice」). A recording supplied by the user does not go through this step.
- The script of this passage has the character's name at the very start of every line, the same as the pack's name (`--name`) (`models/scene3.md`「Put the character name first」).
- Length 10 to 20 seconds, complete and coherent sentences, a consistent speaking rate throughout, and no long pause in the middle. Not over 20 seconds: if a reference is over 20 seconds, the model cuts it somewhere between seconds 12 and 20, the text given is no longer used and the model's own transcription is used instead (`models/scene3.md`「Reference segments」), and every later line then uses what is left after the cut. A dubbing result longer than 20 seconds is not redone: make-pack cuts at a sentence end within 20 seconds and uses the earlier piece (keeping at least 10 seconds), and the verbatim transcript is cut to match (`references/make-pack.md`「Making a pack from a designed voice」step 2; source: requirement, said by the author on 2026-11-08, original words "Didn't I object from the start to that logic of designing twice, checking automatically, and redrawing when it doesn't match? The flow is painfully slow! Write the skill properly!"). Punctuation follows the effect you want to hear (`models/scene3.md`「Punctuation」). A hesitating `……`: write it if the character would hesitate at that point, once or twice; not stammering everywhere or hesitating everywhere: acting follows the reference (inference: one person listened on the first page, and other voices are inference, `models/scene3.md`「Reference segments」); whether a reference full of stammering would make every later line stammer has not been tested and is inference. The words after `……` are occasionally dropped (model judgment, nobody has checked it, `models/scene3.md`「Punctuation」); do not use `……` alone as a pause.
- The acting is how this character normally speaks: natural, like talking to a person, not one whole passage pressed onto a single extreme emotion, and not reading from a script flatly. The acting in the reference mostly carries over to every later line (inference: one person listened to one set, and the other set is a model judgment, lead, see `models/scene3.md`「Reference segments」).
- Use a spoken tone, like speaking face to face: no semicolons, maxims, parallelism or scenery description, and no narrating past events like a narrator (inference that these would make the reference read like reading aloud, and every later line would read the same way; only the model judged whether it sounds like reading aloud, and nobody has listened to it).
- Name the default segment with `--default-segment`: see `references/make-pack.md` for the syntax; for a design, see "Making a pack from a designed voice", and for a recording, see "Recordings supplied by the user".

## Design audition text when designing

For a designed voice, the audition read out during design is used only as raw material: it is used as the reference when dubbing the default segment, and it does not go into the pack that is handed over (`SKILL.md` section 2「Voice design」). Write the design audition text this way:

- Language: the design audition text, the acted passage dubbed to match it ("Default segment"), and the audition line are all written in the language the character will speak, and all three are the same language (otherwise dubbing that passage and dubbing the audition line would be cross-language and the command stops); the language to speak follows the language the user chats in, and you do not ask ("Language and accent").
- Words this character says face to face to the listener ("Who the script is addressed to" above), in its own words and manner; not a self-introduction (giving its name, age, what it does, where it is from).
- Use the character's own tone: put in the catchphrases and sentence endings from the character's materials (the way it refers to itself, sentence endings and catchphrases in the dubbing guidance's `### 台词` section), with no square-bracket cues. The reason and the source are in the design model notes, section "Design audition text".
- Write words a person says face to face: with the modal particles a person would use at that moment (「来了啊」, 「酒钱啊」: sentence-final particles that only work in Chinese), colloquial words (「挪挪」 "shift over", 「甭管」 "never mind"), and about the thing in front of them and what the hands are doing (asking the other to sit down, moving toward the edge of the stove); no maxims, parallelism or bookish words (「潮水不等人，可也不催人」 "the tide waits for no one, but does not rush anyone", 「莫慌」 "don't panic", 「再迈」 "step again"), and no semicolons or scenery description (same as "Default segment" above). For a young female voice (under 30), use only the modal particles that are in the materials and do not add any (the reason is in the source below). Two pairs that were listened to, the first line of each pair being the original wording and the second the revised one:
  - A 60-year-old blacksmith: `来啦。莫慌，炉子还热着，你先坐下歇会儿。葛三娘那壶烧酒，我迟早给她还上。` revised to `来了啊。坐吧，往炉子边上挪挪，暖和。葛三娘那酒钱啊，回头我给她送过去，你甭管。`
  - A 50-year-old captain (this revised line is better than the original but still not good enough, and is not taken as a model; see the source below): `哟，你来啦？别急，慢慢上船，脚下的缆绳湿，踩稳了再迈。潮水不等人，可也不催人。` revised to `哎，来啦？上来上来。慢点儿啊，那绳子湿的，踩旁边那块板儿。哎，对喽，坐吧，不着急。`

  Source: on 2026-11-09 one person listened to the audition designed for these two characters (conclusion): both revised lines are better than the originals; the blacksmith's is somewhat better (they did not ask further what it still lacked), and the captain's is still not enough, and the problems picked were that the lines do not sound like a person speaking, the rhythm drags, and the pauses are odd. At the same time the description was changed to write only timbre (design model notes "How to write a description", first item), so two things were changed together and which one made the difference cannot be separated; the modal particles, colloquial words and removal of bookish words are literal differences present in both revisions; maxims and parallelism were only in the captain's original; the other points (the thing in front of them and what the hands are doing, no semicolons or scenery description) were already like this in the original wording, so they are not a difference of this change. Which points made the difference was never separated and is inference. What the captain's line has more than the blacksmith's: about the same length (31 and 32 characters) but cut more finely (10 clauses against the blacksmith's 7), repetition (「上来上来」 "come on up"), and filler inside a sentence (「哎，对喽」 "ah, that's right"); whether the problems that were picked came from these was not separated and is inference, so these were not written into the way of writing above, and you should not pile them up by following it. Only these two Chinese-speaking middle-aged or older male voices were listened to: that younger voices, female voices, voices with an accent, and voices speaking other languages should also be written by this item is inference. For young female voices there is a model judgment in the opposite direction on modal particles (the age heard, nobody has checked it): of 4 young female voices whose design audition text had 「哎呀」, 「嘛」 and 「就行啦」, 3 were heard as too young (2026-10-30 and 10-31, with the description still in the old way of writing, see design model notes section "Design audition text"); the two ways of writing were not compared on young female voices, so this model judgment is followed for now, and modal particles that are not in the materials are not added.
- Write an amount that can be read through comfortably in about 10 seconds: about 40 Chinese characters, or about 25 English words, and do not write toward 20 seconds. Reason: for the two voices designed on 2026-11-06, design audition texts of 66 and 61 characters were both read in about 10.5 seconds, about 6 characters per second (reading); the relation between character count and speaking rate has not been measured. A clone mostly reads at the rhythm of the reference (inference): for packs made by using these two auditions directly as the reference, the audition line came out at only 3 to 4 seconds (measured duration), short of the about 5 to 8 seconds that "Audition line" asks for. On the same day another voice was designed, and its 41-character audition was read in 7.0 seconds, also about 6 characters per second. There are only these three; whether about 40 characters is read comfortably cannot yet be said.

## Audition line

The audition line is a line written by the agent from the character's materials; when making the pack, it is dubbed with this pack's own voice and stored in the pack, and it is what the pack's preview card plays. It is the same for a designed voice and a voice made from recordings: both hand in this line when making the pack. For a designed voice, the reference and the default segment are the acted passage dubbed to match the audition ("Default segment"), and this line is also dubbed from it; the audition read out during design is mostly flat (inference; the only one listened to was one character, `models/scene3.md`「Reference segments」) and does not go into the pack or onto the card: a flat reading is not put on the card, and this line is written by the agent from the character's materials. For a voice made from recordings, what is said in the recording does not match the situation the audition line needs, so a line is also written from the materials and dubbed with the pack, and a passage from the recording is not put directly on the card. If this line is not handed in, the card plays the recording of the main language's default segment, only as a fallback. The exception for making a new pack from an existing one (clean room): this line is not written or edited by an agent that has read the source pack; the line the clean-room writing session, which has not read the source pack, wrote into `output/card-line.txt` following the brief is handed in as is with `--card-line` (`references/clean-room.md` steps 2 and 3); the way of writing below is for when the clean room is not used and the agent writes this line itself.

- It is one line this character says face to face to the listener ("Who the script is addressed to" above), like one voice line on a home screen: one mood, containing a form of address, one concrete thing from its world, and a catchphrase or a sentence ending. The mood at this moment is taken from the materials, and the situation in the materials is where it is and what it is busy with at this moment. If there is only a description and no other materials, write from the description and the name.
- The wording follows the way of referring to itself, sentence endings, catchphrases and word choice in the dubbing guidance's `### 台词` section.
- The character's name is written at the very start, the same as the pack's name (`--name`) (`models/scene3.md`「Put the character name first」).
- Cues follow `models/scene3.md`「Good examples」, using every form the vendor documentation lists, in the right place (`models/scene3.md`「Cues」): an acting cue at the start that says an emotion that fits this character at this moment; the state and cue of each clause in one or two sentences follow `models/scene3.md`「Where a cue is written and how far it reaches」›「Set the state first, then write the cue.」; one word to be stressed is wrapped in a paired tag (`<emphasis>…</emphasis>`); a laugh or a sigh is written where it happens (`[small laugh]`, `[sighs]`). Each acting cue is two or three words, in English, short and exact, for example `[happy, bright voice]`, `[gentle, slowing down]`, `[shy, soft voice]`, not written as a sentence; the situation in the materials, the physical action, what this sentence is doing, whom it is said to, and how it wants the other to react are not written into the square brackets; write how it lands in the voice, and write only what can be heard with the eyes closed (`models/scene3.md`「What to write」). An acting cue says how this line sounds: one emotion or voice state, for example `[calm]`, `[warm, relaxed]`. The card wants the character's usual voice: do not press the key of the whole line toward whispering, and do not write a `<whisper>` that wraps the whole line, unless the situation in the materials is itself a whisper; a volume or speed change at one point is still written (`[displeased, hushed voice]`, `[gentle, slowing down]`). Readings: `[quietly]` was measured once, with a weak reading, and may make this line breathier and softer with a flatter pitch; `<whisper>` was measured on one line and one seed, voiced portion fell from 54% to 22% and loudness was about 6 dB lower, sounding like a whisper, and nobody has listened to it (`models/scene3.md`「What to write」「Paired tags」). If the mood at this moment is tired or sleepy, still write it (`[tired, drowsy]`). A character who normally speaks softly gets that across by wording. Onomatopoeic words are not written into a cue (they may be read out); for a laugh, write it where the laugh is (`[small laugh]`) or write the way of speaking (`[smiling voice]`) (`models/scene3.md`「Sudden sounds and pauses」). For the syntax see `references/markup.md` and `scenes/one-line.md` step 3.
- Punctuation follows `models/scene3.md`「Punctuation」. The card shows the text of this line, and the same punctuation mark repeated (`？？`, `！！！`, `～～`, `!!!`) is not used; for English questions choose the punctuation by the tone wanted: a single `?` sounds like an interrogation, and `?!` sounds like surprise or doubt; `?!` is allowed, and the audition line check in make-pack does not block it (requirement, the author, 2026-11-09: "For English I think it's the punctuation that affects the emotion; a single question mark sounds more like an interrogation, ?! sounds more like surprise, doubt, and so on"; one pair of `?` and `?!` was listened to, once for each); a Chinese question has only a single `？`, the model judges the sentence end mostly goes down (lead, nobody has listened to it), and for the questioning tone write what exactly changes in the voice at this point, and do not write names of sentence types such as `[反问]` (rhetorical question) or `[疑问]` (question) (`models/scene3.md`「What to write」); for an English single `?` the measured sentence end goes up (the pair with the biggest difference that one person listened to, audible; the model judgment that it rises is only 4/9, a lead).
- Pronunciation is not written as a phoneme tag: the text of this line is stored in the manifest as it is and written on the card (`protocol/lib/preview-card.mjs`), and if a phoneme tag were written, the card would show only pinyin or phonetic symbols. To change a pronunciation, write it into the pack's pronunciation lexicon (`--lexicon`, `references/make-pack.md`「Pronunciation lexicon」); when dubbing this line it is read as the lexicon says, and what is stored is still the original word.
- One or two sentences, about 5 to 8 seconds when read out: not longer than the share file's card can hold (`PREVIEW_MAX_SECONDS` in `protocol/lib/preview-audio.mjs`), so that it can be played in full.
- Do not read out the design audition text, and do not write a self-introduction (a greeting that gives the name, age, what it does, where it is from), unless the situation in the materials is itself a self-introduction.
- When writing, write to two things: whether this character would say this on meeting the listener face to face; and whether it fits the world in the materials and the mood at this moment.

Save the finished line as a text file and hand it in when making the pack with `--card-line <file.txt>`. How it is dubbed, what to do when it is not dubbed, and how a new version carries it over: see `references/make-pack.md`「How to give the audition line」.

## Emotional lines

Making a pack does not clone emotional lines: for a designed voice, the only material for the official pack is the acted passage dubbed to match the audition; for a recording supplied by the user, making the pack once is all (`references/make-pack.md`「Recordings supplied by the user」). A clone mostly copies the acting in the reference, so "happy" and "angry" cloned from a flat-read reference mostly still come out flat (inference, see `models/scene3.md`「Reference segments」).

A pack can hold several reference segments with different emotions and ages (for example several regenerated ones from the library), each with a reference tag (the material's `tag`, `references/make-pack.md`「Segment tags」), used only to switch between these segments.

- `dub` does not pick a reference segment by emotion; the emotion, style and energy cues in the script do not change the reference; which segment is used follows `references/dub.md`「How a line becomes synthesis」step 3. When neither the user nor the setup specifies one, picking by tag is the agent's job (`scenes/one-line.md` step 4): if the character is angry in the script and the pack has the "愤怒" ("anger") segment, hand it to `dub` with `--reference-tag`. Emotion is handed to the model through the cues in the script.
- A character who is written as "raising the voice" or "lowering the voice", such volume: write it on that line in the script, and do not rely on switching the reference segment. Volume is not listed as a separate item of the acting style.
- The lines of the script follow the dubbing guidance's `### 台词` section (the way of referring to itself, sentence endings, catchphrases). How many dialect words to put in the lines, including how to write when the materials say outright that the accent is not strong, follows `models/scene3.md`「Cross-language and accent」step 2. For a character with an accent, the features of the accent are recorded in the dubbing guidance ("Features of an accent" below); when writing the script, write by those features, and write the lines as the dialect's own words (`models/scene3.md`「Cross-language and accent」); when the accent is written in the design description, the design model often cannot produce it (model judgment, nobody has checked it; design model notes "How to write a description"). For the accent of the language in the reference (a Japanese reference reading English), the `[native English pronunciation]` and `<english>` that were listened to did not suppress it (one person listened, small sample); the current practice is in "Language and accent" below.
- A dialect or accent was dubbed and the user says some point did not come out: write more of the features of that point (more of the dialect's own words and modal particles, as recorded under "Features of an accent"), or write the same feature with a different kind of cue (change a square-bracket acting cue into a paired tag, or the other way round, `models/scene3.md`「Cues」), and dub this line again. Source: a practice already used on another platform, carried over; the effect has not been measured.

## Language and accent

**No accent by default; an accent must be chosen or confirmed by the user.** There are two paths, and in both the lines are written in the target language (requirement, said on 2026-11-06 and 11-10, original words "By default there should be no accent, unless the user manually chose it or confirmed they want an accent" and "Write it inside [], and then the text is in the target language; it's the same operation with an accent too"):

| Path | When | What the script writes | Option | What has been listened to | Does it hurt the timbre |
|---|---|---|---|---|---|
| Remove the accent (default) | The reference is in another language and the user did not ask for an accent | Write a name pair at the start of each line, and `dub` writes the language cues for both sides (the first paragraph below; syntax in `models/scene3.md`「Cross-language and accent」) | `--allow-cross-language` | One English reference speaking Chinese, listened to by one person, who settled on this way of writing ("Each has its own timbre leakage and unnaturalness. Forget it, I'm not listening any more, just go with 庚's way of writing"); other language pairs have not been listened to | Yes: the several ways of writing that were listened to "each has its own timbre leakage and unnaturalness" |
| Want an accent | The user wants this character to speak with some accent | Write the name at the start, then one square bracket saying which accent is wanted (`[English accent]`, a syntax example), and write the lines as usual | `--allow-cross-language --no-language-marks` | 4 English voices saying the same Chinese sentence, with an accent cue added at the start of the sentence, 3 brought out the accent (2026-11-05, one person listened) | Yes: the timbre of all 4 voices in the same run drifted |

When handing back, say truthfully which path was used and that it was dubbed cross-language, and ask the user to listen; if the user says the accent did not come out, dub again following the item in "Emotional lines" above about a dialect or accent that did not come out; if the user says the accent was not removed, say truthfully the range that has been listened to (the table above); if there is a recording of this character speaking this language, a reference segment in this language can be added ("Add a reference segment in this language" below).

The voice's language follows the language the user chats in, not the audio (requirement, put forward by the author of `models/scene3.md`「Good examples」 on 2026-11-10). When the reference is in another language, do not ask and do not add another reference: write the lines in the target language, still give `--allow-cross-language`, and write a name pair at the start of each line, `[name in the reference language|name in the line's language]` (`[Harry Potter|哈利·波特][这一刻的说戏]台词`, that is, name pair, then the acting cue for this moment, then the line); the names and the language cues on both sides are written by `dub` (`models/scene3.md`「Cross-language and accent」); the two names are taken from the `- 名字：` (name) item of the dubbing guidance's `### 换语言时怎么说` section; if that item is `缺`, make one up on the spot and tell the user it was made up on the spot. When the user wants an accent, write that accent (`[English accent]`, a syntax example, not tested), add `--no-language-marks`, and do not write a name pair. Square brackets say what to hear and not what to avoid; negations such as `no`, `not`, `without` are not written (`models/scene3.md`「What to write」).

Dubbing learns the voice from the reference, and also learns its language: with a Japanese recording as the reference, reading English is often English with a Japanese accent (inference, one person listened, small sample), and the `[native English pronunciation]` and `<english>` that were listened to did not remove it (`models/scene3.md`「Cross-language and accent」). This reading is kept; for the current way of writing, the only thing listened to is an English reference speaking Chinese (`models/scene3.md`「Cross-language and accent」). When handing back, say truthfully that these lines were dubbed cross-language, and ask the user to listen.

- Recognising the language, comparing, stopping, and listing which lines are affected are all done by the command: when the reference segment `dub` uses is not in the language of the line, it stops before spending any money and reports `dub_cross_language`, and dubs nothing; `--dry-run` reports it too (`references/dub.md` step 3「No accent by default.」); dubbing the audition line when making the pack is the same: it is not dubbed, and "what material is still missing" has `card_line_cross_language` (`references/make-pack.md`「How to give the audition line」).
- If it was reported, the option was missed: do not ask the user; write the name pair as above, add `--allow-cross-language` and dub again; for the audition line, issue a new version and dub again with `--previous <pack directory of this version> --card-line <file.txt> --allow-cross-language`.
- The user wants an accent and wants it more obvious: follow `models/scene3.md`「Cross-language and accent」 to find out the exact features of this accent and write the lines as the dialect's own words; for the effect of writing this way, only Cantonese and Sichuan Mandarin were listened to, by one person on 2026-11-08 (one voice, one sentence for each way of writing, `models/scene3.md`「Cross-language and accent」); other dialects and accents other than dialects have not been tested.
- The user themselves wants a reference segment in this language added (not added by default, and not offered unprompted): hand it in as material and issue a new version with `make-pack --previous <pack directory of this version>` (`references/make-pack.md`「Release a new version」), then dub with the new version; hand in `--card-line` at the same time for the audition line. Where the reference comes from and how it is dubbed: see "Add a reference segment in this language" below.

  If the report says the pack in fact has a reference segment in this language (`hasLanguage` is `true`), do not use this option and handle it as the report says. If the tag and the language were given by you (you picked the tag following `scenes/one-line.md` step 4 item 3, and `--language` was given by you to keep a passage in one request), explain that it should be changed to whichever tag exists in this language, or not give `--language`; if the user named it or the setup wrote it (the setup's default reference, the language the setup wrote), ask the user whether to change it; a merged scene has to be dubbed separately (`--no-scene`), and the gains and losses of separating are explained (`scenes/a-scene.md`「Merging and splitting」) before the user decides.
- If a language mismatch can already be seen at the moment the recording is received, do not ask either; add this option when making the pack.
- The lines the user gave are in another language and the user wants this character to speak them: dub as above. Do not take it on yourself to translate the lines into the language of the pack, and do not switch to another pack.
- A few words of another language inside one line (an English sentence inside a line of Chinese) is mixed speech, and the command does not stop and dubs as usual; it stops only when the whole line changes language.

### Add a reference segment in this language

When the user themselves wants a reference segment in this language added (not added by default, above), where the reference comes from: if there is a recording of this character speaking this language, use the recording (item 1); if not, by default dub with this pack itself, as in item 2. Item 3 (another voice in the library) and the other-model item below (only when the platform can specify a model) are listed to the user, and are taken only if the user picks them.

1. The user has a recording of this character speaking this language: use the recording and hand it in as material (how to use a recording: see "The character's materials" above).
2. No (the same for a designed voice, and the same for a pack already made that needs another language added): by default use this pack itself to dub a passage in this language across languages, as the reference segment for this language. This step does not first ask whether an accent is wanted, and does not first switch to another model; before dubbing, tell the user in one sentence: dubbed this way, it may carry a bit of the accent of the original language.
   1. Write a passage in this language, written as in "Default segment" above (10 to 20 seconds, written following "Who the script is addressed to" as a few sentences said face to face to the listener, with cues written as usual), and save it as a script file.
   2. Dub it with this pack (name pair at the start of that passage, `models/scene3.md`「Cross-language and accent」): `node cli.mjs dub <pack directory of this version> <that passage.txt> --language <this language> --allow-cross-language --no-setup --out <output directory> --adapter <adapter>`. `--no-setup` means no setup from the pack is used (the one marked with `default` is not applied either): what is wanted is the voice itself, without the setup's emotion, notes and speaking rate, with the reference being the default segment of the pack's main language, not the default reference the setup wrote. First add `--dry-run` to look at the plan, and check that it is one request (the text output says "共 1 句", that is, "1 sentence in all").
   3. Use the first one dubbed, do not let the user pick, and do not pick by speaker similarity (the speaker model also picks up language and accent, and the more it resembles the reference in the original language, the heavier the accent may be, `models/scene3.md`「Cross-language and accent」). One longer than 20 seconds is also not redone (reason in "Default segment"): write `scriptText` (the original script text) in the material, which make-pack uses to cut at a sentence end. Hand it in as material: copy `001-<reference segment>.<extension>` in the output directory to `audio/<segment name>.<extension>` next to the material, and write the material as `{ "segments": [{ "id": "<segment name>", "audio": "audio/<segment name>.<extension>", "language": "<this language>", "synthetic": true, "scriptText": "<original script text>" }] }` (`references/make-pack.md`「Regenerated reference segments」). The segment name must not repeat one from the previous version (removed ones count too). Do not write `text`; make-pack transcribes it; if the environment has no transcription, write the script's original text with the cues removed (same as `references/make-pack.md`「Making a pack from a designed voice」step 3). Then issue a new version with `node cli.mjs make-pack <material.json> --previous <pack directory of this version> --output <new directory> --adapter <adapter>`; since the audition line was not dubbed because of the language, hand in `--card-line <file.txt>` at the same time.
3. The user picks a voice speaking this language from the library: the user picks, and you do not pick for them; first make it clear: the lines in this language are that voice, not a recording of this character. This is not the same thing as the paused borrowing of someone else's voice by tag in "Order of choosing a voice" above; here the user chose it.

When listing the options of this step to the user (when they want to add a reference, and in the reply after adding it), always list one more item: "Read it once with <model name> first, then clone: you can try this if you want to tone down the accent", with the model name as the platform writes it. This item means first using another model to read a passage in this language with the pack's original reference (written as in item 2, step 1), then using it together with the original reference as the reference for this language, with the original language first:
   1. The original passage is the default segment in the pack's original language. Trim the silence at both ends of each of the two passages and bring the peaks to the same level, then join them into one audio: the original first, 0.3 seconds of silence in the middle, and what the other model read after it (use an audio tool in the environment, for example ffmpeg). When several reference passages are received, the model side joins them into one passage in just this way (`models/scene3.md`「Reference segments」), and `dub` hands in only one passage per line, so join it first and hand it in as one passage.
   2. After joining, no more than 19.5 seconds: over 20 seconds the model side cuts it, the text given is no longer used, and its own transcription is used instead. If the original passage is too long, cut it short at a pause and cut the text to match, or switch to a shorter one; the two passages are about half each.
   3. The material follows item 2 step 3 above, except that: `text` is the original passage's text, one space, then the text of the passage the other model read (this is how the model side joins them), and `scriptText` is not written (no more than 19.5 seconds after joining, no need to cut); do not write `annotatedText`: when making the pack, ask a model that can listen to audio to annotate according to what this audio actually is, and do not fill it by joining the original passage's cues with the script's cues (the script's cues are the way of speaking that was wanted, not what was read out in this audio). This passage is two languages joined together; if measuring pauses and speed does not work, this passage uses only the cues that were heard (`references/make-pack.md`「Cue annotation」); if the pack already has a passage dubbed with this pack, remove it with `--drop`. Since the audition line was not dubbed because of the language, also hand in `--card-line <file.txt>` at the same time (same as item 2 step 3).

The base part itself does not switch models (`adapters/README.md`「When the model changes」), so this item is listed only when the platform can specify a model; which model, and how to configure it, depends on the platform's adapter; when the platform cannot specify, it is not listed. This item is just said as in the sentence above, and no remark about how good the effect is is added to the option or the reply. After the addition, if the user specifically says this language has an accent, this item is also mentioned. For the source and the readings of adding a reference this way, see `models/scene3.md`「Cross-language and accent」.

## Acting style: which items can reach the model

The acting style (the dubbing guidance's `### 演法` section) is how this line is read. `dub` does not hand the dubbing guidance to the model: the person writing the script writes cues in the script following the acting style (`references/dub.md`「How a line becomes synthesis」step 5, and the sub-skill of each scene). Which forms the model recognises and what the readings are: see the base part's model notes (`models/scene3.md`「Cues」): every form the vendor documentation lists can be used, in the right place; only those whose readings say they are effective can be counted on to be effective, and unverified ones are still written, only without a promise of effect.

- Speaking rate: for an exact multiple, set it with the setup's `speed` or dubbing's `--speed`, which changes the speed after synthesis (`references/dub.md`「Opening cue and speed」). Fast or slow is not also written as a cue: the rate of the whole line relies on `speed`; where the way of speaking itself changes (getting hurried, easing off), write it in the same acting cue as the emotion (`[enthusiastic, hurried]`, `[gentle, slowing down]`, `models/scene3.md`「What to write」), and for a few words only, wrap them in `<fast>…</fast>` or `<slow>…</slow>` (`models/scene3.md`「Good examples」third example). Writing fast or slow into a cue by itself in order to adjust the rate, and adjusting punctuation and pauses to control rhythm, were both listened to and were not good (dropped words, sounding like speaking without breathing); the conclusion and the source are in `models/scene3.md`「Speed and pauses: conclusions from listening」.
- Pauses: write `[pause 0.6s]` in the script (see `references/markup.md`); to pause after a comma, write `，[pause 0.6s]`: a bare `[pause]` is 350 milliseconds, which after a comma is the same as not writing it ("Add a few more things when dubbing." below). When dubbing, a short one is written into the request, using the form that was measured in the model notes, and a long one is cut there and silence is inserted when joining (`references/dub.md`「One request per passage」). Laughing, sighing, drawing a breath: in the script, write them at the position where they happen (`[small laugh]`, `[sighs]`, for the lead see `models/scene3.md`「Sudden sounds and pauses」), and `*笑*` (laugh) and `*叹气*` (sigh) in the script are replaced with English cues when dubbing (`[laughs]`, `[sighs]`); do not write onomatopoeic words (`嘿嘿`, `哈哈`, "hehe", "haha") into a cue, because they may be read out (`models/scene3.md`「What to write」). What is written in the acting style is not handed to the model (`dub` does not hand in the dubbing guidance); it is only the basis for the person writing the script to annotate. Which line should laugh or pause is marked on that line in the script. Habits in the materials ("sighs when tired", "laughs when nervous") are written into the `### 演法` section of the dubbing guidance, and when writing the script they are marked on the line that fits.
- Throat position, tightness, breathiness, huskiness: at the point where the voice should change like this, write a cue of two or three words, together with the emotion of this point (`models/scene3.md`「What to write」, the item on fine acting style); reading: no form was measured to be effective, all are unverified. Whisper, softer, stress, and force that affect only a few words use paired tags (`<whisper>`, `<soft>`, `<emphasis>`, `<forceful>`, `models/scene3.md`「Paired tags」).
- Emotion: written as cues in the script, with the state and cue of each clause written following `models/scene3.md`「Where a cue is written and how far it reaches」›「Set the state first, then write the cue.」, two or three words each, not written as sentences (`models/scene3.md`「What to write」「Good examples」). To switch the reference segment use `--reference-tag`; a cue does not switch the reference (see "Emotional lines").
- **Add a few more things when dubbing.** The person writing the lines first finishes writing following "Set the state first, then write the cue.", and then adds the table below; the words and punctuation are not changed. The basis, readings and range are in `models/scene3.md`「Add a few more things when dubbing.」.

  | Wanted | What the script writes |
  |---|---|
  | A short pause | `，[pause 0.6s]`, written after the comma (a bare `[pause]` is 350 milliseconds, which after a comma is the same as not writing it) |
  | A sigh | `[sighs]`, written at the position where it happens |
  | The emotion changes | Same as the existing rule |

  Fast or slow is not added here (see the speaking rate item above).

  Where to pause (inference; the writer follows it and does not ask a person): after a form of address (「师父，」, "Master,"); before an emotional turn; at the point in a sentence where something is held back and a harsh word is about to be said. At most one per clause. Do not write: `。[pause]`, `[long pause]`, a bare `……`. These were listened to only on lines spoken by one person, one Chinese-speaking voice; other voices and other languages have not been listened to, nor have the default segment and the audition line. For a scene merged from several people, pauses follow `scenes/a-scene.md`, and do not write a `[pause …]` that would cut the request.
- How to fill it in: the seven items are the range of what can be written, not a form to fill in item by item. An item the materials do not write about is left out as a whole line, and no placeholder such as "the materials do not say, not written" is written (a placeholder would be taken as something to act and written into a cue). If there is not a single item, the `### 演法` section is not written. For the syntax and the sections see `make-pack.md`「The five sections of the dubbing guidance」.

## Features of an accent

When the character has an accent or dialect (the materials say so, or the user wants it), the dubbing guidance records the exact features of this accent in the dialect item of the `### 台词` section: this section is for the person writing the script to write from, and is not handed to the model. An accent other than a dialect (Chinese with an English accent) is also recorded here. What is recorded is this dialect's own wording and modal particles, and which common characters are written as other characters (`去` written as `切`, a dialect spelling that only works in Chinese); for a dialect that has its own written form, record that form. Tones and sentence-ending phrasing can also be recorded, for use in short cues, and are not used to spell out the pronunciation of a whole sentence. What to do when you do not know, and how to write by it when writing the script: see `models/scene3.md`「Cross-language and accent」; like the other items of the lines, it carries its source (`references/make-pack.md`「The five sections of the dubbing guidance」). An accent that the reference recording itself carries (a Japanese reference reading English) is a different matter; see "Language and accent" above.

## A designed voice: the description

How to write the description is a matter for the model that designs the voice and is written only in its model notes (the design model's file under `models/`, sections "Dimensions of a description" and "How to write a description"): the dimensions and examples, what to write and what not to write, how to write age, and which words not to write are all there, and are not written again here. The design audition text is used only as raw material, and how to write it is in "Design audition text when designing" above; its character-count limit on this model and the reasons measured for it are in the "Design audition text" section of that file. Here only the points related to the character are added:

- The description writes only timbre (model notes "How to write a description", first item). The character's way of speaking (speaking rate, rhythm, pauses, how the pitch rises and falls, tone, attitude, laughing) is not written into the description, and is not dropped either; they go to different places: speaking rate, pauses, laughing and sighing are written into the `### 演法` section of the pack's dubbing guidance (rhythm goes under the speaking rate and pause items); how it refers to itself, sentence endings and catchphrases are written into `### 台词` (for these two sections see `references/make-pack.md`「The five sections of the dubbing guidance」); expressiveness, tone and attitude are not among the items of these two sections, so when writing the default segment and the audition line (and also when writing a script, if you have the character's materials in hand), write them from the materials as the acting cue of that point (`[calm, unhurried]`, `[warm, lively]`, `models/scene3.md`「What to write」); these three are not recorded separately in the pack, and later dubbing relies on the acting in the default segment to carry them. The default segment is the reference for every later line, and its cues are written following the acting style and the materials ("Default segment" above).
- Gender and age are written every time, following the character's materials; age follows the table in the model notes (a 35-year-old character is written as "青年" (young adult), about 35 years old).
- When the materials clearly state an accent (or the user wants it), or the voice has throat position, tightness, breathiness or huskiness, it is written in the description; for an accent write the concrete features ("Features of an accent") and not the name of the accent; throat position, tightness, breathiness and huskiness are also written in the acting style section of the dubbing guidance. The design model often cannot produce them (model judgment, nobody has checked it), and the model judgment's score found no harm in writing them (lead, model notes "How to write a description").

## Finishing a round without asking, and switching to another

Choosing a voice, making a pack, and the audition line can be finished in one round by an agent without asking anyone (for example creating a new character for the user in the background), and when the user wants to "switch to another", it goes through the same path. Where a user would originally be asked, decide it this way, and write whatever was decided into the report handed back:

- If the materials do not give a gender and the name and description do not show it either: write "中性" (neutral) for the gender of the design description.
- Pack name: the name in the materials; for only recordings with no text of the character, see "The character's materials". The short English name (`--short-name`) is not asked about; if it is not given, `vp` is used.
- Design candidate: design one candidate at a time, do not lock it yet, and look at this audition with `make-pack --dry-run --json` (the material and command follow the temporary pack in `references/make-pack.md`「Making a pack from a designed voice」step 1, with `--default-segment intro`; it costs no money and calls no capability). If this audition cannot be used, the command reports `make_pack_input_invalid`, `details.field` is `defaultSegment`, and the reason says why it could not be used (for example it cannot be recognised as audio). Then do not design again and do not make the pack: write the reason into the report as it is (for example `audio_unrecognized`), and whether to design another is decided by the user (or by the app's "switch to another"). If there is only a quality warning (this segment's `quality.reasons` in the report is not empty, for example shorter than 5 seconds, longer than 20 seconds, clipping, noise floor), do not start over: lock the first one, go on to make the temporary pack, dub that passage, and make the official pack, and write the warning into the report as it is; if the user listens and wants to change, "switch to another". One round is finished, and no extra design is done because of a warning.
- The acted passage: write it following "Default segment", dub it with the temporary pack, and take the expressiveness according to this character (`models/scene3.md`「How to choose the value」, not a number fixed in advance; `references/make-pack.md`「Making a pack from a designed voice」step 2), dub it only once, and use what was dubbed. What `dub` and make-pack themselves report is handled following `references/make-pack.md`「Making a pack from a designed voice」step 2: if it was dubbed by a different model (`modelChange`), do not use it to make the official pack, this round stops here, and write it into the report as it is; if it was not read in full (`speech_maybe_unfinished`), do not dub it again: this item only reports which segment may have been cut, write it into the report as it is, and the user decides; one dubbed longer than 20 seconds (the model side would cut it, see "Default segment") is cut at a sentence end by make-pack, keeping enough for the default segment's length (not shorter than 10 seconds), and is also not dubbed again (`reference_cut_at_sentence_end` in the `make-pack` report). If there is only a quality warning (for example a lot of silence), the same as the previous item: do not dub again, and write it into the report as it is.
- Audition line: the same for a designed voice and a voice made from recordings; write it following "Audition line" before making the pack, and hand it to make-pack together with the pack (`--card-line`). For a designed voice, hand it in together with the official pack, and do not hand it in with the temporary pack. After this line is done it is not dubbed again: a new version without `--card-line` carries over the previous version's line as it is. When switching to another, hand this line in again: the voice has changed, the previous version's line was dubbed with the old voice, and if it is not handed in it is carried over as it is (the report says `card_line_stale`); also hand it in again if a pronunciation was changed and this line uses that word, if the speaking rate was changed directly (switching to another setup does not count), or if the user says outright to dub it again; if the user hears this line read wrongly, handing in the same text also produces a new one (when the request is the same as the previous version's, a different seed is used, see `references/make-pack.md`「How to give the audition line」). If it was not dubbed (`cardLine.status` in the report is `failed`), the pack is still handed over, and the reason is written into the report handed back as it is.
- Whether it sounds like a real person or like this character cannot be judged by the program (`SKILL.md` section 2「Voice design」step 4); do not use it to pick candidates and do not design extra because of it; if the user listens and is not satisfied, they ask to "switch to another".
- Switch to another: change the description with at least one audible feature changed, design another version, pick the candidate as in "Design candidate" above, and go through the temporary pack and the acted passage again too; if only the wording is changed, the designed voice is mostly still very similar (inference, not tested). If the user said what they were unhappy with, change that point (if what they were unhappy with is the way of speaking, change the dubbing guidance and the cues, and not the description); if they did not say, change the texture or a feature of the timbre, and also change the pitch of the voice, which the design model can produce (speaking rate is a way of speaking and is not written into the description), writing something that the previous version's design source (`designSource.description`) did not have: changing only the texture, the design model often cannot produce it (model judgment, nobody has checked it), and the result may still be very similar (design model notes "How to write a description").
- What is switched to is a new version of the same pack, and the pack ID does not change; the previous version is kept, and to go back, install it again. For how, see the second version in `references/make-pack.md`「Making a pack from a designed voice」. The segments of the previous version are of the old voice, and if they are not removed the two voices are mixed. If the previous version was made by base part 2.x or earlier (the manifest's `protocol` is `1.x` or `2.x`), a new version cannot be issued; make a new pack with a new pack ID, also see that section.
