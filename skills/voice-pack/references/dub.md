# 用音色包配音和变声

这一份是基础部分的参考，`SKILL.md` 第 6 节指到这里。流程（什么时候用哪条命令）在 `SKILL.md`，命令的写法、选项、报告、失败的重做、脚本和拼接的规则在这里。

拿到一个音色包（角色部分的目录，里面有 `manifest.json`、`SKILL.md`、`reference/`），先放进环境，再用它的声音给台本配音，或者把一段音频换成它的声音。三个命令都在本目录的 `cli.mjs` 里，都不点名模型，只要运行环境有对应的所需能力。

**放进环境**：`node cli.mjs install <包目录或分享文件>`。先做和 `check` 一样的检查（清单对得上文件、互相校验，还有验签：基础部分和协议核心要有官方签名），通过了才写；放进项目的 `.agents/skills/<包 ID>/`（Codex、Gemini CLI、Cursor、OpenCode 读这里），再复制一份到 `.claude/skills/<包 ID>/`（Claude Code 读这里）。已有同名目录就拒绝，不覆盖。`--project <目录>` 指定项目，默认是当前目录。检查不过（包括签名不对），一个文件都不写；报告点名哪里不对；把它原样告诉使用者，由使用者决定下一步（验签不过，包的来源就没有保证，只有使用者能决定是否信任它）。基础部分或协议核心没有官方签名（自己封的开发副本）时，装要加 `--allow-unsigned`：没有签名的部分不验，输出里写明没验，这不是官方版本；有签名但签不对的，加了也照样拒绝。

**配音**：`node cli.mjs dub <包目录> <台本文件> --out <输出目录>`。台本是带台本标记的文本（`SKILL.md` 第 4 节，写法见 `references/markup.md`），或者 `.json` 数组 `[{ "text": "…", "labels": { "emotion": "angry" }, "instructions": "…" }]`；`-` 是标准输入。先加 `--dry-run` 看规划：只规划，不合成，不花钱。

| 选项 | 作用 |
|---|---|
| `--dry-run` | 只规划：每一句说什么、挑哪段参考、为什么、读音词表换了什么、缺什么运行时 |
| `--language`、`--emotion`、`--style`、`--energy` | 调用方给的标签，用在每一句上，是最优先的一层 |
| `--instructions <文字>` | 代替包里的配音指引 |
| `--only 2,5` | 只做这几句（序号从 1 起）；重做失败的句子用它 |
| `--max-chars`、`--concurrency` | 一次最多合成多少字（超过的按句子切开）、并发数 |
| `--adapter <名字、目录或模块文件>`、`--adapter-option <键=值>` | 模型从适配器接进来：官方的给名字，别的给路径；可以给多个，后给的盖过先给的；`--adapter-option` 给前一个适配器的参数。适配器给了费用说明时，开始之前在标准错误里说明要生成几次，记在使用者自己的账户上。见 `SKILL.md` 第 8 节 |
| `--json` | 标准输出是一份 JSON |

输出目录里，每一句一个音频文件（`<序号>-<参考段>.<扩展名>`），加一份报告 `dub.json`。命令不把各句拼成一个文件：停顿、语速、该不该和前一句连着，都如实记在报告的 `units[i]`（`pauseBeforeMs`、`pauseAfterMs`、`speed`、`join`）里，拼接的人按它处理。退出码：0 全做完；1 有句子失败，或出错停下来了；2 用法错误。`--dry-run` 不做情绪判断（正式运行会判，挑出的参考可能不同）。

**一句话是怎么变成合成的**：

1. 台本里的 `[voice:名字]` 必须是这个包（名字或包 ID）；别的名字报 `voice_unknown`，一个包只有一个声音。
2. 舞台提示（`（耳语）`、`*笑*`）变成这一句的情绪、风格、停顿和语速，从要说的话里拿掉。写法和近义词见 `vocab/cues.json`。括号里词表认不出的内容（例如 `（画外音）`），配音时也拿掉、不念，报告里记着。在配音以外的地方（例如 app 读普通正文），括号里的内容要整个都是词表里的提示才拿掉，其余（例如 `（笑话比赛）`）当正文念，因为它不是舞台提示。规则的正本是 `lib/line-hints.mjs` 的文件头。
3. **挑参考**（`lib/reference-pick.mjs`）：从参考集里挑语言、情绪、风格最对得上的一段。「怎么说」的标签按这个顺序取，前面有了就不再往后看：调用方给的，台本里的提示，环境有 `text-generation` 时它的判断，都没有就用默认参考段。语言先比，再比情绪、风格。默认一句只用一段参考，不融合；留出录音从不当参考。挑的理由写在 `units[i].pick` 里（`rule`、`matched`、`missed`）：`missed` 不空，说明台词要的这一项，参考集里没有哪一段有（例如生气的台词，参考集里没有生气的参考）。
4. **读音词表**：包根目录的 `lexicon.pls`（W3C Pronunciation Lexicon，PLS）。只换要说的话里的词，台本标记原样保留。读法是音素的做不到，报在 `lexicon.unapplied`（`reason` 是 `phoneme`）。只有清单的 `files` 列着 `lexicon.pls` 才读：直接改已装的包里的这个文件，清单没列，就当没有词表，报告里 `applied`、`unapplied` 都空。改读音要发新版本，做法见 `make-pack.md`。
5. **配音指引**：包的 `SKILL.md` 最后一节，分三节（`### 音色`、`### 演法`、`### 台词`，见 `references/make-pack.md` 的「配音指引的三层」）。你先读全部，写台本时照着做：台词和音色是写台本的依据（自称、句尾、口头禅，声音是什么样），不交给模型。运行环境有 `style-instruction` 时，命令把配音指引的演法一节连同这一句的说明，通过参数 `instructions` 传给模型（没有三个小节的旧式指引整段传）；交出去的那段超过 2000 个字，截短再传，报告里记一条 `guidance_truncated`。没有配音指引，就不传，报告里说明。基础部分交整节演法，不按模型挑；每一项在哪个模型上有没有效果，看运行环境的适配器说明里的效果表。这条规则的正本是 `protocol/FORMAT.md` 第 5 节。运行环境有 `style-cues` 时，每一句自己的舞台提示认出来的几个名字（情绪、风格）通过参数 `cues` 随段传给模型；配音指引不走这条路（它是这个声音的习惯，不是这一句的指示）。
6. **增强件**：包里服务 `voice-cloning` 的增强件，递给能力。环境认识对应的模型就用上（报告 `enhancers.used`），不认识就照常生成，`enhancers.statement` 是 `enhancers_not_used`，并附上包的验证记录，让人知道当前环境下效果会差多少。
7. **脚本**：登记在 `dub` 功能名下的，合成之前改要说的话，合成之后改音频，见下。

**拼接**（把各句接成一个音频的人照这几条做：命令行的使用者，或者适配器自己拼的）：

- 每一句的 `pauseBeforeMs` 挂在句首、`pauseAfterMs` 挂在句末，各按毫秒插静音（封顶 10000 毫秒）。续接的句子（`join` 为 `continue`，接着下一句说）也一样：`pauseAfterMs` 是 0 就不插；以「，、；：」结尾的续接处，`pauseAfterMs` 是 500（配音定的，常量在 `lib/pause-in-request.mjs` 的 `JOIN_PUNCTUATION_PAUSE_MS`）。合成能力收 `continues` 的，续接的那一段传 `continues: true`，不到最短字数补「，」，句末补「。」。
- `joined` 的段（一段话里的停顿并进了一次请求，文字里写着 `<break>`，或者靠标点）是一段音频：里面的停顿已经在音频里，不再插静音，只看它的头和尾的 `pauseBeforeMs`、`pauseAfterMs`。只有声明了 `pause-in-text` 的环境会有这种段；没有声明的，报告里没有 `joined`。
- `speed` 为 0.85（放慢）、1.15（加快）的，拼接的人自己变速：合成能力不收语速。`speed` 为 null 表示台本没有语速要求（不是 1.0）。`join` 只在句子被标记切开时出现（值是 `continue`）；没有这个键，这一句不接着下一句说。

**失败和重做**：服务暂时出错的句子记成 `failed`，别的句子照常做，退出 1，输出里给出带 `--only` 的重做命令；重做时，上一次做好的句子（话和参考段都没变、文件还在）原样沿用。报错的 `details.action` 是 `download` 的，任务其实已经做完：报错里的任务号（`details.taskRunId`）用来取结果（适配器说明里写明怎么取），不要重做，重做会再计一次费。输出里打印的重做命令带着这次的适配器（`--adapter`、`--adapter-option`）和标签、说明、`--max-chars`、`--concurrency`，照着原样再跑就行。文字被拒的句子（`details.textRejected`，只和这一句的文字有关，换一句就成）也记成 `failed`，只记这一句，别的照常做，不重试，因为换一句才会有不同的结果。调用之前就查出来的（文字空白、太长、有处理不了的字，错误码 `capability_input_invalid`）不计数；服务商拒的，连着 3 句、还没有一句成功，就和别的错一样停下来（错误码 `dub_text_rejected`，`stoppedBy` 的 `details.rejected` 写明被拒的句子）：这种情况多半是参考或别的输入被拦了，每一句都会这样被拒，停下来才不白花钱。别的错（401、参数不对、缺能力、缺运行时……）直接停下来，不再开始新的句子，已经做好的文件和一份写着 `stoppedBy` 的 `dub.json` 留着。401 说明授权有问题：先让使用者处理好，再接着做（同一句再发还是 401）。

**包里的脚本**：清单 `scripts` 里的 `{ entry, runtime, feature }`，`feature` 是 `dub` 或 `convert`。一个功能只跑登记在自己名下的脚本；没写 `feature` 的不会自动运行（配音指引可以教你手动用）。运行环境完全信任脚本：直接运行，不让使用者确认，不隔离。运行时按名字取：`node` 就是运行命令的 Node，`python` 找 `python3` 或 `python`，别的名字按 PATH 找。缺运行时，只有用到这个脚本的功能报 `runtime_missing`，在合成之前报；`--dry-run` 不报，只在输出里说缺什么。脚本从标准输入读一份 JSON，往标准输出写一份 JSON（什么都不写或 `{}` 是不改）：

- 输入：`{ protocol: 1, feature, hook, pack: { id, name, version }, unit: {…} }`。`hook` 是 `text`（合成之前，`unit.text` 是要说的话）或 `audio`（合成之后，`unit.audio` 是 Base64 的音频，`unit.mimeType` 是它的类型）；同一个脚本两个钩子都会被叫到，没什么要做的就什么都不输出。`convert` 功能只有 `audio` 钩子。
- 输出：`text` 钩子 `{ "text": "改写后的话" }`；`audio` 钩子 `{ "audio": "<Base64>", "mimeType": "audio/wav" }`。别的键、不是 JSON 对象的输出，一律报 `script_output_invalid`，不悄悄忽略。同一个功能有几个脚本时，按清单里的先后一个接一个运行。

**变声和唱歌**：`node cli.mjs convert <包目录> <音频文件> --out <文件>`；`--singing` 是唱歌（输入要是人声分轨，没有伴奏）。说话用 `voice-conversion`，唱歌用 `singing-voice-conversion`，缺哪一项，只有这个命令报 `capability_missing` 并点名缺的是哪一项，配音照常。参考用默认参考段，给了 `--language` 等标签就按标签挑。输出文件已经存在就拒绝，不覆盖，而且是在花钱之前就拒绝；接进来的适配器给了费用说明时，换声之前在标准错误里说明要调一次哪项能力（`--json` 时不说）。登记在 `convert` 功能名下的脚本在换声之后处理音频；增强件的用法同配音。

**各个功能要什么能力**：

| 功能 | 必须有 | 有就用 |
|---|---|---|
| 配音（`dub`） | `voice-cloning` | `style-instruction`（传配音指引）、`style-cues`（传这一句的舞台提示）、`text-generation`（判断没有提示的句子的情绪）、增强件对应的模型 |
| 变声（`convert`） | `voice-conversion` 或 `singing-voice-conversion` | 增强件对应的模型 |

当前运行环境有哪些能力，看接进来的适配器的说明。要用别的模型，自己写一个适配器，用 `--adapter <目录或模块文件>` 交给命令：适配器是一个函数，返回一个对象（能力、运行时、网络读取、费用说明等，键都可选，写法见 `adapters/README.md`「返回的形状」）；后给的盖过先给的，也盖过命令已有的同名项。约定只写在 `adapters/README.md`，每项能力的调用参数和返回值见 `vocab/capability-signatures.md`。适配器在本进程里直接运行，不隔离，和包里的脚本一样。
