# 用音色包配音和变声

这一份是基础部分的参考，`SKILL.md` 第 6 节指到这里。流程（什么时候用哪条命令）在 `SKILL.md`，命令的写法、选项、报告、失败的重做、脚本和拼接的规则在这里。

拿到一个音色包（角色部分的目录，里面有 `manifest.json`、`SKILL.md`、`reference/`），先放进环境，再用它的声音给台本配音，或者把一段音频换成它的声音。这几个命令（`install`、`dub`、`convert`，还有拼接用的 `mix`）都在基础部分根目录（`references/` 的上一级）的 `cli.mjs` 里，都不点名模型，只要运行环境有对应的所需能力（`install`、`mix` 不调能力）。

**放进环境**：`node cli.mjs install <包目录或分享文件>`。先做和 `check` 一样的检查（清单对得上文件、互相校验，还有验签：基础部分和协议核心要有官方签名），通过了才写；放进项目的 `.agents/skills/<包 ID>/`（Codex、Gemini CLI、Cursor、OpenCode 读这里），再复制一份到 `.claude/skills/<包 ID>/`（Claude Code 读这里）。已有同名目录就拒绝，不覆盖。`--project <目录>` 指定项目，默认是当前目录。检查不过（包括签名不对），一个文件都不写；报告点名哪里不对；把它原样告诉使用者，由使用者决定下一步（验签不过，包的来源就没有保证，只有使用者能决定是否信任它）。基础部分或协议核心没有官方签名（自己封的开发副本）时，装要加 `--allow-unsigned`：没有签名的部分不验，输出里写明没验，这不是官方版本；有签名但签不对的，加了也照样拒绝。

**配音**：`node cli.mjs dub <包目录> <台本文件> --out <输出目录>`（几个角色的一场戏：`--pack <包目录>` 给几次，见下表）。台本是带台本标记的文本（`SKILL.md` 第 4 节，写法见 `references/markup.md`），或者 `.json` 数组 `[{ "text": "…", "labels": { "emotion": "angry" }, "speed": 0.9, "expressiveness": 70, "targetDurationMs": 2700 }]`（项自己的标签、语速、起伏盖过命令行上给的，也盖过设定的，见下面「开头的提示和语速」）；`-` 是标准输入。先加 `--dry-run` 看规划：只规划，不合成，不花钱。协议 1.x、2.x 的旧包（参考段是旧写法）这一版不读：`dub`、`convert` 打开包时就停下，报 `pack_protocol_old`（`details.protocol` 是包写的协议版本），一次能力都不调；旧包用它那个主版本的程序配：完整包用它自带的基础部分，只有角色部分的用那个主版本的基础部分（2.x 的包用 2.x 的基础部分，`protocol/FORMAT.md` 第 14 节「2.x 的包」）。

| 选项 | 作用 |
|---|---|
| `--pack <包目录>` | 几个角色：可以给好几次，代替位置上的包目录（给了 `--pack`，位置上只放台本）。第一个包是台本开头的声音；`[voice:名字]` 认包名或包 ID，从那一句起换成那个包。每句的参考段从它那个包里挑，短句只在同一个包里并。`dub.json` 的每个 unit 记着包 ID，顶层 `packs` 列出全部的包；只给一个包时和原来一样 |
| `--dry-run` | 只规划：每一句说什么、挑哪段参考、为什么、读音词表换了什么、用了包里的哪一套设定、缺什么运行时。`--only` 没点到的标 `skipped`；给了 `--out`，能沿用的（见下面「失败和重做」）标 `ok`、`carriedOver`，文字输出写「沿用上一次的……不再合成」，上一次没取回、这次没点到的（同一个请求才算，认法同沿用）照旧标 `failed`（没取回）：规划里 `status` 是 `planned` 的，才是这次要合成、要花钱的。文字输出的第一行是汇总：要念多少字（数法见下面「长文怎么切」的「两种字数」）、分几个请求（一场戏一个请求的算一个；字太少、不发请求的那几句，字和请求都不算）、这次要合成几个（和请求数不一样时才写）、用哪个模型（适配器返回里的 `models`，没说就写「适配器没说用哪个模型」）；不估计要多久。长文分成几个请求时，照它先告诉使用者（`scenes/narration.md` 第 6 步）。`--json` 的输出没有这一行。输出目录里什么都不动 |
| `--language`、`--emotion`、`--style`、`--energy` | 调用方给的标签，用在每一句上，盖过设定的同一项。语言用来挑参考（见下面第 3 步）：整份台本都按它挑，另一种语言的一整行也用这种语言的参考，是跨语言克隆；文字看得出不是这种语言的（英文台词给了 `--language zh`），`dub` 照样停下（第 3 步「默认不带口音」）；情绪、风格、能量不影响用哪段参考，合成一条提示写在每个请求的开头（见下面「开头的提示和语速」）。`--energy` 只收 `low`、`medium`、`high`，写别的报 `pick_input_invalid` |
| `--instructions`（拿掉了） | `dub` 不再把说明发给模型：`--instructions`、`.json` 项的 `instructions`、库里的 `options.instructions` 给了都报 `dub_input_invalid`，`--dry-run` 也报（见下面「开头的提示和语速」）。要的说法，在台本里写具体的提示，写在发生的位置 |
| `--speed <倍数>` | 调用方给的语速（正数，1 不变，0.85 放慢，1.15 加快），盖过设定的：合成以后变速（见下面「开头的提示和语速」） |
| `--expressiveness <0 到 100>` | 起伏，模型的控制参数（越大越有戏，越小越平稳；刻度见 `vocab/capability-signatures.md`），传给每个合成请求。先后：`.json` 台本里项自己的 `expressiveness` → 这个选项 → 这一行用的设定的 `expressiveness` → 包的全局值（清单顶层的 `expressiveness`）；`--no-setup` 不用设定的值，全局值照用；都没有就不传，`dub` 没有自己的默认值。包给了值（设定的或全局的）的，默认不给这个选项，有理由才给，从包给的值挪约 10；包什么都没给的，可以给也可以不给，不给就不传。给多少合适，指到 `models/scene3.md`「起伏」（见下面「开头的提示和语速」的「起伏」）；它对每一行都盖过包给的值，有的声音固定了、有的没固定，或几个声音的值不同时怎么办，见 `models/scene3.md`「怎么取值」 |
| `--setup <名字>` | 用包里的哪一套设定（清单的 `setups`：作者把情绪、风格、语速这类固定值写进了包里，另有一段给写台本的人看的说明，不发给模型，每套有名字）。设定里固定的值补在调用方没给的那一项上（怎么生效见下面「开头的提示和语速」），台本在一段的开头自己写了提示的，那一段照台本。不给就用带 `default` 的那一套，没有就不用设定；名字对不上报 `setup_unknown`，列出包里有哪几套（`--dry-run` 的输出和计划里 `pack.setups` 也列着）。几个包时，每个包在自己的设定里找：`--setup <名字>` 是每个包都按这个名字找；`--setup <包>=<名字>`（包名或包 ID，不分大小写，和台本里 `[voice:]` 认包的写法一样）点某一个包的，可以给几次，没点的包用它自己的默认设定，两种写法不混着给；设定的名字里有 `=` 时写成 `<包>=<名字>`（名字取第一个 `=` 后面的全部）。不给时，每个包用它自己的默认设定。`--dry-run` 和 `dub.json` 的 `pack.setup`（几个包时是 `packs[i].setup`）写明用的是哪一套 |
| `--no-setup` | 这一次哪个包都不用设定，带 `default` 的那一套也不套：参考照 `--reference-tag`、这句语言的默认段挑，语言、情绪、风格、能量、语速只有调用方给的（起伏也不用设定的，但包的全局值照用，见 `--expressiveness` 一行）。要的是声音本身时用，例如拿这个包自己配一段另一种语言的参考（`references/character-voice.md`「补一段这种语言的参考」）。不和 `--setup` 一起给（用法错误）。`--dry-run` 的输出写明这次是 `--no-setup` 不用的，计划和 `dub.json` 里没有 `pack.setup`（`pack.setups` 照旧列着包里有哪几套）。失败后的重做命令把它照写回去 |
| `--reference-tag <标签>` | 用包里哪个音色基底标签的参考（包的 `SKILL.md` 按语言列着有哪些标签）：盖过设定写的默认参考（设定的 `referenceTag`），每句在带这个标签的几段里按语言取（见下面第 3 步）。用户要换参考的、你按台本和情境挑的、使用者听出音色偏了要换的，都从这里给；不给就用设定写的默认参考，再没有就用这句语言的默认段。标签逐字比；包里没有这个标签报 `reference_tag_unknown`（`details` 是 `{ referenceTag, pack: { id, name }, tags }`，`tags` 按语言列出包里有哪些标签），规划时就报，`--dry-run` 也报，一次能力都不调。几个包时：不带包名的 `--reference-tag <标签>` 只给一次，每个包都用它，每个包都要有这个标签；`--reference-tag <包>=<标签>`（包名或包 ID，不分大小写）点某一个包，可以给几次，同一个包只点一次，没点的包照设定、默认段取；两种写法不混着给。`=` 左边是这次给了的某个包的名字或 ID 时才当按包点名，不然整串是标签（标签里可以有 `=`）。失败后的重做命令把它照写回去。一次 `dub` 里一个包只用一个标签，`dub` 也不收同一个包两次：台本中途要换标签，在换的地方把台本拆成两份，两次 `dub` 各给各的 `--reference-tag`，再用 `mix` 把两个输出目录按次序接成一个文件（见下面「拼接」）；拆开的地方 `mix` 不另加停顿，要停一口气，在后一份台本开头写 `[pause 0.5s]` |
| `--target-duration-ms <毫秒>` | 对画面的一句：配出来要多少毫秒，合成以后变速对上它（见下面「目标时长」）。给的是每一项的：`.txt` 台本是整份台本一项；`.json` 台本里项自己写 `"targetDurationMs"`，盖过这个选项 |
| `--min-similarity <数>` | 说话人相似度的阈值：环境有 `speaker-verification` 时，低于它的句子标出来（见下面「比一比音色」）。不给就只报数、不标 |
| `--only 2,5` | 只重做这几句（序号从 1 起）：点到的一律重新合成，没变也重做（要某一句换一条再配用它；环境收 `seed` 的，上一次做成了的那一句换一个 `seed`，见下面「失败和重做」）；没点到的沿用上一次做好的（见下面「失败和重做」） |
| `--max-chars`、`--concurrency` | 一个请求最多发出去多少字（连开头的提示；放不下时只在边界切，见下面「长文怎么切」）。一般不用给：不给时，默认一个请求约 1000 个要念的字符，适配器声明了 `limits.maxChars` 的，发出去的字也不超过它；给了就只照给的数切，适配器的上限也不再管。`--max-chars` 数的是发出去的字（提示、标签、开头加的提示、每个空白都算），和默认的约 1000 个要念的字符不是一种数法：台本里提示、标签多的，`--max-chars 1000` 比默认切得碎。`--max-chars` 不小于 10。`--concurrency` 是并发数，1 到 8，默认 2。这两个超出范围报 `dub_input_invalid` |
| `--no-scene` | 明说分开：不按一场戏一个请求配（见下面「一场戏一个请求」），一行一个请求、一行一个文件，同一个声音接着说的几行也不并（同一行里的几句照旧一个请求）。一行里有请求里放不下的长停顿，或者一行自己放不下一个请求的，照样在那里切开（下面「一段话一次请求」「长文怎么切」），那一行就是几个文件。要每一行一个文件、只重做某一行、或者要按行对时间时用。例外：适配器声明了一个请求至少多少字（`limits.minChars`）时，比它短的一行照旧并到下一行（不并就合成不了；跨章节、跨项也并，条件见下面「一段话一次请求」的「比下限短的照旧并」），那两行是一个文件。行与行之间照台本写的停顿，`dub` 不另加默认的停顿（下面「长文怎么切」的「切口的气口」） |
| `--allow-cross-language` | 要口音：用的参考段不是这一句的语言也照配（跨语言克隆，常带参考那种语言的口音）。不给时这种句子让 `dub` 在花钱之前停下，报 `dub_cross_language`（见下面第 3 步「默认不带口音」）。使用者说了要口音才给。失败后的重做命令把它照写回去 |
| `--adapter <名字、目录或模块文件>`、`--adapter-option <键=值>` | 模型从适配器接进来：官方的给名字，别的给路径；可以给多个，后给的盖过先给的；`--adapter-option` 给前一个适配器的参数。适配器给了费用说明时，开始之前在标准错误里说明要生成几次，记在使用者自己的账户上。见 `SKILL.md` 第 8 节 |
| `--json` | 标准输出是一份 JSON |

输出目录里，每一句一个音频文件（`<序号>-<参考段>.<扩展名>`；一场戏一个请求的是 `<序号>-scene.<扩展名>`，见下面「一场戏一个请求」），加一份报告 `dub.json`。`dub` 不把各句拼成一个文件：停顿如实记在报告的 `units[i]`（`pauseBeforeMs`、`pauseAfterMs`）里，拼接的人按它处理；语速 `dub` 合成以后自己变（见下面「开头的提示和语速」），没变成的记在 `speed` 里，也由拼接的人处理；要一个成品，用 `mix`（见下面「拼接」）。退出码：0 全做完；1 有句子失败，或出错停下来了；2 用法错误。`--dry-run` 的计划里每一句用的参考和正式运行一样。

**用了哪个模型**：适配器报了实际用的模型，`dub.json` 的 `units[i].model` 记着。适配器这一次换了模型（例如原来要用的模型这时不可用），那一句另有 `units[i].modelChange`（`from` 是原来要用的模型，`reason` 是为什么换），输出里另起一条「注意」，列出哪几句、换成了什么、为什么：这几句的声音和演法可能和别的句子不一样，要告诉使用者。`dub` 自己不换模型，也不重试（换不换由平台定，约定见 `adapters/README.md`「换了模型」）。

**一句话是怎么变成合成的**：

1. 台本里的 `[voice:名字]` 认包名或包 ID（不分大小写）。只给一个包时，必须是这个包：一个包只有一个声音，别的名字报 `voice_unknown`。给了几个包（`--pack`）时，第一个包是台本开头（第一个 `[voice:]` 之前）的声音；`[voice:名字]` 从那一句起换成那个包，到下一个声音标记、或这一章结束（回到第一个包）为止。别的名字报 `voice_unknown`，`details` 里列出给了哪些包；名字对上不止一个包的，报 `voice_ambiguous`，用包 ID 指定。
2. **提示原样、按位置交给模型。** 台本里方括号的提示（`[sad and surprised]`、`[hushed voice]`、`[laughs]`，写法见 `references/markup.md`）原样留在它所在的位置，随文字交给模型；`dub` 不解读、不改它，也不另外经参数交说明或情绪的名字。尖括号的标签（`<whisper>…</whisper>`、`<french>…</french>`、`<|phoneme_start|>…<|phoneme_end|>`）也一样原样留在原位：读音词表不改标签名和音素，切开太长的一行时不从一对标签中间切开（比一个请求还长的一对，在里面切开，每一段两头补上这一对标签），认语种时不算标签里的字母和语言标签包住的字（`references/markup.md`「尖括号标签」，那里也写着只声明了 `phoneme-in-text` 的环境的一处例外）。舞台说明（`（耳语）`、`*笑*`）发出去之前换成同样意思的提示（`[耳语]`、`[笑]`），留在原来的位置，括号里的字不念。只有 30 个字以内的 `（…）`、`(…)`、`【…】`、`*…*` 是舞台说明；更长的括号是台词，连括号原样交给模型念。星号要紧贴着字：`3 * 4 * 5`、`* 笑 *` 是正文，原样念；`**…**` 是强调，去掉星号，字照念（`references/markup.md`）。读成停顿的（`（停顿 2 秒）`、`（沉默）`，写法和近义词见 `vocab/cues.json`）照旧是停顿；吸一口气、咳嗽、清嗓子这类一下子的声音不是停顿，和笑一样换成提示（`（深吸一口气）` 是 `[深吸一口气]`，`*coughs*` 是 `[coughs]`）。30 个字以内的括号里写的不管是什么，配音时都这样拿掉、不念，原文括号里要念的正文也一样：`（画外音）` 发出去是 `[画外音]`，`（疫情之前）`、`（笑话比赛）` 也换成提示。括号里一个词表里的词都没有的（`（画外音）`、`（疫情之前）`），报告里那一项的 `recognized` 是 false（`units[i].pick.directions`；一场戏在 `units[i].scene.turns[k].directions`），`notes` 里另有一条 `unrecognized_directions` 列出这几处（文字输出是一行「注意」）。括号里有一个词表里的词就算认得出（汉字按子串找：`（笑话比赛）` 里有「笑」，`（当时很开心）` 里有「开心」），不进这条注意。所以这条注意列不全，不能靠它找：原文括号里要念的正文，配之前自己逐处改成不带括号的写法（逗号、破折号）。括号里的字原样搬进方括号，长的舞台说明就是长的提示：一处提示（方括号写的、舞台说明换成的）超过 4 个词（汉字、假名两个算一个词，`lib/cue-length.mjs`），`notes` 里有一条 `long_cues` 列出来（`details.cues` 每项是 `{ line, cue, words }`），文字输出是一行「注意」。只提醒，不改字，照原样发：自己改成两三个词，只写这一处怎么说（写法见 `models/scene3.md`「写什么」）。只有提示、没有字的一行，提示接到同一个声音的下一句开头。在配音以外的地方（例如 app 读普通正文），括号里的内容要整个都是词表里的提示才拿掉，其余（例如 `（笑话比赛）`）当正文念，因为它不是舞台提示。规则的正本是 `lib/line-hints.mjs` 的 `cuesInPlace`。
3. **用哪段参考**（`lib/reference-pick.mjs`）：按这个顺序取，取到就停：调用方指定的音色基底标签（`--reference-tag`，库里是 `options.referenceTag`）→ 选中的那套设定写的默认参考（设定的 `referenceTag`）→ 这一句的语言的默认段。`dub` 自己不按标签挑，也不按每句的情绪、风格、能量挑参考，不让模型给每句判情绪：情绪靠台本里的提示交给模型；按标签挑是你的事，挑好了用 `--reference-tag` 交进来，挑不出合适的就不给。
   - **这一句的语言**：调用方给的（`--language`），没有就用设定的，再没有就从文字认（认语种读的是去掉提示以后要念的字，方括号里的提示不算）；文字里也看不出，就是没有语言。一段话（台本里的一行）只挑一次：一行里被停顿、提示隔开的几块按整行的字认语种，用同一段参考；整行看主要的文字（一行中文里一个片假名的名字、一行英文里一句「ありがとう」，整行还是中文、英文）。一行中文里的一句英文跟着用中文的那段，那一块标跨语言。包里有英文的（那一块自己挑会用英文的段），这是跟着这一行的跨语言：`pick.followsLine` 是 `true`，给人看的输出里标「跨语言：这一行里有别的语言，跟着这一行的参考段」，不是包里没有这种语言，不用换包；要那一块用英文的段，把它写成单独的一行。包里没有英文的，照下面两条标（只标，不停）。这两种都是一行里混着说，整行还是中文，配音照常配，不停下（下面「默认不带口音」）。和段的语言比：完全一致的优先，没有再看主语言一致的（台词是 `zh`、段是 `zh-CN`），对上几段就取参考集里排在前面的那段。包的主语言是主默认段（`reference.defaultSegment`）的语言。
   - **定了标签**（前两层）：在带这个标签的几段里找这一句的语言的那段。这种语言里没有：用包的主语言里这个标签的段，主语言里也没有，用这个标签在参考集里排在最前的那段；这两种是跨语言克隆，给人看的输出里标「跨语言：这种语言里没有这个标签」；整行都是这种语言的，默认停下，不配；一行里夹着的一块只标，不停（下面「默认不带口音」）。没有语言：用主语言里这个标签的段，没有就用排在最前的那段，不算跨语言。
   - **没定标签**：用这一句的语言的默认段。包里每种语言各有一段默认段（`protocol/FORMAT.md` 4.4「默认段」：主语言的是 `reference.defaultSegment`，别的语言的在 `reference.languageDefaults`；包没写的语言，是参考集里这种语言排在最前的那一段）。包里没有这种语言：用主语言的默认段，这一句是跨语言的，给人看的输出里标「包里没有这种语言」，整行都是这种语言的，默认停下，不配；一行里夹着的一块只标，不停（下面「默认不带口音」）；没有语言，也用主语言的默认段，不算跨语言。
   - 一句只用一段参考，不融合；留出录音从不当参考。和参考一起交给模型的参考文字：参考段有提示标注（清单里的 `annotatedText`，见 `references/make-pack.md`「提示标注」）就交它，没有就交逐字稿 `text`（`lib/reference-pick.mjs` 的 `refTextOf`）；一场戏里每个说话人的参考也一样。用的是哪一段、为什么，写在 `units[i].pick` 里（`--dry-run` 的规划里一样）：`segmentId` 是那一段，`tag` 是它的音色基底标签（默认段也写），`by` 是从哪一层取的（`reference-tag`、`setup`、`default`；按这一句的语言换的默认段也是 `default`），`crossLanguage` 是这一句是不是跨语言克隆，`followsLine`（只在是的时候有）是这一句的跨语言只是因为跟着这一行用的段（见上面「这一句的语言」），`language` 是这一句按哪种语言挑的、从哪来。标成合成的段（`synthetic`）和真录音的段一样挑、一样写。规则的正本在 `lib/reference-pick.mjs` 的文件头。
   - **默认不带口音。** 用一种语言的参考念另一种语言，配出来常带参考那种语言的口音（推断：一个人听的，样本小；日语的参考念英文，常是带日语口音的英文，听过的 `[native English pronunciation]` 和 `<english>` 都没去掉，见 `models/scene3.md`「跨语言和口音」）。所以这一次要合成的句子里有一行用的参考段不是这一行的语言（上面两条标跨语言的），`dub` 在花钱之前停下，报 `dub_cross_language`，一次能力都不调，什么都不写；`--dry-run` 也报。比的是整行的语言：一行里夹着另一种语言的几个字（上面「这一句的语言」那种）不算，看不出语言的一行不算；给了 `--language`（或者设定写了语言）的按给的比，可文字看得出不是这种语言的（英文台词给了 `--language zh`，或者设定写的是 `ja`），`dub` 不信给的，按文字认的比，照样停；文字看不出的（只有数字、标点）、同一种文字的几种语言（英语、法语都是拉丁字母），`dub` 查不出，照给的比；`--only` 没点到的、沿用上一次的句子这一次不合成，也不算。合并的一场（下面「一场戏一个请求」）比的是每个说话人整场用的那一段和他的每一轮。
     - 报告说哪几段（第 N 段，同 `--only` 的序号）、哪个包、哪段参考、参考段的语言→台词的语言。台词的语言：给了的（`--language`、设定的）照写，`ja→en`；从文字认的（连上面不信给的），假名、谚文这种只可能是一种语言的写那种语言，拉丁字母、汉字不猜是哪一种，写文字，`ja→拉丁字母`。
     - `details.units` 一段一项（一场戏里一个说话人一项）：`{ unit, pack: { id, name }, speaker?, segmentId, by, from, to, script?, lines, hasLanguage }`。`unit` 是段的编号（从 0 起，`--only` 的序号减 1），`speaker` 只在一场戏里有，`segmentId`、`by` 同 `pick`，`from` 是这段参考的语言，`to` 是台词的语言（不猜的是 `null`，另有 `script`，例如 `Latin`），`lines` 是哪几行（同 `dub.json` 的 `lines[i].index`，从 0 起），`hasLanguage` 是包里有没有这种语言的参考段。
     - 两条路，由使用者定（停下来以后怎么问，见各场景的子 skill），他没说要口音就不加 `--allow-cross-language`。要口音：加 `--allow-cross-language`（库里 `allowCrossLanguage: true`）再配，照上面跨语言克隆配，`pick.crossLanguage` 照旧标着。不要口音：给包补一段这种语言的参考，当素材交给 `make-pack`，给上一版的包目录发新版本（`references/make-pack.md`「发新版本」），再用新版本配。参考从哪来：有这个角色说这种语言的录音就用录音；没有的，默认用这个包跨语言配一段这种语言的话（`--language <这种语言> --allow-cross-language --no-setup`，不套包里的设定，素材标 `synthetic`）；或者使用者在库里挑的一个说这种语言的声音（是另一个声音，先说清楚）；平台能指定模型的，另列一项先用别的模型念一遍再克隆。做法和怎么跟使用者说，见 `references/character-voice.md`「补一段这种语言的参考」；停下来的报告也这样说。
     - 包里其实有这种语言的段的（`hasLanguage` 是 `true`），报告另说怎么用上它：给了语言、文字却不是这种语言的，不给 `--language`（是设定写的，用 `--language` 写台词的语言盖过它，或者换一套设定 `--setup`、不用设定 `--no-setup`）；定了标签的，是这种语言里没有这个标签，换一个这种语言里有的（`--reference-tag`），或者不指定（标签是设定的默认参考 `referenceTag` 的，用 `--reference-tag` 盖过它，或者换一套设定、不用设定 `--no-setup`）；合并的一场里一个说话人整场只用一段参考的，分开配（`--no-scene`），每一行各用各的语言的参考。这几条要改的是使用者点名的、设定写的，先照 `references/character-voice.md`「语言和口音」问他。
4. **读音词表**：包根目录的 `lexicon.pls` 的用法、音素的条件和报告的写法，见 `dub-details.md`「读音词表」（只有清单的 `files` 列着它才读，改读音要发新版本）。环境声明了 `phoneme-markers`（合成的模型认音素标签，写法见 `models/` 里那个模型的说明），词表的音素写成音素标签，一场戏也标，`--dry-run` 的 `spoken` 里看得到；只写一个字的词条用上了，规划的说明里有一条 `lexicon_single_character`。
5. **配音指引**：包的 `SKILL.md` 最后一节，分三节（`### 音色`、`### 演法`、`### 台词`，见 `references/make-pack.md` 的「配音指引的三层」）。你先读全部，写台本时照着做：台词和音色是写台本的依据（自称、句尾、口头禅，声音是什么样）；演法写成提示，写进台本里说法变化的地方（一句里可以有好几个，每个两三个词、不写成句子，一律写英文；只管几个字的用成对的标签；见 `models/scene3.md`「提示」）。`dub` 不把指引交给模型，报告的 `guidance.sent` 恒为 false。
6. **增强件**：包里服务 `voice-cloning` 的增强件怎么递给能力、认不出时报告怎么写，见 `dub-details.md`「增强件」。
7. **脚本**：登记在 `dub` 功能名下的，合成之前改要说的话，合成之后改音频，见下。

**一段话一次请求**（`lib/dub.mjs` 第 5c 步）：一段话是台本里的一行（非空的一行是一段），同一个声音。一行里被停顿（`[pause …]`、舞台说明里的停顿）隔开的几段用同一段参考、一次请求说完，后面没写提示的句子在同一个请求里，接着前面的说法；同一章里接着的几行，放得下也并进这一个请求，行和行之间换行（见下面「长文怎么切」）。`dub.json` 里它是一个 unit，`joined` 列着并了哪几段。中间的停顿：

- **短的写在请求的文字里。** 不超过适配器声明的 `limits.maxPauseInRequestMs`（一个请求里一处停顿最多多长；没声明用基础部分的默认值，`lib/pause-in-request.mjs` 的 `DEFAULT_MAX_PAUSE_IN_REQUEST_MS`）的，写成量过的写法里出来的静音最接近的那一种：没有标点的地方写逗号或 `[pause]`；前面是逗号一类的，要长一些就再加 `[pause]`；前面已经是句号、问号、叹号的不再加（它们自己就停得够长，在后面再加，量到过把后一句丢掉）。没写停顿、只是换了一行的，换一行接上（请求的文字里两行之间是换行）；只写着停顿的一行也照这一条，写在两行之间。写法和读数在 `models/scene3.md`「停顿」；短停顿出来多长只是大概，量过的上下有几百毫秒的出入。
- **长的在那里切开。** 长过它的，在那一处切成两个请求，停顿记在报告里（前一句的 `pauseAfterMs`、后一句的 `pauseBeforeMs`），`mix` 插进一样长的静音。
- **切开的后一个请求不带前一个的提示。** 提示只在台本写它的地方：长停顿以后还要那样说，在停顿后面再写一次（`（生气）你好。[pause 3s][生气]我走了。`）。
- 总是切开的地方：章节、`.json` 台本的项与项之间（每一项自己算一章：不和别的项并进一个请求，`[voice:]` 不跨项，每一项从第一个包起）、换声音（`[voice:]` 写的名字变了）、行与行之间换了语言（包里有那种语言的默认段，参考段不同；`dub.json` 里后一块的 `cutBefore` 是 `language`，`notes` 里有一条 `language_cut` 列出切在哪）、设定的语速不同、开头的提示不同、这一行要加设定的提示而前面要并进的那个请求里已经有台本自己写的提示（见下面「开头的提示和语速」）、包里有 `dub` 脚本。其中章节、项与项之间、包里有 `dub` 脚本、要加设定的提示这四处，挡不住比 `limits.minChars` 短的一行或一项并过去，见下一条。一小段混着语言的话要留在一个请求里：写在同一行里（一行只挑一段参考，夹着的另一种语言跟着这一行，不停）；或者给 `--language`（整份台本按这一种语言挑参考），或者给一个只在一种语言里有的 `--reference-tag`：这两种，另一种语言的整行用的都是这段参考，是跨语言克隆，常带口音，要加 `--allow-cross-language`，不然 `dub` 停下（第 3 步「默认不带口音」），所以只在使用者要口音时这样给。放不下一个请求的，照下面「长文怎么切」在边界切。这些切口（章节、`.json` 的项与项之间、换声音除外）台本没写停顿的，`dub` 记一个默认的停顿，见下面「长文怎么切」的「切口的气口」。
- **比下限短的照旧并。** 适配器声明了一个请求至少多少字（`limits.minChars`）时，比它短的一行或一项照旧并到下一行（不并就合成不了）：同一个包，参考、语速、起伏、开头的提示一样，中间没写停顿，并起来放得下一个请求，就并，跨章节、跨项、`--no-scene` 时都一样。上一条里的包里有 `dub` 脚本、这一行要加设定的提示而前面已经有台本写的提示，也挡不住它（后一条并过去以后开头的提示怎么加，见下面「开头的提示和语速」）。给了目标时长的一项只和同一项里的并（下面「目标时长」）。`dub.json` 里并起来的是一个 unit，`joined` 列着并了哪几句，`notes` 里有一条 `short_lines_joined`。并完还短的，照上面并进同一个请求以后再判，还不到下限的记成没合成（下面「失败和重做」）。

**长文怎么切**（`lib/dub.mjs` 第 5、5c 步，切口的规则在 `lib/pause-in-request.mjs` 的 `requestsOf`）：放得下就不切，放不下只在边界切。

- **上限。** 一个请求默认不超过约 1000 个要念的字符（英文约 170 个词；`lib/synthesis-limits.mjs` 的 `DEFAULT_MAX_SPOKEN_CHARS`），旁白和一场戏都一样。这是 `dub` 自己默认的切法，不是平台报错的上限：超过了就在边界切开，每个请求里照旧并。适配器声明了 `limits.maxChars`（一个请求最多发出去多少字，连请求开头加的提示）的，也不超过它：两条都要满足。给了 `--max-chars`，只照给的数切（发出去的字），默认的 1000 和适配器的上限都不再管。为什么默认是 1000、模型一个请求装得下多少，看模型说明（例如 `models/scene3.md`「一个请求的上限」）；平台另加的限制（例如网关只等多久），看适配器的说明。
- **两种字数。** 默认的 1000 数的是要念的字：按字符数，一个汉字、一个字母、一个标点各算一个，英文也按字母数，不按词数；方括号的提示不算，尖括号标签的名字不算，成对的标签包住的字照算（语言标签包住的另一种语言的字也算），一个音素标签算一个字；连着的空白（词和词之间的空格、一个请求里行与行之间的换行）算一个，两头的不算。`--dry-run` 汇总里「要念的 N 个字」也是这样数的（`lib/synthesis-limits.mjs` 的 `spokenLength`），是各个请求的字加起来。适配器的 `limits.maxChars` 和 `--max-chars` 数的是发出去的字：每个字符都算，提示、标签、每个空白、请求开头加的提示都在里面。
- **边界。** 台本里非空的一行是一段，行与行之间是段落的边界；只写着一个停顿的一行（`[pause 1.5s]`，或者读成停顿的舞台说明，例如 `（停顿 2 秒）`、`（沉默）`）是场景的边界；停顿写在一行的行尾、行首的（`他出了门。[pause 1s]`、`（沉默）中午……`），照段落的边界算；章节标题（`# 标题`）总是切（比 `limits.minChars` 短的一行或一项例外，见上面「一段话一次请求」的「比下限短的照旧并」）。放得下时，只写着停顿的那一行照旧在请求里：停顿不超过一个请求里放得下的，写在文字里（上面「一段话一次请求」），长过它的照那一节切开。
- **放不下时的次序。** 先在场景的边界切，放得进一个请求的几个场景照旧并在一起；还有放不下的场景，在它里面的行与行之间切；一行自己就放不下，才在这一行的句子之间切（一句还放不下的，在逗号一类的地方切；还超过发出去的字的上限，即适配器的 `limits.maxChars` 或 `--max-chars`，才在字与字之间硬切）。默认的约 1000 个要念的字只切到逗号一类的地方，不硬切：一句没有逗号、又长过它，就整句一个请求，不在一个词中间切开。硬切剩下只有标点的一截，并进前一截。切出来的一块还放不下，只在它里面往下一级切，不和前后的块并。
- **报告。** 因为放不下切开的那一块，`dub.json` 的 `units[i].cutBefore` 写着和前一块切在哪种边界：`scene`（场景）、`paragraph`（段落）、`sentence`（一行里面）。`notes` 里有一条 `cut_to_fit`：`details.maxSpokenChars`、`details.maxChars` 是这一次的两个上限（要念的字、发出去的字；不管的那个是 `null`），`details.cuts` 列着每一处（`unit` 是切口后面那一段的编号，从 0 起；`at` 是边界），一行里面切开的，说明里另写一句。文字输出在那一块下面写「放不下一个请求，在……和前一段切开」。长停顿、章节、换声音切开的不是这一种，没有 `cutBefore`；换了语言切开的，`cutBefore` 是 `language`（上面「一段话一次请求」）。
- **切口的气口。** `dub` 自己切开、台本在切口没写停顿的，`dub` 在切口后一块的前面记一个默认的停顿，`mix` 照它插成静音：540 毫秒，行与行之间、一行里面的句子之间都是这个数（`lib/dub.mjs` 的 `CUT_PAUSE_MS`）。`units[i].pauseBeforeMs` 是这个数，`units[i].cutPause` 是 `paragraph`（行与行之间）或 `sentence`（一行里面），表示这是切口的默认停顿，不是台本写的；文字输出在那一块下面写明。不管为什么切开都加：放不下（`cutBefore`）、行与行之间换了语言（`cutBefore` 是 `language`）、开头的提示不同（含上面那一条「这一行要加设定的提示」）、设定的语速不同、包里有 `dub` 脚本。一场戏太长、`dub` 在行与行之间把它切成几场的（下面「一场戏一个请求」），切口两边是同一个人接着说（前一块最后说话的人就是后一块第一个说话的人）也加，`cutPause` 是 `paragraph`；切口在换人处的不加，靠 `mix` 换人处的规则（下面「拼接」，两边的静音削短，约 0.1 秒）。不加的：台本在切口写了停顿的，照台本；一句话自己放不下、在它中间（逗号一类的地方，或者硬切）切开的，一句话中间不停（`cutBefore` 照旧是 `sentence`）；章节、`.json` 台本的项与项之间、换声音、一场戏的前后，是台本自己的边界（要一口气，在后一块的开头写 `[pause 0.5s]`）；明说分开（`--no-scene`）时的行与行之间，一行一个请求是你要的，照台本的停顿，和以前一样。出处：一段中文长文配了两版来量，整段一个请求那一版，模型在段落交界留了 650 到 740 毫秒的静音（中位数 660）；切开那一版切口两边的块头尾本来只有 90 到 170 毫秒（中位数 120），插的是两者的差（细则和量法见 `CUT_PAUSE_MS` 上的说明）。一行里面句号处量到的 610 到 830 毫秒和段落交界的叠在一起，分不出两种，所以只有一个数。只在一个模型、一段中文上量过：换了模型，块头尾本来留的静音不一样，切口实际的静音也跟着差；要别的长短，在切口写 `[pause …]`。
- **切开的几块接得上的地方。** 用的是同一段参考（参考按语言挑，切开不换；一场戏切成的几场，每个人都用切开以前整场挑到最多的那一段，几场一样，见下面「一场戏一个请求」；单独配的一行照它自己那一行挑）；开头的提示每一块加一次（规则见下面「开头的提示和语速」）。运行环境声明了 `seed-in-request`（它的合成收 `seed`，见 `vocab/capability-signatures.md`），`dub` 给每个请求同一个固定的 `seed`（`lib/dub.mjs` 的 `DUB_SEED`），写在 `units[i].seed`，`capabilities` 里有 `seed-in-request`；没声明的环境，请求里没有 `seed`。同一个 seed 能不能让前后更接近，看模型说明。`--only` 点名重配的一句换一个 `seed`（「失败和重做」）。
- **一块听不到上一块。** 前后只靠同一段参考、同一个 seed、同一条开头的提示接上，所以切点越少越好。平台在前面超时的（例如网关只等几分钟），在那一块中间的场景或段落边界加一个章节标题切开，再跑同一条命令：没变的块原样沿用，不重复花钱（「失败和重做」）。加标题要注意两条：声音标记不跨章，标题后面接着说的不是第一个包的，在标题下一行开头重写 `[voice:名字]`，不写就回到第一个包；章节处 `dub` 不记切口的默认停顿，要和 `dub` 自己切开时一样停一口气，在标题下一行开头写 `[pause 0.5s]`。

**开头的提示和语速**（设定和调用方给的几项：作者把情绪、风格、能量和语速固定进设定，配音时选一套；调用方也可以给这几项，同一项上调用方的盖过设定的）：

- **合成一条提示，写在每个请求的开头。** 情绪、风格、能量每一项先取调用方给的（`--emotion`、`--style`、`--energy`，`.json` 台本里项自己的 `labels`），没有再取设定的，合成一条方括号的提示，例如 `[angry, low energy]`：情绪、风格写成标签词表（`vocab/cues.json`）的规范名字（设定写「生气」，提示里是 `angry`），能量写成 `low energy` 这样。三项都没有就不加。规则的正本是 `lib/dub.mjs` 第 7a 步和 `lib/opening-cue.mjs` 的文件头。
- **说明（`instructions`）不发给模型。** 「带一点四川口音」这种概括的标签，模型不知道具体怎么念。所以 `--instructions`、`.json` 项的 `instructions`、`options.instructions` 都拿掉了：给了就报 `dub_input_invalid`（`--dry-run` 也报，一次能力都不调），`details.field` 是 `instructions` 或 `script[<序号>].instructions`，消息说 `dub` 不再把说明发给模型，要的说法在台本里写具体的提示，写在发生的位置。包里设定的 `instructions`（`references/make-pack.md`「几套设定」）是给写台本的人看的：用了带说明的设定，`notes` 里有一条 `setup_instructions`，`details` 是 `{ setup, instructions, lines, pack? }`（说明原文，哪几句用了这套设定；几个包时每个带说明的包一条，`pack` 是包 ID），叫写台本的人照说明在台本里写具体的：用词、语气词直接写进台词，读音不同的常用字写成读那个音的字，声调、尾音、节奏的变化在发生的那几个字前面写一个短提示（写法见 `models/scene3.md`「写什么」「跨语言和口音」）。`--no-setup`、没用设定、设定没有说明时没有这一条。
- **要短。** 模型只收文字，开头的提示写进每个请求。数法和上限写在 `lib/cue-length.mjs`：合成以后整条不超过 10 个词（`MAX_OPENING_CUE_WORDS`）；汉字、假名两个算一个词，拼音文字按空格数，数字、标点不算。`cueWords` 和两个上限（`MAX_CUE_WORDS`、`MAX_OPENING_CUE_WORDS`）是给调用方用的稳定接口：调用方可以直接 import，在交给 `make-pack`、`dub` 之前自己先查。限长以内的，请求的文字和以前一字不差。
  - 情绪、风格是一下子的声音（叹气、笑、咳嗽这类，`vocab/cues.json` 的 `oneShot`；情绪的值整个得是一下子的声音的一个词，例如 `笑`、`laugh`，`微笑`、`惊叹` 是普通的情绪，照合）：设定的、调用方给的都不加进开头的提示，开头的提示管的是整句怎么说。`notes` 里有一条 `one_shot_style_skipped`，`details` 是 `{ item, style, from, setup?, lines }`（`item` 是 `emotion` 或 `style`，`style` 是那个声音的规范名字；这一句开头台本自己写了提示的不算）。要这一下，写在台本里它发生的地方，例如 `[sighs]`。
  - 兜底：要加的提示合成以后整条超过 10 个词（情绪、风格写了词表以外的一长串），规划时报 `dub_input_invalid`，`details.field` 是 `openingCue`；消息写明办法：用更短的 `--emotion`、`--style` 盖过设定的那一项，或者 `--no-setup`，或者改包里的设定。这一句开头台本自己写了提示的（提示不会发出去）不报。开头的提示加上一个空格，`--max-chars` 剩下的不到 10 个字、这一句又放不进一个请求要切开，也报 `dub_input_invalid`，`details.field` 是 `maxChars`：不切成每段几个字；整句放得进一个请求的照发。做包时设定合成的开头的提示整条超了，也在花钱之前报（`references/make-pack.md`「几套设定」）。
- **加在哪个请求上**：每个请求的最前面一条（单独一个请求的一段，或者并成一个请求的几句、几行，都是一个请求；并起来的按它的第一句算，中间的几行不再加）。并成一个请求的几行，开头的提示只在第一行前面：它跨行还管不管，厂商没写，也没测过（`models/scene3.md`「写在哪里，管到哪里」）。台本在这个请求开头的那一句自己写了提示（方括号的，或者一行开头的舞台说明，例如 `（小声）`），这个请求不加：照台本；同一句被切开的后几段也照这一句的开头算。照台本的只是写了提示的那一行：同一章里接在后面、自己没写提示的一行，前面那个请求里已经有台本写的提示（开头的，或者哪一行行首、句中写的），就不并进去，另起一个请求、加设定的提示（`（小声）快过来。` 下一行 `听我说。`，是两个请求，后一个开头是设定的提示；`快过来。（小声）真的。` 下一行 `听我说。` 也是两个）；前面那个请求从头到尾都是设定的提示，照旧并（`（小声）快过来。[pause 2s]真的。` 下一行 `听我说。`：长停顿把行首那一句切成了自己的一个请求，`真的。` 和 `听我说。` 并成一个、开头是设定的提示）。「前面那个请求」按上限切开之前的那一串算：一行的台本提示因为上限被切进前一个请求时（例如 `（小声）<一长句>。[pause 0.3s]真的。` 正好在 `真的。` 前面切开），`真的。` 那个请求从头到尾是设定的提示，下一行也不并进去，偶尔多一个切点；设定的提示不会丢。同一行里停顿以后的几句照旧接着用行首的提示。例外：适配器声明了一个请求至少多少字（`limits.minChars`）时，比它短的一行或一项照旧并到下一行（不并就合成不了，条件见上面「一段话一次请求」的「比下限短的照旧并」），这一条挡不住它，跨章节、跨项也一样：并起来的请求开头的提示照短的那一行算，它开头自己写了提示的，整个请求不加；下一行都不另加设定的提示（比下限短的 `（小声）快。` 下一行 `听我说，我们没时间了。`，是一个请求，开头没有设定的提示）。句中写的提示照旧在原位、从写的位置起生效，开头照加。一场戏一个请求时，每一轮是这个说话人的一次开头：每一轮各加他自己那个包的设定合成的提示（那一行开头自己写了提示的不加），和一行一个请求时每行加的一样。开头的提示不一样的两句不并成一个请求。开头的提示算进发出去的字（适配器的 `limits.maxChars`、`--max-chars`：切开、并段时给它留出位置），不算进要念的字和字数下限（提示不念）。
- **语速合成以后变。** 语速先取调用方给的（`--speed`、项自己的 `speed`），没有再取设定的；合成能力不收语速（模型说明里写着它收不收语速参数、文字里写放慢有没有效果），所以 `dub` 合成以后把这一段的音频变速（保持音高），规则同「目标时长」的变速：上下限见 `lib/mix.mjs` 的 `SPEED_LIMITS`，超出的按最近的那一头变，要 ffmpeg。变过速的段，`dub.json` 里 `speed` 是 null（`mix` 不再变一次），`speedChange` 写着要的倍数（`wanted`）、实际用的（`speed`）、变速前后多长（`originalMs`、`actualMs`），超出上下限的另有 `limit`。环境没有 ffmpeg：照原长交出，不报错，`speed` 留着要的语速，`speedChange.speed` 是 null，输出里有一条注意 `speed_not_applied`；之后用有 ffmpeg 的 `mix` 拼，它会按 `speed` 变。给了目标时长的一项，语速由目标时长定，调用方和设定的语速都不用。
- **起伏交给合成能力，不变音频。** 取到的起伏（先后见上面选项表 `--expressiveness` 一行）原样传给这些行的每个合成请求（一个人说话的请求和一场戏的请求都传），记在 `dub.json` 和规划的 `units[i].expressiveness`，取到值的话还记着是哪一层给的，`units[i].expressivenessFrom`：`item`（`.json` 项自己的）、`option`（`--expressiveness`）、`setup`（设定的）、`global`（包的全局值），并进同一个请求的几行值一样、来自不同的层时是 `mixed`；包自己会给什么，规划和 `dub.json` 的 `pack.expressiveness`（几个包是 `packs[i].expressiveness`）是 `{ value, from }`，`from` 是 `setup` 或 `global`，指命令行上什么都不给时这个包给的值，`--dry-run` 就看得到（不花钱；文字输出里，全局值单独一行「包给的起伏」，设定的值在「设定」一行），包什么都没给就没有这一项；选中的那套设定写了起伏的，规划和 `dub.json` 里讲用了哪套设定的地方（`pack.setup`，几个包是 `packs[i].setup`）也带着它的 `expressiveness`，不管这一行最后用没用它（`--expressiveness` 或 `.json` 项给了值、盖过设定的，也带着），写台本的人看得到哪个声音固定了值；文字输出的「设定」一行写「起伏 <值>」。不是 0 到 100 的整数（小数、0 到 1 的写法、越界、不是数），报 `dub_input_invalid`，`details.field` 是 `expressiveness` 或 `script[<序号>].expressiveness`，`--dry-run` 也报，一次能力都不调。
  - 都没有就不传：请求、`dub.json` 和没有这一项时一字不差（设定、全局都没写这个值的包也一样）；`dub` 不按场景（对白、旁白）自己填默认值，不给就是环境自己的默认。谁给、给多少合适，看模型说明：`models/scene3.md`「起伏」。
  - 一个请求只带一个值：值不同的行不并进同一个请求（`.json` 的项与项之间本来就是不同的请求；比下限短的并段不跨值；几个包各用各的设定、值不一样的两个人，不并成一场戏，见下面「一场戏一个请求」的「在哪里切开」）。
  - 环境的模型没有这个旋钮的怎么办，见 `vocab/capability-signatures.md` 里 `voice-cloning` 的 `expressiveness`。
- **报告**：`dub.json` 的 `units[i].openingCue`（一场戏是 `units[i].scene.turns[k].openingCue`）：`cue` 是合成的提示，`added` 是加了没有（false 是那一句开头台本自己写了提示），`parts` 是用上的每一项 `{ value, from }`，`from` 是 `caller`（调用方给的）或 `setup`（设定的）。文字输出里每一句下面写着开头加的提示和每一项从哪来。
- 再跑时沿用上一次的文件，要开头的提示、语速和起伏（含设定的、全局的起伏）也都没变（见下面「失败和重做」）。

**一场戏里换人**（几个包配一场戏，`--pack` 给了几次）：换人的地方默认接得紧（`mix` 削到约 100 毫秒，细则见「拼接」）。这一句是拒绝、反驳、不情愿的回应，或者被噎住、迟疑，在这一句前面标 `[pause 0.5s]`（0.4 到 0.8 秒，要多长看戏）；写在舞台说明之后也一样：`（生气）[pause 0.5s]不行，我不去。` 发出去的是 `[生气]不行，我不去。`，停顿在它前面；标的停顿在削过的静音之外另插（合并成一场的，不超过上限的留在请求里，不另插，见下面「一场戏一个请求」的「在哪里切开」）。出处：对话研究里 700 毫秒以上的换人间隔多和不情愿的回应一起出现（Levinson & Torreira 2015）。创作者给的台本常写成「名字：台词」：把前缀换成 `[voice:名字]`（名字是包名或包 ID），不换的话名字会被念出来。没换的 `--dry-run` 会提醒：一句要念的字以给了的某个包的名字或包 ID 开头、后面跟着「：」或「:」，规划的 `notes` 里有一条 `speaker_name_in_line`，列出哪几句（`details.lines`）、建议换成什么；只提醒，不改字，也不换声音。

**一场戏一个请求**（环境声明了 `text-to-dialogue` 和 `scene-in-request`，又给了几个包）：几个人轮流说的一段连续的话放进**一个**请求，出**一个**音频文件（`<序号>-scene.<扩展名>`），不再一行一个请求。`--dry-run` 看得到哪几行成了一场。要点：

- **每一行没有各自的音频。** 一个请求只有一个音频，平台也没有给每一轮的边界或时间戳；`dub.json` 里这一场是一个 unit（`joined` 列着成员行，`scene.speakers` 写着每个说话人整场用的参考段和原因（`scene.speakers[i].pick`：`segmentId`、`tag`、`by` 写整场用的那段的，同上面第 3 步；`crossLanguage` 是这个说话人有没有哪一轮的语言和这段对不上，例如一个角色一场里说了英文和中文，整场只能用一段，对不上的那种语言就是跨语言的，给人看的输出里这个说话人标「有几轮跨语言」；有这样的一轮，没给 `--allow-cross-language` 就停下，见上面第 3 步「默认不带口音」），`scene.turns` 写着每一轮的说话人和话（提示在原位）、这一轮取到的参考（`picked`）和读到的舞台提示（`directions`），`pack` 是第一个说话人的包，`lastSpeakerPack` 是最后一个；这一场的 unit 自己没有 `pick`）。要每行一个文件、或者只重做某一行（`--only` 按 unit 编号，一场是一个编号），用 `--no-scene`（库里是 `options.scene: false`；例外同上面表里的 `--no-scene`：适配器声明了 `limits.minChars` 时，比它短的一行照旧并到下一行，那两行是一个文件，见上面「一段话一次请求」的「比下限短的照旧并」）。
- **每个说话人整场只用一段参考**：他的每一轮先按上面第 3 步的顺序各取一段（`--reference-tag` 点了他的包、他的设定写了 `referenceTag`，就是那个标签的段），整场用次数最多的那一段，并列取先出现的。太长切成几场的，按切开以前的整场数，几场里他用同一段，不在 `dub` 自己切的地方换声音（这时某一场里他说的语言可能和那一段对不上，`crossLanguage` 照实写）。每一轮的提示就写在这一轮的文字里（台本里写的，和舞台说明换成的），原样交给模型；所以情绪起伏大的戏，靠每一轮的提示，不靠换参考段。
- **在哪里切开**：换章、长过 `limits.maxPauseInRequestMs` 的停顿（和「一段话一次请求」同一个上限，每一处各比各的）、语速变了、起伏变了、包里有 `dub` 脚本的包、说话人超过适配器声明的上限（`limits.maxSpeakers`）都是切点，长的停顿留给 `mix` 插。不超过上限的停顿（`[pause …]`、只写着停顿的一行、读成停顿的舞台说明）留在这一场的请求里，不切开，写法和「一段话一次请求」一样：同一行被停顿切开的几段还是一轮，写法接在前一段后面；轮与轮之间（换人，或者同一个人接着说的下一行）写在前一轮的末尾；写法是什么都不加的（例如句号后面）就什么都不加。留在请求里的，`mix` 不再插：这一场的 `pauseBeforeMs`、`pauseAfterMs` 只有这一场头尾的，`scene.turns[i].text` 就是发出去的文字（写法在里面；设定的开头提示不在里面，记在 `openingCue`，发的时候加在这一轮最前面），`notes` 的 `pauses_in_request` 也把它们数上。一场里这样写出来听着怎样，没有人听过。写成方括号提示的停顿（`[沉默片刻]`、`[停了一下]`），`dub` 不当停顿，也不当切点：原样交给模型，停不停、停多长由模型定，换人处这样写推断停得不稳（没有人听过，只有模型判多半停得不够，是线索，`models/scene3.md`「停顿」）；要 `dub` 认它是停顿，写 `[pause …]`（或者圆括号里读成停顿的舞台说明，例如 `（沉默片刻）`）：长过上限的，这一场在那里切开，`mix` 插多长就是多长；不超过上限的写进请求，静音取量过的写法里最接近的那一种。一场放不进一个请求的（上限同「长文怎么切」，要念的字是各轮加起来，写进去的停顿也算），在行与行之间切成几场：换人处，或者同一个人接着说的下一行，不在一行中间切；每一场里照旧几个人一个请求。切开的后一场，`dub.json` 里 `cutBefore` 是 `paragraph`，`notes` 的 `cut_to_fit` 也列着，文字输出在那一场下面写明；切口两边是同一个人的，前面另记约半秒的停顿（上面「切口的气口」）。一行自己就放不下的，单独配（只有一个人说话，照「长文怎么切」在句子之间切）。一场至少两个说话人：只有一个人说话的一段（独白，或者切完只剩一个人）照旧用 `voice-cloning`，按「长文怎么切」放得下就一个请求。
- **太长**：按上限切完，平台还说一场装不下的，不再自动切开，也不重发：那一场记成失败（每个装不下的场各自失败、各有一条 `scene_too_long` 说明，别的场照常配，不会因为几场都装不下而停下），输出里说明是哪一场，在那一场中间加一个章节标记（`# 标题`）把它切成两场（加标题要注意的两条，见上面「长文怎么切」的「一块听不到上一块」），或者用 `--no-scene`。
- 没声明的环境：不按一场戏一个请求配，一个声音一个声音地配；同一个声音接着说的几行照「长文怎么切」放得下就并成一个请求。给了 `--no-scene`：一行一个请求、一行一个文件，同一个声音接着说的几行也分开（一行里放不下的长停顿、放不下一个请求的一行，照样在那里切开，见上面表里的 `--no-scene`）。适配器声明了 `limits.minChars` 时，比它短的一行照旧并到下一行，给没给 `--no-scene`、跨不跨章节都一样（上面「一段话一次请求」的「比下限短的照旧并」）。

**目标时长**（对画面的一句：给视频配一句，台词要对上画面的时间）：一项台本给了目标时长（`--target-duration-ms`，或 `.json` 台本里这一项的 `targetDurationMs`，正整数，毫秒），`dub` 合成以后把这一项的音频变速（保持音高），让它的长度对上目标。要点：

- **一项配成一段音频。** 目标时长对的是一段音频。给了目标时长的一项不和别的项并成一个请求；它自己要是配成了不止一段（中间有请求里放不下的停顿、章节、换声音，行与行之间换了语言或开头的提示（「一段话一次请求」里总是切开的地方），或者一个请求放不下、被切开（「长文怎么切」）），花钱之前就报 `dub_input_invalid`（`--dry-run` 也报）：拆成几项、各给各的目标时长，或者去掉切开它的东西。几个人轮流说的一项进了一场戏（「一场戏一个请求」），一场是一个音频，整场一起变速。
- **变速的上下限同拼接**：倍数是原长除以目标（大于 1 是加快），上下限见 `lib/mix.mjs` 的 `SPEED_LIMITS`（出处在那里，`mix` 的变速用的是同一处）；要的倍数超出了，按最近的那一头变，不硬变。变速要 ffmpeg：环境没有，照原长交出，不报错。
- **语速由目标时长定**：给了目标时长的段，调用方和设定给的语速都不用，报告里它的 `speed` 是 null（不然 `mix` 会再变一次）。
- **报告**：`dub.json` 的 `units[i].targetDuration`：`targetMs`（目标）、`originalMs`（合成出来多长）、`speed`（变速的倍数，没有 ffmpeg 是 null）、`actualMs`（交出去的多长）、`offByMs`（比目标长多少，短了是负数），毫秒都取整；超出上下限的另有 `limit`（`max` 上限、`min` 下限）。`--dry-run` 里只有 `targetMs`。变不到目标的（超出上下限的、没有 ffmpeg 的），输出里有一条注意 `target_duration_missed`，列出每一段的目标、实际、差多少：差得多，改这一句的台词再配（长了删字，短了加字）。文字输出里，每一句下面的括号里也写着目标、原长、倍数。
- 没给目标时长的台本：和以前一样。

**比一比音色**（音色漂移：配出来的声音偏离了参考）：运行环境有 `speaker-verification` 时，`dub` 给每个不是一场戏的请求（一个 unit，可能并了几行），合成出来以后量一次它和所用的那一段参考的说话人相似度。要点：

- **量什么。** 合成出来的音频和这一句用的参考段（`pick.segmentId`）的录音比。量的是模型出的那段：包里脚本改过的、按语速或目标时长变过速的，量的都是改之前的。
- **报告。** `dub.json` 的 `units[i].speakerSimilarity`：`similarity` 是相似度，`segmentId` 是和哪一段参考比的。给了 `--min-similarity`，低于它的那一句 `drifted` 是 `true`（不低于是 `false`），输出里另起一条「注意」列出这几句；没给就只有数，没有 `drifted`。默认阈值要等试听定，现在不给。数的范围看环境的 `speaker-verification`（适配器说明里写）。顶层的 `speakerSimilarity` 写这一次量没量（`measured`）、阈值（`minSimilarity`，没给是 `null`）；环境没有这项能力时，`measured` 是 `false`，`reason` 是 `capability_missing`，每一句都没有相似度：报告里写明没量，不是量过了没问题。`--dry-run` 里也有这一项。
- **一场戏一个请求量不了。** 一个音频里没有每个说话人的边界，那一场的 `speakerSimilarity.speakers` 里每个说话人一项，`status` 是 `unmeasurable`、`label` 是「量不了」，`reason` 是 `scene_in_request`，不调能力。要量，用 `--no-scene` 一行一个请求。
- **量不到、没听成。** 某一路嵌不出声纹（太短、近乎静音），这一句是「量不到」（`status` 是 `no_speech`，`which` 说是合成出来的那一路还是参考那一路）；服务暂时出错是「没听成」（`not_heard`）。都不重试，这一句照样做成。量的时候别的错（401 之类）和合成时一样，停下来。
- **偏了怎么办。** `dub` 只量、只报，不自己花钱重配，agent 也不因为 `drifted` 或数低自己重配：数照实写进 `dub.json`，使用者问音色稳不稳，照实说数。使用者听出偏了，照他的话换一段参考（换一个音色基底标签）再配，用 `--only` 只重做他点到的那几句（标出来的，或者他听出来的），别的句子留着上一次的文件和参考段；包里的设定写了默认参考也可以换。重做时沿用的句子带着上一次的相似度，按这一次的 `--min-similarity` 重标。
- **费用。** 每量一句调一次 `speaker-verification`，花钱之前的费用说明里写着最多几次。

**念完没有**：模型一个请求念不完时不一定报错，是念到一半就停（例如 `models/scene3.md`「一个请求的上限」）。所以每个请求合成成了，`dub` 量一下模型出的那段音频有多长，和按字数估的比：

- **估多长。** 去掉提示以后按 `lib/speech-length.mjs` 的 `SPEECH_RATE` 往快里估（汉字、假名、谚文一种语速，别的字母和数字一种，标点、空白不算；语速只写在那里）。这比量过的说话快（读数：中文每秒 4.2 到 4.7 个字，`models/scene3.md`「一个请求的上限」），估的偏短。
- **报告。** 出来的不到估的一半，`notes` 里给这一段记一条 `speech_maybe_unfinished`：`details` 是 `{ unit, expectedMs, actualMs }`（段的编号从 0 起、估的、出来的，都是毫秒），文字输出里是一条「注意」。这一段照样是 `ok`、照样交出。只抓得到念了不到一半的：少念一两句（例如一行的最后一句没念）出来的还长过估的一半，没有这一条，要靠使用者听出来（下面「认不全」）。
- **不花钱。** 不重试、不报错、不多调用能力。量长度要解音频：WAV 自己解，别的格式要 ffmpeg；量不出的不比，也不说。
- **认不全。** 只认得出停得很早的：念到一半上下才停的，出来的比估的一半长，这里不提醒。所以没有这一条不等于都念完了：交回去时请使用者听每块的结尾（旁白和长文的子 skill，`scenes/narration.md` 第 7 步「看报告，交回去」），agent 自己不转写去对。
- **看到了怎么办。** 报了这一条的那一段，或者使用者听出结尾没念完的那一段，用 `--only <序号>` 重配（环境收 `seed` 的，这一句换一个 `seed`，见「失败和重做」；不收 `seed` 的，每次一般不一样，推断，没测过），或者在中间加一个章节标题把它切短（加标题要注意的两条，见「长文怎么切」的「一块听不到上一块」）；环境声明的 `maxChars` 太大的，告诉适配器的主人。

**拼接**（把各句接成一个音频的人照下面的细则做：命令行的使用者，或者适配器自己拼的）：`joined` 的段（并进一次请求的几句）、变速和换人处的静音的细则，见 `dub-details.md`「拼接的细则」。

- **换人处的静音**（`mix` 做）：相邻两句换了人，上一句尾和下一句头的静音各削到 50 毫秒，细则见 `dub-details.md`「拼接的细则」。
- **`mix`**：把各句接成一个 WAV，按 `dub-details.md`「拼接的细则」做：`node cli.mjs mix <dub 输出目录>... --out <文件.wav>`，只在本地算，不调能力，不花钱。可以给几个输出目录（一个台本拆成几次 `dub` 配的，例如中途换音色基底标签、几个角色要用不同的标签）：按给的次序接成一个文件，目录之间的接法同一个目录里相邻两句（停顿照插，包不同就是换人处，照削，语速照变）。目录之间不另加停顿：两边台本都没写停顿的接缝一毫秒都不插。其中同一个包接着说的（前一个目录最后说话的包和后一个目录第一句的包相同），文字输出点名是哪两个目录之间；要停一口气，在后一份台本开头（或者前一份末尾）写 `[pause 0.5s]`，已经配好的，加上以后用同一个 `--out`、不带 `--only` 再跑那条 `dub`，做好的全部沿用、不花钱，再 `mix`（带着 `--only` 再跑，点到的几句一律重配、再计一次费，见下面「失败和重做」；那个目录里有几句是带着 `--only` 换了 `--reference-tag` 重做的，不带 `--only` 时每一句都比命令里的那个参考，对不上的几句也要重配）。换人处的接缝照上一条削，和同一个目录里一样，不点名。这时句子的号数从第一个目录接着往下数，报告的 `directories` 写着每个目录是成品里的第几到第几句。只给一个目录时和以前一样。句前句后的停顿插成静音，换人处的静音照上一条削；`joined` 的段照那一节的规则；各句的采样率、声道和第一句不同的，统一成第一句的（重采样是纯 JS，不依赖 ffmpeg）。`speed` 不是 null 的句子（`dub` 没变成速的，见「开头的提示和语速」；`dub` 变过的 `speed` 是 null，不再变）：环境有 ffmpeg 就用它 atempo 变速（保持音高；上下限同「目标时长」，超出的按最近的那一头变，报告的 `speedChanged` 里另写 `wanted` 和 `limit`），没有就照原速接上，报告里记一条 `speed_not_applied`，不报错。非 WAV 的句子（mp3 之类）要 ffmpeg 解码，没有就报 `runtime_missing`。有句子没做成（`dub.json` 里不是 ok），或者 dub 中途停下了（`stoppedBy`），就不出成品（`mix_incomplete`）：报错列出是哪几句（`details.failed`），照每一句没做成的原因说怎么办，分法同 `dub` 的输出（下面「失败和重做」）：原样重做就行的（服务暂时出错、这一次没做的）提示先用 `dub --only` 重做；文字被拒的先改台本里这几句的字，再给 `--only`（不是一场戏的一句平台说装不下的，另说把它改短）；比字数下限短的、一场戏装不下的不给 `--only`，说先怎么改台本（叫人加章节标记切开的，同一句里写上加标题要注意的两条，同 `dub` 的输出，见「长文怎么切」的「一块听不到上一块」），改好以后不带 `--only` 再跑那条 `dub` 命令；只给一条重做的命令（`dub` 的输出同样）：文字被拒的和原样重做就行的同时有，先改字，再用一条 `--only` 把两种一起重做，有比字数下限短的、装不下的一场就一条 `--only` 也不给，别的都在不带 `--only` 再跑的那一次里一起重做（先跑一半，没点到的被拒的、装不下的会记成这一次没做，原因就丢了，细则见 `dub-details.md`「失败和重做的细则」）；要先改台本的，都指到 `dub` 的输出或 `dub.json` 里这一句的 `error`；没取回的不叫人重做（见「失败和重做」）。dub 中途停下的，照停下的原因说，引着 `dub` 停下时的说明（`stoppedBy`）：没跑完（`code` 是 `dub_unfinished`）的，提示再跑同一条 `dub` 命令；连着被拒停下的（`dub_text_rejected`，多半是参考或别的输入被拦了），说原样重做还是会被拒，先换一段参考（`--reference-tag`）或者改掉开头的提示（`--emotion`、`--style`、`--energy`、设定写的），换了还被拒才改被拒那几句的字（点名是哪几句，序号同 `--only`）；别的错停下的，先照停下的原因处理好（401 这类要先让使用者处理）。都不给新的 `--only`（停下以后没开始的句子不在 `dub.json` 里，点不全），说处理好以后再跑停下的那条 `dub` 命令，带着 `--only` 的照样带着：去掉了，那条命令里只想给那几句用的 `--reference-tag` 就用到整份台本上，做好的句子也要重配、再计一次费（只有参考是这样：情绪、风格、能量改的是每一句开头的提示，带着 `--only` 没点到的句子也沿用不了）；停在 `dub_text_rejected` 的，换参考的只换 `--reference-tag`、带着 `--only` 的照样带着，换开头的提示的另给两条路：照旧带着 `--only` 再跑，没点到的会记成这一次没做，所以只给没做好的几句换的用 `.json` 台本写在这几项自己的 `labels` 上、命令照旧（`dub-details.md`「只给几句换开头的提示」），整份都换的不带 `--only` 再跑（那条命令里只想给那几句用的 `--reference-tag` 也用到整份台本上，只想那几句用它的，拆成几次 `dub` 再 `mix`，同上面 `--reference-tag` 那一行）；提示里写明不带 `--only` 的那条换了参考、开头的提示，做好的句子也要重配、再计一次费。`--only` 点到的一律重配，所以停下以前这一次做好的几句，提示点名、说从 `--only` 里去掉再跑（停在 `dub_text_rejected` 的也是：换参考的留着它们会照新的参考重配，换开头的提示的 `.json` 那条它们不写新的，留着会照原来的重配）；停下以前就没做成、原样再跑还是做不成的（文字被拒的、比字数下限短的、装不下的），也点名、说再跑之前先改，列在 `details.failed`；给了几个目录时，`details.directory` 点名是哪个目录，`details.failed` 里的号数是那个目录里的。报告里有总时长、接了几句、插了几段静音（次数和毫秒数，只数插进去的，各句音频自带的头尾安静不算）、哪几句变了速、削了几处换人的静音（次数和毫秒数）。

**停顿放不放得下**（计划阶段核，`--dry-run` 也核，一句都没合成、没花钱）：台本里所有的停顿（`[pause …]` 和舞台说明里写的）照拼接的次序加起来，看一份 WAV 装不装得下。成品的格式这时还没有，按参考段估：采样率取参考段里最高的，声道取最多的（mp3 这类读不出声道的当单声道）；外部的参考段、读不到或认不出格式的不算。拼接用的是第一句音频的实际采样率，所以两边可能差在这里：参考段的采样率各不相同，或者合成能力返回的采样率和参考段不一样。差出来的只会在长到十几个小时以上的停顿上，那已经是写错的台本，拼接时照常核，装不下照样报错。一段参考也读不出采样率时，计划里核不了：计划和 `--dry-run` 的输出里有一条注意（`pause_length_unchecked`）说明这一次没核、为什么。装不下报 `mix_too_long`（几处停顿加起来超出的，点名超出的那一处）；单独一处停顿就超过任何采样率都装不下的，读台本时就报 `pause_out_of_range`；报错都说清是台本的哪一处。

**失败和重做**：服务暂时出错的句子记成 `failed`，别的句子照常做，退出 1，输出里给出带 `--only` 的重做命令。比合成能力的字数下限（适配器的 `limits.minChars`）短、和相邻的句子也并不成够长的一段的，也记成 `failed`（`error.code` 是 `text_too_short`，`details` 是 `{ chars, min }`），不调能力，`--dry-run` 里就看得到；输出里单列成「没合成 N 句」，不在重做命令里：重做没有用，改台本让它够长，或者和相邻的句子写在一起。同一个 `--out` 再跑同一条命令，做好的不重复花钱：上一次 `dub.json` 里做成了、文件还在、这一次的请求一模一样的句子不再合成，沿用那个文件（`carriedOver` 是 `true`），`notes` 里的 `carried_over` 和文字输出写明沿用了哪几句。按内容认，不按序号：前面加了章节标题、序号变了也认得出，文件按这一次的序号改名。`--only` 点到的句子一律重新合成：要某一句换一条再配，用它。环境收 `seed`（声明了 `seed-in-request`）时，同一个 `seed`、同样的请求出来的音频是一样的（试听里核过，逐样本一样），所以 `--only` 点到的一句，上一次在同一个 `--out` 里做成了的，这一次的 `seed` 用上一次的加 1：`dub.json` 这一句记着 `seed` 和 `seedChange`（`from` 是上一次的），文字输出在这一句下面写「换了 seed」。这样 `--only` 重配没成（例如服务暂时出错）的，失败的记录里也记着那一次的 `seed` 和 `seedChange`，再 `--only` 它接着往上加，不退回固定的那一个（退回去，配出来正是想换掉的那一条）。从没做成过的一句（第一次就失败了），`--only` 它照旧用固定的那一个：要的是把它做出来，和切开的别的几块用同一个 `seed`。沿用的句子，`seed`、`seedChange` 跟着文件走：记的是那个文件配的时候用的，下一次 `--only` 按它加 1。不是自动重试：只在你点名重配时换。没点到的不比参考段，留着上一次的文件和参考段：偏了的几句换一个 `--reference-tag`、加 `--only` 重做时，别的句子不跟着重配。换情绪、风格、能量、语速和起伏不一样：情绪、风格、能量改的是每一句开头的提示，语速（`--speed` 给的或设定写的）改的是每一句的语速，起伏（`--expressiveness` 给的）改的是每一句传给合成的值（给了、没给之间换也算换了），加 `--only` 也一样，没点到的句子对不上上一次的，记成这一次没做（`skipped`）；只给几句换，见 `dub-details.md`「只给几句换开头的提示」（语速、起伏写在 `.json` 台本那几项自己的 `speed`、`expressiveness` 上）。要整个重来，换一个 `--out`。沿用不比适配器和模型：换了适配器或模型要重配，就换一个 `--out`，或者用 `--only`。再跑之前想知道哪几句会沿用，同一个 `--out` 加 `--dry-run` 看规划。跑到一半被打断的（进程被杀、命令超时）：`dub.json` 是一份没跑完的（`ok` 是 `false`，`stoppedBy` 的 `code` 是 `dub_unfinished`），只列着已经做好的句子，`mix` 不出成品；再跑同一条命令接着做，被打断以前做好的也沿用；带着 `--only` 的那条例外：点到的一律重配，被打断以前这一次做好的几句（`ok`、没有 `carriedOver`）从 `--only` 里去掉再跑才沿用（`mix` 的提示点名是哪几句）。什么算同一个请求，正本在 `cli/commands/dub.mjs` 的文件头「沿用」。服务那头已经做完、只是结果没取回来的句子（适配器标了 `details.unretrieved`）单列成「没取回」，不在重做命令里：再跑同一条命令（或者 `--only` 点到它）会把它重配、再计一次费；不想重配，照输出里写的办法手动取回。手动取回的音频现在还没有办法交回输出目录给 `mix` 用，要出成品就只能重配。`dub.json` 顶层的 `unretrieved` 列出这几句的序号（和 `--only` 的序号一样，从 1 起），看一眼就知道有几句已经生成、只是没取回，每一句怎么取回在它的 `error.details.retrieve`；一句都没有就没有这一项。之后照输出里的 `--only` 命令重做别的句子，没点到的这几句照旧记成没取回（同一个请求才算，认法同沿用），`unretrieved` 和 `retrieve` 都还在，那一次也退出 1。这时照原样再跑那条 `--only` 命令不会重配它们，还会把点到的句子再配一次、再计一次费：要重配，用 `--only` 点到它们，或者去掉 `--only` 再跑（那一次输出的「没取回」一段就这样说）。其余细则（没取回的、文字被拒、停下来的条件、401）见 `dub-details.md`「失败和重做的细则」。

**包里的脚本**：清单 `scripts` 里的 `{ entry, runtime, feature }`，`feature` 是 `dub` 或 `convert`。一个功能只跑登记在自己名下的脚本；没写 `feature` 的不会自动运行（配音指引可以教你手动用）。运行环境完全信任脚本：直接运行，不让使用者确认，不隔离。运行时按名字取：`node` 就是运行命令的 Node，`python` 找 `python3` 或 `python`，别的名字按 PATH 找。缺运行时，只有用到这个脚本的功能报 `runtime_missing`，在合成之前报；`--dry-run` 不报，只在输出里说缺什么。脚本从标准输入读一份 JSON，往标准输出写一份 JSON（什么都不写或 `{}` 是不改）：

- 输入：`{ protocol: 1, feature, hook, pack: { id, name, version }, unit: {…} }`。`hook` 是 `text`（合成之前，`unit.text` 是要说的话）或 `audio`（合成之后，`unit.audio` 是 Base64 的音频，`unit.mimeType` 是它的类型）；同一个脚本两个钩子都会被叫到，没什么要做的就什么都不输出。`convert` 功能只有 `audio` 钩子。
- 输出：`text` 钩子 `{ "text": "改写后的话" }`；`audio` 钩子 `{ "audio": "<Base64>", "mimeType": "audio/wav" }`。别的键、不是 JSON 对象的输出，一律报 `script_output_invalid`，不悄悄忽略。同一个功能有几个脚本时，按清单里的先后一个接一个运行。

**变声和唱歌**：`node cli.mjs convert <包目录> <音频文件> --out <文件>`（`--singing` 是唱歌），缺能力、输出文件已存在、换声的费用说明和脚本，见 `dub-details.md`「变声和唱歌」。

**各个功能要什么能力**：

| 功能 | 必须有 | 有就用 |
|---|---|---|
| 配音（`dub`） | `voice-cloning` | `text-to-dialogue` 加 `scene-in-request`（几个人轮流说的一段话一个请求配完）、`speaker-verification`（每个请求和参考比一比音色）、`seed-in-request`（每个请求同一个 seed，`--only` 重配换一个）、`phoneme-markers`（读音词表的音素写成音素标签；只声明了 `phoneme-in-text` 的，拼音写成 SSML）、增强件对应的模型 |
| 变声（`convert`） | 说话要 `voice-conversion`，唱歌（`--singing`）要 `singing-voice-conversion` | 增强件对应的模型 |

当前运行环境有哪些能力，看接进来的适配器的说明；自己写适配器，见 `dub-details.md`「自己的适配器」。
