# 用音色包配音和变声：主路用不到的细则

这一份是 `references/dub.md` 挪出来的：下面几节是主路用不到的细则，原处留了一行指针。配一段台本、几个角色的一场戏、出成品这几条主路，碰到下面的情况才读对应的一节：有读音词表，有增强件，并进一次请求的段、变速或换人处的静音（「拼接的细则」），失败要重做（「失败和重做的细则」）。变声和唱歌、自己的适配器不在这几条路上，要查时再读。

## 读音词表

4. **读音词表**：包根目录的 `lexicon.pls`（W3C Pronunciation Lexicon，PLS），写法见 `make-pack-details.md`「读音词表」。只换要说的话里的词，台本标记、方括号的提示和尖括号标签原样保留（提示里的词不换，音素也不标进提示；标签名、音素标签里的音素不换，成对标签包住的字照样换，见 `references/markup.md`「尖括号标签」）。`<alias>` 照做。同一个位置几个词条都对得上，长的优先；整段一次换完，换出来的字不再查词表。`<phoneme>` 用不用看环境的声明：
   - 声明了 `phoneme-markers`：拼音（`x-pinyin`）、Arpabet（`x-arpabet`）、日文罗马字（`x-romaji`）写对的，和 `<alias>` 在同一次替换里换成音素标签（拼音一个音节一个标签，别的一个词条一个标签），不转义，规划的 `spoken` 里就是发出去的样子；一场戏一个请求时，每一轮照它说话人的包换。用上的记在报告的 `lexicon.phonemes`，并从 `unapplied` 去掉。
   - 只声明了 `phoneme-in-text`：只用拼音，发送前写成 SSML。句子里用上的记在 `lexicon.phonemes` 和那一句的 `phonemes` 里，并从 `unapplied` 去掉。用上了拼音音素的那一句，整句转成 `<speak>`，句子里的尖括号标签也被转义、到不了模型：这一种的例外，见 `references/markup.md`「尖括号标签」。一场戏一个请求时不标。
   - 没用上的、字母表环境不收的，报在 `lexicon.unapplied`（`reason` 是 `phoneme`）；环境没声明的，音素一律是 `reason: phoneme`；环境收这种字母表、写法对不上的，是 `reason: phoneme_format`（`problem` 是 `term`、`count` 或 `form`）。
   - 这次用上了只写一个字的词条（汉字这类按字面找的字，例如「曾」），规划的说明里有一条 `lexicon_single_character`，`details.terms` 是那几个字（几个包时每个包各一条，说明开头点名包，`details.pack` 是包 ID）：含这个字的每个词都照它念了。照样换，不拦；只想改一个名字，词条写成整个词。

   只有清单的 `files` 列着 `lexicon.pls` 才读：直接改已装的包里的这个文件，清单没列，就当没有词表，报告里 `applied`、`unapplied` 都空。改读音要发新版本，做法见 `make-pack.md`。

## 增强件

6. **增强件**：包里服务 `voice-cloning` 的增强件，递给能力。环境认识对应的模型就用上（报告 `enhancers.used`），不认识就照常生成，`enhancers.statement` 是 `enhancers_not_used`，并附上包的验证记录，让人知道当前环境下效果会差多少。

## 拼接的细则

- 每一句的 `pauseBeforeMs` 挂在句首、`pauseAfterMs` 挂在句末，各按毫秒插静音，不封顶，插多长就是多长（请求里放不下、在那里切开的长停顿，就是这样插回去的；`dub` 自己切开、台本没写停顿的切口，`dub` 记的默认停顿也是，见 `references/dub.md`「长文怎么切」的「切口的气口」）。
- `joined` 的段（一段话的几句并进了一次请求，中间的短停顿用量过的写法写在文字里；或者比字数下限短的几句并在一起）是一段音频：里面的停顿已经在音频里，不再插静音，只看它的头和尾的 `pauseBeforeMs`、`pauseAfterMs`。各句的提示跟着各自的字，在请求的文字里。试运行里并起来的那一截，`pick.directions` 列着每个成员的舞台说明。
- `speed` 不是 null 的（调用方或设定给的语速，`dub` 没变成的：合成时环境没有 ffmpeg，`speedChange.speed` 是 null），拼接的人自己变速：合成能力不收语速。`speed` 为 null 表示没有语速要求（不是 1.0），或者 `dub` 已经变过（`speedChange` 里写着变速前后的长度），拼接的人不再变；台本里写的放慢、加快是提示，交给了模型，不在这里。变速的上下限见 `lib/mix.mjs` 的 `SPEED_LIMITS`（和 `dub` 的目标时长、语速同一处），超出的按最近的那一头变。有 `targetDuration` 的段，`dub` 已经按目标时长变过速，`speed` 是 null，拼接的人不再变。
- 一场戏一个请求的段（有 `scene`，音频文件是 `<序号>-scene.<扩展名>`）：一个请求、一个音频，里面几轮的间隔是模型定的，拼接的人不碰；它的头是第一个说话人的包（`pack`），尾是最后一个说话人的包（`lastSpeakerPack`），`pauseBeforeMs`、`pauseAfterMs` 是场头场尾的。没有每一行各自的音频（要的话，配音时用 `--no-scene`）。
- **换人处的静音**（`mix` 做）：上一句的 `lastSpeakerPack`（没有就是它自己的 `pack`）和下一句的 `pack` 不同（换了人）时，上一句尾、下一句头的静音各削到 50 毫秒，再插这一处标的停顿，没标的约 100 毫秒。不削的话，合成句子头尾的静音相加，换人处会停好几百毫秒，比多数对话的换人间隔长。同一个包接着说的不削；整句低于 -40 dBFS（每 10 毫秒量一次）的不削，报告里记一条 `silent_unit`。

## 失败和重做的细则

平台说一场戏一个请求装不下（`details.problem` 是 `too_long_for_one_request`，也记成 `failed`，也不标暂时出错）：不自动切开，不重发，重做同样的一场还是装不下；`notes` 里的 `scene_too_long` 说明是哪一场，在那一场中间加章节标记（`# 标题`）切成两场，或者用 `--no-scene` 一行一个请求。叫人加章节标记的地方（这里的两种装不下、`mix` 的提示、`notes` 里的 `scene_too_long` 和 `speech_maybe_unfinished`），同一句里都跟着写加标题要注意的两条（`references/dub.md`「长文怎么切」的「一块听不到上一块」）：标题后面接着说的不是第一个包的，在标题下一行开头重写 `[voice:名字]`，不写就回到第一个包；要停一口气，在标题下一行开头写 `[pause 0.5s]`。文字输出里它单列成「装不下」，不在重做命令里，也不给 `--only` 命令：切开以后序号会变，改好以后不带 `--only` 再跑（做好的沿用）。不是一场戏的一个请求也可能这样报（`voice-cloning` 上也可以标 `too_long_for_one_request`，约定见 `vocab/capability-signatures.md` 的 `voice-cloning` 一节；一个人说话和说一场戏用同一个模型时就会）：它不算「装不下」，`--no-scene` 对它没用，照文字被拒列（见下面），给 `--only` 命令，原因下面另写一行：把这一句改短，再照那条命令重做；要切成两个请求的，切开以后序号会变，改好以后不带 `--only` 再跑。两种切法代价不同：在中间另起一行写章节标记的，只有那一章重新切，别的章做好的沿用，不重复花钱；调小 `--max-chars` 的，整份台本都照新的数重新切，比新的数长的请求都会切开，切法变了的做好了也要重配、再计一次费。一场的、一句的装不下都只和那一段的长度有关，不算进下面服务商连着拒 3 句的那个数（开头几句都装不下，也照常往下配，不说成参考被拦了）。`mix` 不出成品时照同样的分法说：装不下的一场、比字数下限短的不给 `--only`，说先怎么改台本、改好以后不带 `--only` 再跑；文字被拒的（连一句装不下的）先说改字（改短），再给 `--only`；原样重做就行的才直接给 `--only`。几种同时有时，`dub` 的输出和 `mix` 的提示都只给一条重做的命令（例外：`notes` 里的 `speech_maybe_unfinished` 照旧另给一条点那一句的 `--only`；有文字被拒的时候别单跑它，把那一句的号并进「文字被拒」一段的那条命令一起重做）：先跑哪一条都只跑了一半，`--only` 没点到的被拒的句子、装不下的一场会记成这一次没做（`skipped`），原因就从 `dub.json` 里丢了，`mix` 再叫人原样重做。所以文字被拒的和原样重做就行的同时有，先改字，再用一条 `--only` 把两种一起重做（`dub` 的输出里这条命令在「文字被拒」一段，「服务暂时出错」那一行不另给）；有比字数下限短的、装不下的一场，一条 `--only` 也不给，改好以后不带 `--only` 再跑，别的没做成的在那一次里一起重做。服务那头已经做完、只是结果没取回来的句子（适配器在报错上标了 `details.unretrieved`，约定见 `vocab/capability-signatures.md`「通用约定」）也记成 `failed`，可不是暂时出错：输出里单列成「没取回」，照适配器给的 `details.retrieve`（用什么取、任务号这类线索）说怎么取回，不放进重做的命令。再跑同一条命令、或者 `--only` 点到它，都会把它重配、再计一次费；不想重配，照 `details.retrieve` 手动取回，可手动取回的音频现在还没有办法交回输出目录给 `mix` 用（要出成品就只能重配）。`mix` 的提示也不叫人 `--only` 重做它，同样写明这两条路。照输出里的 `--only` 命令重做别的句子时，没点到的没取回的句子照旧记成没取回（`failed`，`error` 连着 `details.retrieve` 照上一次的；同一个请求才算，认法同沿用），不记成 `skipped`，所以取回的线索一直留在 `dub.json` 里，`mix` 也不会叫人 `--only` 重配它；`--dry-run` 给同一个 `--out` 也这样标。这时照原样再跑那条 `--only` 命令不重配它，还会把点到的句子再配一次、再计一次费，所以那一次输出的「没取回」一段说的是「用 `--only` 点到它、或者去掉 `--only` 再跑这条命令」，`mix` 说的是再跑整份台本的那条 `dub` 命令。照旧记着的句子，`seed`、`seedChange` 照上一次的，再 `--only` 它接着往上加。输出里打印的重做命令带着这次的适配器（`--adapter`、`--adapter-option`）和标签、设定、目标时长、`--max-chars`、`--concurrency`，照着原样再跑就行。文字被拒的句子（`details.textRejected`，只和这一句的文字有关，换一句就成）也记成 `failed`，只记这一句，别的照常做，不重试，因为换一句才会有不同的结果：它不在「服务暂时出错」那条重做命令里，文字输出里单列一段「文字被拒」，列着每一句的错误码和原因，另给一条点这几句的 `--only` 命令（有服务暂时出错的，连它们一起：几种同时有时只给一条重做的命令，见上面）。先改台本里这几句的字，再跑那条命令；只照原样再跑，还是被拒。调用之前就查出来的（文字空白、太长、有处理不了的字，错误码 `capability_input_invalid`）、平台说一个请求装不下的（上面）不计数；服务商拒的，连着 3 句、还没有一句成功，就和别的错一样停下来（错误码 `dub_text_rejected`，`stoppedBy` 的 `details.rejected` 写明被拒的句子）：这种情况多半是参考或别的输入被拦了，每一句都会这样被拒，停下来才不白花钱。这时原样重做还是会被拒：先换一段参考（`--reference-tag` 换一个音色基底标签）或者改掉、去掉交给模型的说明（`--instructions`，设定写的说明换一套 `--setup` 或者 `--no-setup`），换了还被拒的，多半才是被拒那几句的字的问题，改字；处理好以后再跑停下的那条命令，只换参考或说明：带着 `--only` 的照样带着，只重配点到的几句；不带 `--only` 的，换了参考、说明，参考段或开头的提示变了的句子做好的也要重配、再计一次费（沿用只认同一个请求）。别的错（401、参数不对、缺能力、缺运行时……）直接停下来，不再开始新的句子，已经做好的文件和一份写着 `stoppedBy` 的 `dub.json` 留着：原样再跑多半还会这样停，先照停下的原因处理好，再跑停下的那条命令，带着 `--only` 的照样带着（去掉了，那条命令里只想给那几句用的 `--reference-tag` 这类选项就用到整份台本上，做好的句子请求变了也要重配、再计一次费）。不带 `--only` 的，做好的沿用；带着 `--only` 的，点到的一律重配，停下以前这一次做好的几句（`ok`、没有 `carriedOver`）从 `--only` 里去掉再跑才沿用，被打断的（`dub_unfinished`）也是。停下以后没开始的句子不在 `dub.json` 里，`--only` 点不全，所以 `mix` 遇到停下也不给新的 `--only`，照这样说先处理什么，指到 `dub` 停下时的说明（`stoppedBy`），停下以前这一次做好的几句点名；停下以前就没做成、原样再跑还是做不成的句子（文字被拒的、比字数下限短的、装不下的）也点名，说再跑之前先改，`details.failed` 列着它们：不然照着再跑，它们再发一次、再被拒，还得再来一轮。合成成了（计过费）、合成以后的几步（量念完没有、包里脚本的 `audio` 钩子、目标时长、语速）出错停下的那一句也留着：文件是模型原样出的那段，`dub.json` 里是 `ok`，另记着 `afterSynthesisFailed: { step }`，`step` 是出错的那一步：`speech-length`、`audio-hook`、`target-duration`、`speed`。它不算做完：再跑同一条命令不沿用它，重配、再计一次费，那几步照这一次的环境做。401 说明授权有问题：先让使用者处理好，再接着做（同一句再发还是 401）。

## 变声和唱歌

**变声和唱歌**：`node cli.mjs convert <包目录> <音频文件> --out <文件>`；`--singing` 是唱歌（输入要是人声分轨，没有伴奏）。说话用 `voice-conversion`，唱歌用 `singing-voice-conversion`，缺哪一项，只有这个命令报 `capability_missing` 并点名缺的是哪一项，配音照常。用哪段参考同配音（`references/dub.md`「一句话是怎么变成合成的」第 3 步），只是不能点设定：包里有带 `default` 的那一套就一律用它（它的 `referenceTag`、`labels.language`），没有 `--setup`、`--no-setup`（给了是用法错误）。`--reference-tag <标签>` 盖过设定的默认参考，只给一次，整串是标签；`--language` 是这句的语言，盖过设定的（变声没有台词可认，没给时怎么定见 `lib/convert.mjs` 的文件头）。标签包里没有，报 `reference_tag_unknown`，不调能力、不说费用、不写文件。变声没有情绪、风格、能量的选项（给了是用法错误）。返回的 `pick` 写法同配音的 `units[i].pick`；交给模型的参考文字同配音：参考段有提示标注（`annotatedText`）就交它，没有就交逐字稿。输出文件已经存在就拒绝，不覆盖，而且是在花钱之前就拒绝；接进来的适配器给了费用说明时，该核对的都核对过（能力、脚本要的运行时、用哪段参考）以后、换声之前，在标准错误里说明要调一次哪项能力（`--json` 时不说）。登记在 `convert` 功能名下的脚本在换声之后处理音频；增强件的用法同配音。

## 自己的适配器

当前运行环境有哪些能力，看接进来的适配器的说明。要用别的模型，自己写一个适配器，用 `--adapter <目录或模块文件>` 交给命令：适配器是一个函数，返回一个对象（能力、运行时、网络读取、费用说明等，键都可选，写法见 `adapters/README.md`「返回的形状」）；后给的盖过先给的，也盖过命令已有的同名项。约定只写在 `adapters/README.md`，每项能力的调用参数和返回值见 `vocab/capability-signatures.md`。适配器在本进程里直接运行，不隔离，和包里的脚本一样。
