# Making a new pack from an existing one: clean room and duplicate check

This file holds only the section "The clean room and the duplicate check": read it to make a new pack from an existing one (the path for making your own pack from an existing pack). The body text was not changed when it was moved. It used to be in `references/make-pack-details.md`, and the pointer in `references/make-pack.md` now points here.

## The clean room and the duplicate check

**Making a new pack from an existing one (clean room and duplicate check)**：to make a voice that is "your own", the new pack's description, guidance, lines and recordings all come from the user's own words and from newly made material. That is what makes the new pack new: once the source pack's text or recordings are carried in, it is no longer a new voice. The authoritative flow is `protocol/new-pack/README.md` (how to write each field, who may see what). The commands follow these steps:

1. `node cli.mjs clean-room --output <clean-room input directory> [--name <character name>] [--tags <tag,…>] [--words "<the user's own words>" | --words-file <file>] [--language <language this voice will speak>] [--designed]`: puts the tags from the design lexicon, the user's own words (as given, not rewritten; if the words are long or contain line breaks, use the file form), the language this voice will speak, and the abstract spec and blank templates from the protocol core into a new directory. Give at least one of tags and own words. Give the character name too: the writing session puts it at the start of the audition line and in the name in "what to say when switching language" (`换语言时怎么说`). Give the language too: the writing session writes the example lines and the audition line in it, and if they are written in another language, making the pack cannot dub them (`protocol/new-pack/README.md`「Language」). This step does not read the source pack. What kind of voice the user wants (tags, own words), what language it speaks, the pack name, and designed or recorded are asked first by the product in use; do not make them up for the user (the new pack starts empty, with only what the user said; the source pack is used only for the duplicate check). For a designed voice, add the designed option to the step 1 command: it only records "this voice was designed" in the attributes, and the writing agent does not write a design source because of it.
2. Hand the step 1 clean-room input directory to a newly opened session or sub-agent (if the environment can open sub-agents, open one yourself and give it only the directory and one sentence: "Read BRIEF.md, follow it, and write into output/."; if it cannot, tell the user why a new session is needed and how to open one: open a new session with the working directory set to the clean-room input directory, send this sentence as the first message: "Read BRIEF.md, follow it, and write into output/.", and say so when it has finished writing. The output of `clean-room` contains this ready-made text). The new session follows the `BRIEF.md` inside to write the description, dubbing guidance, example lines and audition line (into its `output/`; it may write the audition line itself or pick one line from the example lines it wrote). It must be a session that has not read the source pack, because text written by an agent that has read the source pack carries traces of the source pack. The new session must be opened where it cannot read the source pack. If the source pack is installed as a skill, its description text (which contains a voice description) is loaded automatically into any session that reads it, so what that session writes is not a clean room; tell the user. When it has finished, look at the items marked `缺` in `output/guidance.md` (the two sections "who this person is" (`这个人是谁`) and "what to say when switching language" (`换语言时怎么说`)): if the user is present, ask them for these items and hand the answers back to the writing session as they are (if it is still open, send them to it; if it has been closed, add the answers to the user's own words, rerun step 1 with a new directory, and hand it to a new session to rewrite). An agent that has read the source pack does not edit the guidance itself. If the user is not present and cannot be asked, leave `缺`, do not make anything up, and tell the user which items are still missing when delivering the pack; the make-pack report's "what material is still missing" also lists these items (`guidance_gaps`), and once they are filled, issue a new version with `--previous`.
3. Prepare the material. Your own recordings: follow `references/make-pack.md`「Recordings supplied by the user」; or design a voice. For a designed voice, the caller writes the design description from the user's words (following `references/character-voice.md`「A designed voice: the description」), designs with the `design` command, and locks the audition (the output of `node cli.mjs clean-room --designed` lists all the commands for the design and the steps after it) (for how, see `SKILL.md` section 2「2. Three ways to make a voice」›「Voice design」); the audition is used only as raw material, and the material is an acted passage dubbed to match it (`references/make-pack.md`「Making a pack from a designed voice」). The design audition text is not written by an agent that has read the source pack: pick one or two lines from the example lines written into `output/` in step 2 and remove the cues (how long, and why no cues, see `references/character-voice.md`「Design audition text when designing」). It is recorded as is in the design source's `auditionLines`; the duplicate check does not compare this item, so copying the source pack's lines would not be caught. The acted passage is also not written by an agent that has read the source pack: join a few example lines from `output/` (step 2) that sound ordinary in tone and connect well; do not write a separate one, and do not write it from the source pack's lines; add the cues following `references/character-voice.md`「Default segment: a passage the character says naturally, with acting」. This passage becomes the verbatim transcript of the new pack's reference segment, and the duplicate check compares it against example lines, not against transcription. The audition line is the same: it is not written or edited by an agent that has read the source pack: use the line written into `output/card-line.txt` in step 2, and do not write it from the `cardLine` in the source pack's manifest; the duplicate check compares it as a line. Record as written the description used in the design, the model and date used, and the audition lines: they are records on the design side, and the clean-room writing agent does not write them (see `protocol/new-pack/README.md`「Design source」).
4. Make the pack, with the duplicate check at the same time. When making the pack, add `--direction`, `--guidance`, `--sample-lines`, `--card-line` (pointing at the four files written into `output/`) and `--source-pack <source pack directory or share file>`; for recordings, add `--source-pack` to the make-pack command for "recordings supplied by the user"; for a designed voice, the material and `--design-source` follow `references/make-pack.md`「Making a pack from a designed voice」, and the four files and `--source-pack` go on the final pack command in step 3 of that section, not on the temporary pack. Before the steps that cost money (cutting segments, transcription, picking the default segment, cue annotation, trial synthesis, dubbing the audition line), compare the new pack's text (description, guidance, example lines, audition line, the design source's description) and recordings with the source pack (on the source pack side, its manifest's audition line is compared too). If too much overlaps, it reports `duplicate_detected`; `details.findings` says which item, how much was measured, and what the threshold is, and not a cent has been spent; rewrite the text in your own words and replace those recordings, then make the pack again. `--dry-run` also runs the check.

The duplicate check compares "text written by the author" and "the same recording": for text it looks at the F1 of the longest common subsequence and the overlap of consecutive word groups; for recordings it uses an audio fingerprint, and it recognises a recording after a change of loudness, re-encoding, resampling, trimming the head and tail, or mixing into a longer recording; another sentence spoken by the same person does not count as reuse. The check compares only these two things; whether the speaker sounds alike, tags, names, transcription, the pronunciation lexicon, and the design source's audition lines (`auditionLines`) are all outside its scope. It cannot catch rewording (writing it again in different words), speed change, pitch change, or reversal, so it is the last gate and must be used together with the clean room. What it compares, the thresholds, and the basis are in the file header of `lib/duplicate-check.mjs` (the data and scripts used for calibration are not published with this directory). The source pack is read only in this step (no signature check, no network); its path, name and pack ID are used only in this step, and none of them appears in the new pack, standard output or the report (the clean room requires the new pack to carry no trace of the source pack); the new pack uses a new pack ID, and the manifest's `madeWith` records only the base part's version.
