# 照一个已有的包做新包：净室和查重

这一份只放「净室和查重」一节：照一个已有的包做新包（照一个包做自己的那条路）读它。挪的时候正文一字没改，原在 `references/make-pack-details.md`，`references/make-pack.md` 的指针指到这里。

## 净室和查重

**照一个已有的包做新包（净室和查重）**：要做一个「你自己的」声音，新包的描述、指引、台词和录音，都从使用者自己的话和新做的素材来。这样新包才是新的：来源包的文字和录音一旦搬进来，就不再是新的声音。流程的正本是 `protocol/new-pack/README.md`（每个字段怎么写、谁能看什么），命令按这几步：

1. `node cli.mjs clean-room --output <净室输入目录> [--tags <标签,…>] [--words "<使用者自己的话>" | --words-file <文件>] [--language <这个声音要说的语言>] [--designed]`：把设计词表里的标签、使用者自己的话（原样，不改写；话长、带换行就用文件那一种写法）、这个声音要说的语言和协议核心里的抽象规格、空白模板放进一个新目录。标签和自己的话至少给一个。语言也给上：写作会话照它写示例台词和卡片那一句，写成别的语言，做包时配不了（`protocol/new-pack/README.md`「语言」）。这一步不读来源包。使用者要什么样的声音（标签、自己的话）、说什么语言、包名、设计还是录音，由使用的产品先问清楚，不替使用者编（新包从空的开始，只有使用者说的；来源包只拿来查重）。设计出来的声音，第 1 步的命令里带上设计那个选项：它只把「是设计出来的」记进属性，写作的 agent 不因它写设计来源。
2. 把第 1 步的净室输入目录交给一个新开的会话或子 agent，由它照里面的 `BRIEF.md` 写描述、配音指引、示例台词和卡片试听那一句（写进它的 `output/`；卡片那一句它可以自己写，也可以从它写的示例台词里挑一句）。由没有读过来源包的会话来写：读过来源包的 agent 写出的文字会带着来源包的痕迹。新会话要开在读不到来源包的地方；来源包如果装成了 skill，它的说明文字（里面有音色描述）会自动载入读到它的会话，这样写出来的就不是净室，要告诉使用者。
3. 备素材。自己的录音，照 `references/make-pack.md`「使用者给的录音」；或者设计一个声音。设计出来的声音，由调用方从使用者的话写设计描述（照 `references/character-voice.md`「设计出来的声音：描述」），设计、试听锁定（做法见 `SKILL.md` 第 2 节「造声音的三条路」的「设计」）；锁定的试听就是素材（`references/make-pack.md`「设计出来的声音怎么做包」）。试听文本不由读过来源包的 agent 写：从第 2 步写进 `output/` 的示例台词里挑一两句，去掉提示（多长、为什么不带提示，见 `references/character-voice.md`「设计时的试听文本」）。它原样记进设计来源的 `auditionLines`，查重不比这一项，照抄来源包的台词也查不出来。它也是新包参考的逐字稿，查重比示例台词，不比转写。卡片试听那一句也一样，不由读过来源包的 agent 写或改：用第 2 步写进 `output/card-line.txt` 的那一句，不照来源包清单里的 `cardLine` 写；查重把它当一条台词比。设计时用的描述、用的模型和日期、试听台词，照原文记下：它们是设计那一边的记录，净室的写作 agent 不写（见 `protocol/new-pack/README.md`「设计来源」）。
4. 做包，同时查重。做包时加 `--direction`、`--guidance`、`--sample-lines`、`--card-line`（指到 `output/` 里写好的四个文件）和 `--source-pack <来源包的目录或分享文件>`；录音的，`--source-pack` 加在「使用者给的录音」那条做包命令里；设计出来的声音，素材和 `--design-source` 照 `references/make-pack.md`「设计出来的声音怎么做包」，这四个文件和 `--source-pack` 加在那一节那条做包命令里。花钱的几步（切段、转写、挑默认段、标提示标注、试合成、配卡片那一句）之前，先把新包的文字（描述、指引、示例台词、卡片试听那一句、设计来源的描述）和录音同来源包比一遍（来源包那边也比它清单里的卡片那一句）。重合太多报 `duplicate_detected`，`details.findings` 写明是哪一项、量了多少、阈值多少，一分钱没花；文字改成自己的话、换掉那几段录音，再做。`--dry-run` 也查。

查重比的是「作者写的文字」和「同一段录音」：文字看最长公共子序列的 F1 和连续词组的重合；录音用音频指纹，换了响度、重新编码、重采样、截头去尾、混进更长的录音都认得出来，同一个人说的另一句话不算复用。查重只比这两样；说话人像不像、标签、名字、转写、读音词表和设计来源里的试听台词（`auditionLines`）都不在它的范围里。它抓不到改写（换个说法再写一遍）、变速、变调、倒放，所以它是最后一道关，要和净室一起用。比什么、阈值、依据都在 `lib/duplicate-check.mjs` 的文件头（标定用的数据和脚本不随这个目录发布）。来源包只在这一步读（不验签、不联网），它的路径、名字、包 ID 只用在这一步，新包、标准输出和报告里都没有这些（净室要求新包不带来源包的痕迹）；新包用新的包 ID，清单的 `madeWith` 只记基础部分的版本。
