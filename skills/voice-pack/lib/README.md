# Workflow layer

Programs of the workflow layer: dubbing and changing a voice with a voice pack, making a pack, picking references, measuring fidelity, duplicate check, and preparing the input for the make-pack agent in the clean room. Every `.mjs` in lib/ has one row in the tables below.

- `.mjs`; for how to write them see `../protocol/README.md`「Module conventions」.
- Anything that needs a model, the network or a command-line tool comes from the injected runtime environment (`env`); when something is missing, throw an error that names what is missing. See the same document, 「Runtime environment」.
- You may use `../protocol/lib/` (the core layer) and `../tools/`, and you may read the JSON vocabularies in `../vocab/`.
- Command-line entry points live in `../cli/commands/`, one command per file.

## Reading a pack, dubbing and changing a voice

Generate sound from a voice pack: dubbing (a script becomes the pack's voice) and voice conversion. Each file header states its own rules; a rule is written there once. The pure-computation files touch no audio and use no model, so every rule can be tested directly with data. The commands are `cli/commands/dub.mjs` and `convert.mjs`; they only read and write files.

| File | What it does |
|---|---|
| `voice-pack.mjs` | `openVoicePack(source, { env, verify? })`: opens a role part for use: reads the manifest and fetches reference audio, the pronunciation lexicon, dubbing guidance, enhancers and scripts on demand. Every external resource is checked when fetched. The size and SHA-256 of files inside the pack were checked when the pack entered the environment and are not recomputed here by default (`verify: true` checks them; publishing a new version uses it to read the previous version). A pack of protocol 1.x or 2.x is not opened: it throws `pack_protocol_old` (`details.protocol`), calls no capability at all, and is not migrated: an old pack uses the base part of its own major version (`../protocol/FORMAT.md` sections 11 and 14). `MIME_OF_FORMAT` maps audio formats to MIME types; the workflow layer writes this mapping only here |
| `dub.mjs` | `planDub` only plans (which reference segment each line gets, what the pronunciation lexicon replaced, the cue added at the start of each request, the pause and speed records; costs nothing). `dubScript` plans, then synthesizes line by line (a speed given by the caller or the setup is applied after synthesis by changing the speed). A temporary service error on a passage, a text the service rejects (`details.textRejected`), or a result the service finished but that was not retrieved (`details.unretrieved`) is recorded as failed and the other passages carry on. A text error found before the call (`capability_input_invalid`) and a request the platform says is too large for one request (`too_long_for_one_request`) are not counted. Dubbing stops when 3 lines in a row are rejected by the provider and none has succeeded yet (`dub_text_rejected`); any other error stops it. When the environment has `speaker-verification`, each synthesized line is compared once with the reference it used for speaker similarity and lines below the threshold are flagged (a scene sent as one request cannot be measured). If the caller passes `reuse`, before spending money it asks for each passage whether the last run produced an identical result; if so, that result is kept and nothing is synthesized (running the command again with the same output directory does not spend again; the rule is in `cli/commands/dub.mjs`). With `only`, just the named passages are synthesized and the others are marked skipped; for a named passage, if the environment accepts `seed`, the seed becomes the previous one plus 1 (`previousSeed`). `only`, reuse and the seed change are computed the same way by `planDub` and `dubScript`, so what the plan shows is what the real run will do |
| `mix.mjs` | `planMix(report)` checks the dub report (if one line was not made, or dub stopped midway, no finished product is produced). `mixParts(env, parts)` joins the lines into one WAV: the pauses before and after a line are inserted as silence; at a change of speaker (two adjacent lines from different packs) the silence on each side is first trimmed to 50 ms; everything is unified to the sample rate and channel count of the first line (pure-JS resampling); a speed that dub did not apply is applied with ffmpeg's atempo (without ffmpeg the line is joined at its original speed and a note is recorded); a non-WAV line needs ffmpeg to decode. For several dub output directories, run `planMix` on each, join them in order into one sequence and pass it to `mixParts`; the boundary between directories counts like two adjacent lines. The speed limits `SPEED_LIMITS` and the speed change itself `changeSpeed` are here; the speed and target duration in `dub.mjs` use them too. Pure computation: calls no capability, costs nothing |
| `convert.mjs` | `convertAudio(env, pack, audio, options)`: voice conversion and singing (`voice-conversion`, `singing-voice-conversion`): turns a piece of audio into the pack's voice while the content, rhythm and melody stay the same. The reference is chosen as in dubbing (`options.referenceTag` → the `referenceTag` of the default setup → the default segment of this line's language); `onPlan` is called before any money is spent |
| `reference-pick.mjs` | `pickReferences(manifest, lines, options)`: picks references by the reference tag the caller specifies (`options.referenceTag`) → the default reference written in the setup (`options.setup.referenceTag`) → the default segment of this line's language; when a tag is set, among the segments of that tag it picks by language. The result records `{ segmentId, tag, by, crossLanguage }`; a tag the pack does not have throws `reference_tag_unknown`. `speaksLanguage` checks whether a segment matches the language of a line (a merged scene uses it to mark a speaker as cross-language). `defaultSegmentFor` finds the default segment of this pack for a line's language (the same layer as when no tag is set; make-pack uses it to check whether the audition line's default segment changed). `pickSetupOf` takes a setup from the manifest as the keys that reference picking reads, and `refTextOf` is the reference text handed to the model (dubbing and conversion both use these two). It does not pick by tag on its own, does not pick by emotion, style or energy, and calls no capability (the rules are written only in the file header) |
| `line-hints.mjs` | Reads cues from a line (pure computation): `readDirections` reads stage directions ((whisper), \*laughs\* and so on) and pauses; `cuesInPlace` turns stage directions into cues left in place (used by dubbing); `detectLanguages` identifies the language by writing system (looking at the main script); `scriptFitsLanguage` checks whether the detected script matches a given language; `canonicalLabel`, `wholeLabel`, `primaryLanguage` and `normalizeLanguage` normalize emotion, style and language tags. The vocabulary is `../vocab/cues.json` |
| `pause-in-request.mjs` | One request if it fits (pure computation; used by dub step 5c in `dub.mjs`): `requestsOf` merges adjacent segments into a few requests (one pause is at most the limit the environment declares, or `DEFAULT_MAX_PAUSE_IN_REQUEST_MS` when none is declared; a long passage is cut and handed to joining; when the character limit does not fit, it cuts at scene, paragraph and sentence boundaries in `BOUNDARIES` order from strongest to weakest; there can be several limits, each measured on its own). `pauseWriting` is the measured way to write a short pause inside a request |
| `cue-length.mjs` | How many words a cue has (pure computation): `cueWords` (a Chinese character or a kana counts as one word, alphabetic scripts count by spaces, digits and punctuation do not count). The two limits `MAX_CUE_WORDS` (one cue in a script) and `MAX_OPENING_CUE_WORDS` (the cue at the start of a whole request after synthesis) are written only here. The three exports are a stable interface for callers: a caller may import them directly and check on its own before handing input to `make-pack` or `dub`. These use it: make-pack checking the opening cues synthesized from a setup (`checkSetupOpeningCues` in `make-pack-input.mjs`), dubbing checking the whole request after synthesis (`dub.mjs` step 7a), and the plan listing the long cues in the script (`long_cues` in `dub.mjs`) |
| `opening-cue.mjs` | The cue at the start of a request (pure computation, `dub.mjs` step 7a): `openingCueOf` combines the emotion, style and energy given by the caller and the setup into one cue in square brackets (emotion and style are written as the canonical names from the tag vocabulary; a one-off sound is not merged in; the description is not in it and is not sent to the model). `withOpeningCue` writes it at the very start of a request's text (whether there is a space between the cue and the text is `cueThenText`; a script piece that holds only a cue and is joined to the start of the next line uses it too). `opensWithCue` recognizes whether a text already starts with a cue |
| `scene-in-request.mjs` | A scene as one request (pure computation, `lib/dub.mjs` step 5a): `sceneRuns` splits consecutive script segments in which several speakers take turns into scenes (a scene that does not fit in one request is cut between lines into several scenes); `mostPicked` takes the one reference segment a speaker uses for the whole scene; `isScene` recognizes whether a unit is a scene; `TOO_LONG_FOR_ONE_REQUEST` is the `details.problem` the adapter puts on the error when the platform says a scene does not fit. The rules for cut points and for picking the reference are written only in the head of this file |
| `cross-language.mjs` | How to say it across languages (pure computation): `languageOfText` decides which language to compare with the reference segment (a given language that the text clearly does not match is overridden by the language recognized from the text), `lineTarget` writes the language of a line as `{ to, script? }` (a given language is written as given; for a recognized one, a language is written only if the script can be only one language, otherwise the writing system is written), `languagePair` writes "reference-segment language→line language" (`ja→en`, `ja→Latin script`), `referenceSources` says where the reference supplemented for the no-accent route comes from (use a recording if there is one; if not, by default dub a passage across languages with this pack, or another voice in the library, and where the platform lets you choose the model, one more option). Dubbing that stops with `dub_cross_language` (`dub.mjs` step 3a) and make-pack's `card_line_cross_language` (`material-hints.mjs`) both use it |
| `cut-at-sentence-end.mjs` | Cuts an overlong acted passage at a sentence end (pure computation, used by `make-pack-take-audio.mjs`): `sentenceEndCut(samples, sampleRate, script)` gives the second to cut at: between 10 and 20 seconds, the sentence end estimated by the proportion of characters and aligned to a pause; if no point can be found it is `null` (no cut); it does not redub |
| `speech-length.mjs` | The minimum time a text takes to speak (pure computation, used by dub step 9a in `dub.mjs`, "did it finish speaking"): `expectedSpeechMs` estimates on the short side from the speech rate (cues and punctuation do not count), `SPEECH_RATE` is the rate (written only here), `UNFINISHED_BELOW` is the ratio of the estimate below which the output is considered possibly not finished |
| `pronunciation-lexicon.mjs` | The pronunciation lexicon (W3C PLS): `parseLexicon`, `lexiconRules`, `applyLexicon`: before synthesis, replaces words in the lines with the intended pronunciation. In an environment that declares phoneme-markers, `applyLexicon` also replaces phonemes (pinyin `x-pinyin`, Arpabet `x-arpabet`, Japanese romaji `x-romaji`) with phoneme tags (`<\|phoneme_start\|>…<\|phoneme_end\|>`); in an environment that declares only phoneme-in-text, `applyPhonemes` replaces pinyin with SSML `<phoneme>` before sending. An entry of a single character gets a warning (`singleCharacterNote`). The parser is written in-house, with no third-party dependency |
| `enhancers.mjs` | How enhancers were used (shared by dubbing and conversion): checks the audio a capability returned against the `enhancers_used` it reported, and summarizes whether this run used an enhancer |
| `pack-script.mjs` | Scripts in the pack: calls a script by the entry and runtime registered in the manifest and reads its answer (`runScript`), checks which runtime is missing (`missingScriptRuntimes`), and lists the scripts that have no registered feature (`scriptsWithoutFeature`) |

## Fidelity

Two methods measure "does the voice generated with the voice pack sound like the character". The authoritative reading is the section "How to read this report" in the header of `fidelity.mjs`.

| File | What it does |
|---|---|
| `fidelity.mjs` | `measureFidelity`, `redoNotHeard`, `planRedo`: the two methods, speaker similarity (divided by the real-person baseline) and blind listening; the report is grouped by the reference set's tags. An item that had a temporary service error is recorded as not heard and can be redone; a blind-listening item whose answer was blocked by the model's provider (`provider_blocked`) is recorded as voided, counted separately, and not redone; a recording from which no voiceprint can be embedded is recorded as not measurable. The pickup check of blind listening (`openingErrorRate`) compares only the first `OPENING_WORDS` words of each audio, not the whole original text; both sides are folded to a normal writing and compared again (katakana as hiragana; when there are Chinese characters, Arabic numerals as Chinese numerals), and the smaller of this and the as-is comparison is taken |
| `fidelity-reading.mjs` | `readReport(report)`: the program form of the reading: banding, which numbers are not scores, voided (including how many were blocked), and how many are not heard and not measurable; the command line (`cli/commands/fidelity.mjs`) and the app both display from its return value and do not each write their own thresholds |

## Making a pack (`make-pack`)

The make-pack flow is in `make-pack.mjs` (the authoritative description of input, options, report and errors is in its file header); it only handles the order. Each step is in its own file, and each file header states its own rules, which fields of an entry it reads and writes, and the errors it throws; a rule is written there once. The pure-data files touch no audio and use no model, so every rule can be tested directly with data.

| File | What it does |
|---|---|
| `make-pack.mjs` | `makePack(env, input, options)`: the make-pack flow, calling the files below step by step: read the input, take the audio, screen the segments, merge sentences, trial assembly and plan (before spending money), transcription, decide the language, pick references, publish a new version, annotate cues, decide the reference tags, adjust loudness, assemble the pack, trial synthesis and fidelity measurement, dub the audition line, write the report. `options.describeChanges` lets the caller write the changes as one sentence itself; when it is not given, the Chinese wording of `pack-version.mjs` is used. `options.textLanguage` (`'zh'` or `'en'`; when not given, Chinese) is the language of the `SKILL.md` skeleton in the pack |
| `make-pack-input.mjs` | Reads `input` and `options`; if they are written wrong, throws `make_pack_input_invalid` (naming the field) before any money is spent, and arranges them into the entries that the later steps read and write |
| `make-pack-precheck.mjs` | Checks the input before the segment preparation that costs money (`precheckInput`): before the command line cuts a long recording or runs a preview (vocal separation, VAD), it first checks the items of `makePack` that can be found from the input alone before spending money (in `makePack`, input and options, the previous version, renaming and the version number are checked first; the named default segments (`assertDefaultsUsable`: two segments named for the same language, not fitting under the reference limit), the setup's `referenceTag`, the trial assembly and the audition line are checked after taking the audio, screening the segments and merging sentences, before the plan), plus the segments to be cut: whether the prefix of a segment name collides with an existing segment name, and whether the long recording's sentences and the sentences in the material are marked the same way in `synthetic` and `annotatedText`. If a problem is found, no capability is called at all |
| `make-pack-take-audio.mjs` | Takes the audio (no cost, before screening the segments): a segment that is not in a format the pack can hold (mp4, mov, mkv and so on with a video track) has its first audio track extracted with ffmpeg and saved as WAV; a segment with start and end seconds written (`trim`) keeps only those seconds. A reference in the pack is audio as before; external resources are not touched. Several segments of the same file are decoded only once. A segment that cannot be extracted, cannot be cut, or overlaps the previous segment of the same file is eliminated, and the reason is written into the report. `trimRange` is which samples to cut; the duplicate check cuts the same way |
| `make-pack-screen.mjs` | Screens the segments (no cost): recognizes the format, runs the duplicate check, measures sound quality (warns only, does not eliminate), and eliminates segments that cannot be recognized, duplicates, and segments that cannot be decoded; when a new version is published, the segments brought over from the previous version are only measured, not eliminated |
| `make-pack-plan.mjs` | The plan (no cost): after screening, the most times each capability will be called and how many segments of material are usable (`plan`; what the user confirms before the first capability call is this) |
| `make-pack-transcribe.mjs` | Transcribes the segments that have no text; after transcription decides where each segment's text comes from, and eliminates a segment with no word at all; after cue annotation, for a Chinese segment given the original script text, writes the stretches that read alike in the script's way of writing (`writeFromScripts`) |
| `script-writing.mjs` | For a recording dubbed from a script, writes the stretches of the transcribed text that read the same as the script in the script's way of writing (pure functions): `writtenFromScript`, `annotationWrittenAs`, `readsAlike`, and `readingOf` for comparing characters by reading (the marker of one character's toneless reading). make-pack uses it for Chinese segments given the original script text (`scriptText`), after cue annotation; the rules are in the file header |
| `mandarin-readings.json` | The reading table used by `script-writing.mjs` (data, not a program): the toneless Mandarin reading of every Chinese character (the first value of kMandarin in Unihan); its origin and the original text of the Unicode license are in the file. Other programs that compare characters by reading use `readingOf` of `script-writing.mjs` and do not read it directly; if its format or location changes, say so in the CHANGELOG |
| `designed-pack-steps.mjs` | The commands for the steps after a designed voice, from the locked audition to the pack handed over: `design` and `clean-room --designed` both print them |
| `make-pack-tags.mjs` | Language and reference tags (no cost): decides each segment's language (given by the material, reported by transcription, recognized from the text; one that cannot be recognized is eliminated); checks that the setup's `referenceTag` matches, once before spending money and once after payment; after cue annotation decides each reference segment's reference tag (given by the material, brought over from the previous version, the name the model gives along the way while annotating cues, and failing all of these the segment name; a name that collides within one language gets a sequence number), and who decided each item |
| `make-pack-sentences.mjs` | Merges sentences into segments (no cost): the sentences of a long recording (sentence mode), before transcription, are grouped by the language and sample rate given by the material (not split by the language transcription reports), and each group is merged in the original order into segments of 5 to 20 seconds, after which each segment is transcribed once (sentences are not transcribed one by one and not listened to one by one first); adjacent sentences keep their original pause, and 0.3 seconds of silence goes between the others; a segment is marked only if every sentence in it is marked `synthetic`, and a segment is joined from cue annotations only if every sentence was given a cue annotation; synthesized segments are screened as usual |
| `make-pack-pick.mjs` | Picks references: hands the entries to the rules of `pack-material.mjs` and writes the conclusion back to the entries; throws an error when no segment is usable, when a named default segment does not match (or two segments are of the same language); when a language's default segment is not decided, and the environment has a model that can listen to audio, it asks that model to pick (`default-pick.mjs`, once per language); if there is none or it did not manage to pick, and the environment has speaker similarity, it measures every pair of references once and picks the most typical segment; an error while asking or measuring (not an abort, not a 401) falls back, and the report states the reason |
| `default-pick.mjs` | Has a model that can listen to audio (`audio-text-to-text`) pick, among several candidate segments, the most natural one with acting as the default segment: one call hands over all the candidates (at most `MAX_PICK_CANDIDATES` segments); the pickup check is the same as in blind listening and compares only the first `OPENING_WORDS` words of the picked segment; an answer that cannot be read, did not finish normally or was blocked is voided (no retry); a temporary service error asks again by the rules of `call-attempts.mjs` |
| `make-pack-annotation.mjs` | Annotates cues: after the reference set is picked, decides the cue annotation (`annotatedText`) of every reference segment newly added in this version: material that gave one is used as given, what the previous version brought over stays as it was, and every other segment is handed once to `segment-annotation.mjs` to listen to and to `point-measure.mjs` to measure pauses and speed (a temporary error follows the rules of `call-attempts.mjs`, listening is asked at most 3 times; for a segment whose material gave no reference tag, a short name is asked for along the way while listening); the held-out recording is not annotated; a segment that was not annotated keeps only its verbatim transcript, and the report states which segments and why |
| `make-pack-loudness.mjs` | Adjusts loudness: the references and held-out recordings written into the pack are unified to the target loudness (the rules and what the report records are in the file header, how it is adjusted is in `../tools/loudness-normalize.mjs`); a segment left unchanged gets its reason written |
| `make-pack-assemble.mjs` | Assembles the pack: trial assembly (before spending money), the path of each segment and the audition line in the pack and how they look in the manifest, and calls `packRolePart` to make the role part |
| `make-pack-card-line.mjs` | The audition line: before spending money it plans dubbing it with the trial-assembled pack (an error if it is not exactly one request); after the pack is made it hands it to `dub.mjs` to dub with this pack (no setup and no reference named), and if the dubbing did not succeed it is only recorded in the report. When this line was handed in and the request is identical to the previous version's line (the user redubs with the same text), and the environment accepts a seed, a different one is used: the previous version's seed plus 1 (`cardLine.seed` in the manifest), and the seed used is recorded in the manifest and the report. When publishing a new version without this line given, the previous version's line is carried over as it was (its seed comes with it), and the report compares whether it still matches the current way of dubbing (`carriedCardLine`) |
| `make-pack-trial.mjs` | Trial-synthesizes the held-out recordings (a temporary error follows the rules of `call-attempts.mjs`, at most 3 tries per item; `envForPackDub`, also used to dub the audition line); every synthesized line is checked before its fidelity is measured, and one whose silence share or duration does not match is voided and does not enter the ratio (`checkSynthesized`); measures fidelity and writes the verification record; the environment used for trial synthesis (external resources use the bytes in hand) |
| `make-pack-report.mjs` | The report: where every segment ended up, `dryRun` and the final return; what material is still missing (`material-hints.mjs`) is also computed here |
| `pack-material.mjs` | Picks material (pure data): which become references and which become held-out recordings (a held-out recording is never a reference), one default segment per language, and the main language (a carried-over one, one the model picked, the most typical by average similarity, one by priority; the model's pick and the similarities are given by the caller) |
| `segment-annotation.mjs` | Has a model that can listen to audio (`audio-text-to-text`) annotate a recording with cues: asked once, then joined with the pauses and speed that `point-measure.mjs` measured: it hands over the verbatim transcript with the first `OPENING_WORDS` words removed, and the answer is a fixed-format `opening` and `cues` (`{ cue, before }`), plus a `name` when a name is wanted (`nameOf` turns it into a reference tag); the pickup check is the same as in blind listening; it inserts the cues into the verbatim transcript according to `cues` to build `annotatedText` (`insertCues`, the transcript is not changed by a single character), and a cue whose original text cannot be found is dropped; an answer that cannot be read, did not finish normally, failed the pickup check, has not one cue matching the original text, or was blocked by the provider voids this segment (no retry). Other programs that annotate a reference with cues follow the way written here |
| `point-measure.mjs` | `measurePoints`, `speechChunks`, `alignChunks`, `pointsOf`, `clauseStartsOf`, `clauseFinder`: cuts speech chunks, transcribes each chunk once, aligns the characters, computes the pause before each chunk and the characters per second of each clause, and converts them to `[pause]`, `[short pause]`, `[faster]`, `[slower]`; when measuring fails it returns the reason and does not block the annotation |
| `recording-noise.mjs` | When a voice is made from recordings, says on the spot how noisy they are (pure computation, costs nothing): `recordingNoiseNote` takes the signal-to-noise ratio already measured by the quality check (median under 25 dB) and the sample rate (16 kHz or less), and gives one `recording_noisy` note when either holds; a designed voice is not reported; the basis of the lines is in the file header |
| `material-hints.mjs` | "What material is still missing" (pure data): one code per rule, the thresholds are in the file header |
| `pack-version.mjs` | Publishes a new version: reads the previous version, computes the version number, compares the two versions, the description in effect for this version, does not publish when nothing changed, and generates the changelog (in Chinese; a caller that wants another wording gives `options.describeChanges` to `makePack`, and its return value also passes through `fitChangelog` here to be trimmed to the length the manifest allows) |
| `design-vocab.mjs` | A voice tag can only be taken from the design vocabulary (pure data) |
| `pack-setups.mjs` | Saves or deletes a setup of a pack's current version in place (no new version): `saveSetup(files, setup)`, `deleteSetup(files, name)`; `files` is the role part's file set (`Map<path, Uint8Array>`), and the return is `{ changed, report }`: `changed` is the files to write to disk (`manifest.json`, and `SKILL.md` if it changed), and `report` is `{ status: 'added' \| 'replaced' \| 'deleted', name, setups }`. It does not modify the file set passed in and does not touch the disk (writing to disk is the job of the command `setups`). A setup of the same name is overwritten; when saving with `default: true`, the `default` of the other setups is removed; if all are deleted the manifest has no `setups`. Before acting it checks that the pack is intact, and after the change the whole manifest is handed to `validateManifest` (a failure throws `pack_setup_invalid`, `details.problems`); a name that does not exist throws `setup_not_found`. The one sentence in `SKILL.md` that depends on the setups (whether a setup wrote `referenceTag`) is regenerated from the current manifest; for a `SKILL.md` that was not generated by the library, only that sentence is replaced; when the new value equals the old, `changed` is empty. The rules, how `SKILL.md` is handled, and that two processes changing the same directory at the same time are not handled, are all in the file header |

Used before `makePack`:

| File | What it does |
|---|---|
| `long-recording.mjs` | `prepareLongRecording(env, recording, options)`: long recording → (separation) → cut into segments → transcribe segment by segment, producing `input.segments` and `input.notes` of `makePack`. If the environment has `voice-activity-detection` it cuts with it, otherwise by energy (`../tools/silence-split.mjs`); the input, the output and the rules of each step are in the file header |

## Clean room and duplicate check for a new pack

To make a new pack from an existing one, the source pack's text and recordings must not be carried over (the authoritative flow is `../protocol/new-pack/README.md`). The commands are `cli/commands/clean-room.mjs` (generates the clean room input) and `--source-pack` of `make-pack` (the duplicate check); the commands only read files, the rules are all in these files, and each file header states its own rules.

| File | What it does |
|---|---|
| `clean-room.mjs` | `buildCleanRoomInput({ protocolCore, attributes })`: a pure function that takes only the protocol core and the attributes the user stated (tags, their own words, language, whether it is designed), and assembles the clean room input: task description, abstract spec, field format, blank template, attributes. It does not take the source pack and cannot: the keys of the arguments are a whitelist, so nothing of the source pack can be in the clean room input |
| `duplicate-check.mjs` | `checkDuplicates(env, { candidate, source })`: compares the new pack with the source pack by text and by recording, and throws `duplicate_detected` (which item, how much measured, what threshold) when the overlap is too large. The threshold is written only here, with the basis of its calibration; `materialOfInput` and `materialOfPack` arrange the two sides into what is compared |
| `text-overlap.mjs` | `compareTexts`: three measures of text overlap (ROUGE-L F1, the share of the candidate that is copied, the share of the source that is carried away), by character for Chinese and by word for Latin script |

Audio fingerprinting (finding "the same recording") is in `../tools/audio-fingerprint.mjs`, a small computation-only tool. The data, scripts and per-item results used to calibrate the thresholds are not shipped with the base part; the thresholds and their basis are written in the header of `duplicate-check.mjs`.

## Turning an old voice into a voice pack (migration)

How a voice from before voice packs (only one reference recording and its verbatim transcript, plus display text such as a blurb, gender, age range and tags) becomes the part of a voice pack that belongs to it: the rules are written only here, and the app embedding this library and the server's migration program both call it, each not writing its own copy. Pure data: touches no audio, does not use the network or a model, and runs in both the browser and Node.

| File | What it does |
|---|---|
| `legacy-voice.mjs` | `convertLegacyVoice(voice, options)`: a whole old voice → one reference set segment named `default` (verbatim transcript, language tag) plus dubbing guidance (voice description, voice tags); when it cannot be converted it returns the reason (no name, no text, text too long) and does not throw; `legacyDirection` (converts only the guidance). Only tags the design vocabulary recognizes are kept; tags it does not recognize and usage words go into `dropped` and are not carried into the pack; a publishing form that needs them kept as they are passes `unknownTags: 'keep'`. Avatar, license and URL are not in what comes out |
| `language-tag.mjs` | `languageTagOf(displayName, text)` and `languageLabelOf(tag)`: in the app a voice's language is a display name (中文, English), while the pack's manifest needs a BCP 47 tag (zh, en). When the name is not recognized, it is recognized by the writing system of the text (Chinese characters zh, kana ja, hangul ko); if that fails too it is `und`, no guessing. `isLanguageTag` is the way to write a language tag the manifest can hold (correctly formed, at most 35 characters); make-pack, long recording and the clean room input all use it to check language tags, and the form is written only here. A separate file that imports no other module: every page of the app has to read a voice's language and must not pull in the vocabulary for it |

## Adapter check and skeleton

The adapter convention is written only in `../adapters/README.md`; here are the programs that check an adapter and generate one. The commands are `cli/commands/adapter.mjs` (`adapter new`, `adapter check`), which only read and write files; the rules are all in these two pure-function files.

| File | What it does |
|---|---|
| `adapter-check.mjs` | Pure functions that run in the browser, Node and Bun; they take the object an adapter factory returns (or a runtime environment): `checkAdapterShape` (container and types, used when the command line loads an adapter), `checkAdapterStructure` (structure check, calls no capability), `planLiveCalls` and `checkAdapterLive` (really call each capability once with a very short input and check the return), `checkCapabilityResult` (checks one return of one capability). An app's tests can call it directly to verify the environment the app assembled itself. The problem codes, the reasons a live call skips a capability (`SKIP_REASONS`, of which `no_signature` and `not_wired` mean respectively not in the signature table, and in the signature table but not wired into the check) and the return rules of each capability are in the file header |
| `adapter-check-voice.wav`, `adapter-check-voice.json` | The human voice used by the live-call check (data, not a program): one person reading one sentence, a 16 kHz mono 16-bit WAV, 5 to 8 seconds. The json beside it holds the verbatim transcript (`text`, which voice-cloning uses for `ref_text`), the description used while reading, the source and the date. `cli/commands/adapter.mjs` reads it and passes it in through `voice` of `checkAdapterLive`; the library does not read files |
| `adapter-skeleton.mjs` | A pure function: the skeleton that `adapter new` generates. `parseSignatureDoc` reads the description, call form and parameter names of each capability from `../vocab/capability-signatures.md` (the comments and the function parameters are generated from it, not copied); `generateModuleSkeleton` generates the module skeleton; other kinds are generated by an official adapter's own `skeleton.mjs`, and the context it receives and the shape it returns are in the file header |

## Small things several modules share

One thing is written in one file, and the other modules refer to it.

| File | What it does |
|---|---|
| `capability-calls.mjs` | A few small functions shared when calling a required capability: `isServiceError` (whether an error a capability threw is a "temporary service error", by `details.transient`), `isProviderBlocked` (blocked by the provider: the code `provider_blocked`, or a temporary error whose `details.problem` is `provider_blocked`; used by transcription), `summarizeError` (the error summary that goes into a report), `badResult` (a capability's return does not match the convention; builds `capability_result_invalid`), `pool` (splits a batch of jobs across several concurrent workers; once there is an error no new job is started), `reportedModel` (the model reported in a capability's return, and `modelChange` when the model was changed, see `adapters/README.md`「When the model changes」) |
| `input-batches.mjs` | Splits a very long input into several requests (pure computation): `splitBatches` packs the input into batches by the input limit a model accepts in one request (`limits.maxPromptTokens` declared by the environment), measured by the UTF-8 byte count of the prompt, and an item that alone exceeds the limit is listed on its own; `askBatches` asks batch by batch, and a batch whose answer was truncated is split in half and asked again; `utf8Length`. The app's text features use it; the base part's own commands do not use it now |
| `manifest-limits.mjs` | The length limits of the long and short text fields in the manifest (`LONG_TEXT_MAX`, `SHORT_TEXT_MAX`), read from the manifest schema of the protocol core, so the workflow layer does not copy the numbers; the form of a language tag stays in `language-tag.mjs` (which imports no other module) and has to match the form in the schema |
| `event-loop.mjs` | Lets the event loop turn once: `turnEventLoop` (waits for one macrotask, using `MessageChannel`), `nowMs` (the clock that measures "how long it has worked continuously"), `YIELD_AFTER_MS` (50: after working this long continuously, yield one turn). Cutting and compiling segments of a long recording (`long-recording.mjs`) and make-pack's segment screening (`make-pack-screen.mjs`) both use it: when a synchronous job runs long the page freezes, and in the browser `await crypto.subtle.digest` does not let the event loop turn, so you have to yield yourself |
| `synthesis-limits.mjs` | The few synthesis-request limits that the base part sets itself: the minimum a declared `maxChars` may be (`MIN_MAX_CHARS`), which dubbing, make-pack's audition line dubbing and the adapter check all check against instead of each writing a copy; the default maximum number of spoken characters in one dubbing request (`DEFAULT_MAX_SPOKEN_CHARS`, 1000, the source is in the file header), and how those characters are counted (`spokenLength`: by character count, cues and tag names do not count, consecutive whitespace counts as one, characters wrapped in a language tag count as usual, and one phoneme tag counts as one character); dubbing's request splitting and the summary of `dub --dry-run` both use it |
| `../protocol/lib/word-spacing.mjs` | Whether to put a space where two pieces of text are joined (pure computation): `writtenWithoutSpaceBetween`, `joinWritten`, `endsWrittenWithoutSpaces`, `spaceAfterCue` (whether to leave a space after a cue is removed), and their character classes. It sits in the protocol core (the preview card uses it too), and the rules and character classes are written only there. These use it: make-pack joining sentences (`make-pack-sentences.mjs`), cue annotation deriving the verbatim transcript (`make-pack-input.mjs`), dubbing merging lines and writing pauses inside a request (`dub.mjs`, `pause-in-request.mjs`), and whether there is a space between a cue and the text (`cueThenText` in `opening-cue.mjs`, `dub.mjs`) |
| `call-attempts.mjs` | The most times a capability call for one recording may be tried, and how long to wait after a temporary error before trying again; the rules are written only here. These use it: make-pack's transcription (`make-pack-transcribe.mjs`), picking the default segment (`make-pack-pick.mjs`, `default-pick.mjs`), annotating cues (`make-pack-annotation.mjs`, `segment-annotation.mjs`), trial synthesis and the audition line (`envForPackDub` in `make-pack-trial.mjs`), long recording (`long-recording.mjs`), and the app's audition listening. `callWithRetries` (at most `MAX_ATTEMPTS` times per segment, tried again only after a temporary error, waiting `RETRY_DELAYS_MS` before each retry: 5 seconds, 15 seconds), `extraAttempts` (the upper limit of extra listening, the number the user agreed to in "Confirm cost"), `spent` (hands back unchanged a failure whose attempts have been used up). The file header also says why these numbers, and how it is measured whether a failed transcription is charged |
