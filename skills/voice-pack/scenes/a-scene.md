# A multi-person scene (including one person playing several parts)

**When to use this document.** Read this one when two or more characters take turns speaking in one continuous scene and the result is one whole piece: a scene of a radio drama, a story with several characters, a conversation among several people. When one character (one pack) plays several roles inside one passage, also read this one; the method is in "One person playing several roles". For one or two lines a character says to someone, read `scenes/one-line.md`; for narration and long text, read `scenes/narration.md`.

## What fit means

- **Gap before the next line**: most speaker changes follow very closely; only a refusal, a rebuttal, or a reluctant response is preceded by a long pause (in conversation research, turn gaps of 700 milliseconds or more mostly occur together with reluctant responses, Levinson & Torreira 2015).
- **The later line responds to the earlier one**: you can hear that it follows what the other person said.
- **Emotion carries across lines**: if the previous turn turned into a quarrel, the next turn does not suddenly go flat.
- **The voices stay distinct and do not bleed into each other**: each person is himself from start to end.
- **Loudness is consistent across speakers**.

On the dubbing model (`models/scene3.md`) only four things can be moved: how much goes into one request (one request for the whole scene, or one request per line), what words and cues to write, which reference segment to use, and how to stitch after dubbing. The steps below settle these four in turn.

## Steps

1. **Identify the speakers.** List which speakers this scene has and which pack each uses; pass `--pack` once per pack. If one pack has to play several roles, first read "One person playing several roles" below. For each pack, read its `SKILL.md`: the dubbing guidance (`### 音色` voice, `### 演法` acting style, `### 台词` lines) and the reference tags listed by language in the reference set. Done when: for every line you know which pack says it.
2. **Decide merged or separate.** When the runtime environment declares one request per scene (`text-to-dialogue` plus `scene-in-request`), `dub` by default synthesizes a passage where several people take turns as one request; when it does not declare it, the voices are dubbed one voice at a time and then stitched (several lines of the same voice in a row are merged into one request when they fit, `references/dub.md`「How long text is split」). The default is to merge (requirement: what the author of `models/scene3.md`「Good examples」 said on 2026-11-04, "otherwise the acting effect is not enough"; that merged acting is better and the replies more natural is inference: one person listened blind on the first page, a merged scene is smoother for a steady scene, and for a scene with emotional ups and downs the separate version was the best); this is a default and not fixed, and the trade-offs of the two ways are in "Merging and splitting" below. By default one request is about 1000 characters (of what is read: cues and tag names are not counted, consecutive whitespace counts as one, about 170 words in English; for how they are counted see `references/dub.md`「How long text is split」), cut at paragraphs and speaker changes: a long scene is cut by `dub` itself between lines into several scenes, each scene is still merged as before, each person uses the same reference segment in all of the scenes, and nothing is cut in the middle of a line (except a line that does not fit by itself: it is dubbed alone, and cut between sentences). Do not add `--max-chars` yourself. In these cases pass `--no-scene` to dub separately:
   - the user hears that someone's timbre is wrong, or wants them separate (step 8);
   - you need one file per line, only one line redone, or timing by line (subtitles, picture). Exception: when the adapter declares a minimum number of characters per request (`limits.minChars`), a line shorter than it is still merged into the next line, and those two lines are one file (`--no-scene` in `references/dub.md`);
   - the pauses must be exact.

   When merged into one scene, a pause written in the script (`[pause …]`; a stage direction in round brackets that reads as a pause, for example `（沉默）`, "(silence)", also counts) that is longer than the limit for one pause inside a request (the adapter's `limits.maxPauseInRequestMs`, default 750 milliseconds when not declared) cuts the scene there, and the parts are dubbed separately, and before and after the cut they are no longer acted together; one that does not exceed the limit stays in the request and is not cut, and is written in the form that was measured, and the silence is not inserted; how this sounds when written inside a scene nobody has listened to (the facts are in `references/dub.md`「One request per scene」›「Where to split」). So decide this first, then write the script: where the acting must run on in one breath, do not write a pause longer than the limit, and leave the pause at a speaker change to the model; write a pause longer than the limit only where you really want a split.
3. **Revise the script.**
   - One line per turn: each turn of each speaker starts on a new line, and the line starts with `[voice:<pack name or pack ID>]`, including the turns of the first pack. If the script is written as "name: line", replace the prefix with `[voice:<pack name or pack ID>]` (where the character name and the pack name differ, write the pack name, otherwise `voice_unknown` is reported); if you do not replace it, it is read aloud (inference: these characters are sent to the model as they are, not tested specifically). Only when the prefix is exactly the name or pack ID of one of the packs given does the `notes` of the `--dry-run` plan have a `speaker_name_in_line` entry listing which sentences; other names are not flagged, so check yourself. The speaker marker (`models/scene3.md`「Speaker markers」) is written by `dub` from `[voice:]`.
   - Colloquial: for the wording follow the `### 台词` (lines) section of the dubbing guidance in this person's own pack, written as `scenes/one-line.md` step 2 item 3 says; for his attitude toward each person in the scene, follow the `对不同的人` ("toward different people") item under `### 这个人是谁` (who this person is).
   - When making it colloquial or adjusting sentence breaks, lose no speaker marker, and keep the words of two people each on their own line.
   - Write stage directions as cues (`[sighs]`), so that the words to be read contain only lines. `dub` also converts what is written in brackets into cues, with the rules in `references/markup.md`: every bracket (full-width or half-width) of 30 characters or fewer is treated as a stage direction, and is not read even when the lexicon does not recognize it. When `dub` converts one, it moves the words inside the brackets into square brackets as they are, without shortening: so turn a long stage direction into a cue of two or three words yourself first, and the meaning is written more exactly. Body text inside brackets in the source that is to be read must first be rewritten without brackets (commas, dashes); for ones you missed, the `notes` of the `--dry-run` plan has an `unrecognized_directions` entry that lists the brackets it did not recognize; but it does not list all of them: a bracket that contains a word from the lexicon (`（笑话比赛）` contains 「笑」, "laugh") is not in it, and is also not read, so check every place yourself.
   - Write ellipses and repeated words deliberately, by the meaning of the acting: hesitation, trailing off, written as `models/scene3.md`「Punctuation」 says (a stutter does not rely on `——`: repeat the character with `，` or `……` between); do not use `……` alone as a pause, do not write `。……`, `。[pause]`, or `[long pause]`, and do not write an ellipsis inside a word (with these the reading loses the sentence after them; an ellipsis inside a word, in Chinese, the model judged that 2 times in 9 it broke the word apart, nobody has checked; `models/scene3.md`「Pause between lines」「Punctuation」). Being interrupted: the sentence-final `——` and `……` that were tested did not show it (the measured durations and sentence endings were about the same; whether it was judged to stop abruptly is only the model's judgment, a lead; nobody has listened; `models/scene3.md`「Punctuation」). For the effect of being interrupted, write no pause before the next turn: when dubbed separately, `mix` already trims the gap at a speaker change to about 100 milliseconds (`references/dub.md`「Changing speakers within a scene」); in a merged scene the gap is decided by the model. Whether a close follow-up can be heard as an interruption has not been tested.
   - Reading: write proper names, numbers, and polyphonic characters as the words to be read, the same way throughout; for words the pack's pronunciation lexicon covers follow the lexicon (`references/dub-details.md`「Pronunciation lexicon」), and for words it does not cover and where you must fix the pronunciation, use a phoneme tag (`models/scene3.md`「Phoneme tags」).
   - Language: write the line in whatever language it is; do not translate it into the pack's language yourself and do not switch packs. In a merged scene a language change is not cut: each speaker has one reference segment for the whole scene, and if a turn of his is in a language that does not match that segment, it is cross-language cloning and often carries an accent (some of the voices listened to had an audible accent, the others are inference), and `dub` stops by default (step 6). When dubbed separately, or in several lines a person continues with, if the language changes between lines and the pack has a default segment of that language, it is cut there (in the report the `cutBefore` of that block is `language` and `notes` has a `language_cut` entry). A short passage of mixed-language speech must stay in one request: write it in the same line (a line picks only one reference segment, the words in the other language are wrapped in a language tag, `models/scene3.md`「Language tags」; the other language inside the line follows this line and does not stop); or pass `--language` (the whole script picks references by this one language), or pass a `--reference-tag` that exists in only one language: with these two, the whole line in the other language uses this reference segment, which is cross-language cloning and often carries an accent, and you must add `--allow-cross-language`, otherwise `dub` stops.
   - Pauses: in a merged scene the gap at a speaker change is decided by the model and generally is not marked (if you write `[pause …]`, or a round-bracket stage direction that reads as a pause, one longer than the limit cuts there, and one not longer than the limit is written into the request, step 2). When dubbed separately, mark `[pause 0.5s]` (0.4 to 0.8 seconds, depending on the scene) before a turn that is a refusal, rebuttal, reluctance, or hesitation; for a clear silence also write `[pause …]`. A pause written as a square-bracket cue (`[沉默片刻]`, `[停了一下]`; Chinese cues meaning "a moment of silence" and "paused for a moment") is not treated by `dub` as a pause: it does not cut there, and hands it to the model as it is; whether it pauses and for how long is up to the model; written like this at a speaker change in a merged scene, it is inference that the pause is unstable: nobody has listened, only the model judged that it mostly does not pause enough, a lead (`models/scene3.md`「Pause between lines」). For an exact pause, write `[pause …]` (a round-bracket stage direction that reads as a pause, for example `（沉默）`, works the same): when dubbed separately, and in a merged scene when longer than the limit, `mix` inserts it, and it is as long as inserted; in a merged scene when not longer than the limit it is written into the request, and the silence takes the closest of the measured forms, and is not inserted.

   Done when: every line starts with `[voice:]`, and the words to be read contain no speaker name and no stage direction.
4. **Write the cues.** First follow `models/scene3.md`「Where a cue is written and how far it reaches」›「Set the state first, then write the cue.」, once for each turn. For the notation and the readings see `models/scene3.md`「Cues」「Speaker markers」; use every form the vendor documentation lists, in the right place; write as the "Good examples" there shows: write one when the delivery changes, each short and exact. At the very start of each turn write first the name of the character who says this turn (`[甘雨]`, written in the language of this turn's words), ahead of all cues (`models/scene3.md`「Put the character name first」).
   - A cue is written in each turn's own text, right after `[voice:]` and before the line: `[voice:林晚][hushed, apologetic]对不起，我来晚了。` Write one at the start of every turn. When this pack has selected a setup and this turn has the same base tone as the setup, follow `scenes/one-line.md` step 3 item 6: the start may be left without one, and `dub` adds the setup's cue for this turn.
   - For a few words that change delivery, wrap those words in paired tags, which can be used inside every turn: a word stressed hard `<emphasis>…</emphasis>`, a half-sentence said low `<whisper>…</whisper>`, a half-sentence of coaxing `<soft>…</soft>`, a shout to stop `<forceful>…</forceful>` (`models/scene3.md`「Paired tags」). A momentary sound (a sigh, a laugh, a breath in) is written at the place where it happens (`[sighs]`, `[small laugh]`, same section, "Sudden sounds and pauses"). For a few words of another language inside a turn, wrap them in a language tag (`<japanese>…</japanese>`, same section, "Language tags").
   - Each cue is two or three words that say clearly the emotion or the delivery at this place; always write them in English, whatever the language of the line; do not write them as sentences. What this turn is responding to and why it is said this way do not go into the square brackets: write how it lands on the voice. If he is stung by the other's words and answers coldly, write `[cold, clipped]`, and do not write `[被这句话刺到，冷冷地回]` ("stung by this sentence, answers coldly": a counter-example, in Chinese). Who it is said to, what you want the other to do, what the sentence is doing, body movement, eye contact, things in the hands, and the scene likewise do not go into the square brackets: write only what can be heard with the eyes closed (`models/scene3.md`「What to write」).
   - Do not write too few either: if a person's emotion continues into his next turn, write it again in the next turn. Set the strength by the content at this place: the stronger the cue, the more intense the acting (inference: one person listened blind on the first page, one group heard the difference in strength, and another group with a different seed heard the two versions as about the same, `models/scene3.md`「Readings from the first-page audition」). For a sentence that has been restrained throughout, where sadness rises and is then held down again, write it as the cue that was deleted in the second example of `models/scene3.md`「Good examples」 (inference, only for this one sentence).
   - Write each person's acting by the dubbing guidance of his own pack, and the two sections each go to their own place: `### 台词` (lines: self-reference, sentence endings, word choice, a habit of asking back, and the like) goes into the words of the line itself, not into the square brackets (step 3, colloquial): the habit itself (likes to complain) goes into the words, and if he is complaining at this place, write it as the state of this clause, as `models/scene3.md`「Where a cue is written and how far it reaches」›「Set the state first, then write the cue.」 says; the only exception is the items in the dialect entry that are given to be used as short cues, which are written as short cues (`models/scene3.md`「Cross-language and accent」 step 1); only what in `### 演法` (acting style) can land on the model is written as a cue (written as `scenes/one-line.md` step 3 item 5 says). For a pack with a selected setup, the emotion, style, and energy fixed in the setup are added by `dub` as a cue, and what the script writes goes as the script writes it (`--setup` in `references/dub.md`): if a turn starts with a cue written, the setup's cue is not added for this turn. The setup's notes (for example the features of an accent) are for you; `dub` does not send them to the model: write them concretely in this person's lines as they appear, at the place where they happen. Write accents as `models/scene3.md`「Cross-language and accent」 says: when crossing languages write the name pair at the start; write a dialect as its own words, and do not write the name of the dialect (things like `[带一点四川口音]`, "with a slight Sichuan accent": a Chinese cue that names the dialect, which you must not write).
   - The few extras added when dubbing (`models/scene3.md`「Add a few more things when dubbing.」: a short stop is written `，[pause 0.6s]`, a sigh is written `[sighs]`) were listened to only on lines spoken by one person, and not in a scene of several people. In a merged scene, pauses follow step 3: `，[pause 0.6s]` does not exceed the limit, stays in the request, is written as `，[pause]`, and does not cut; written like this nobody has listened to it in a scene of several people, so do not write it in a merged scene, and do not write pauses nobody has listened to for the sake of marking point by point; one longer than the limit would also cut there. When dubbed separately (step 2), each turn is one line of one person, and it can be added by the table.

   For example (an example of the notation, not tested):

   ```
   [voice:林晚][hushed, apologetic]对不起，我来晚了。
   [voice:周屿][cold]嗯。[cold, impatient]坐吧。
   [voice:林晚][stunned]你……[aggrieved, holding back]你就不问问我<emphasis>为什么</emphasis>？
   ```

   Done when: every clause of every turn has had its state set and every place where the state changes has a cue; every turn starts with a cue (written by you, or the same as the setup and added by `dub`), and a few words that change alone use paired tags; no cue is longer than 4 words (target two or three), and none is written as a sentence.
5. **Decide the reference.** Decide for each speaker separately, taking the first one below that exists:
   1. One the user specified: you were asked to change it, or the user changed it by hand;
   2. The selected setup names a default reference (`referenceTag`): follow the setup, nothing more to pass;
   3. Neither: look at the script and the situation (in this scene he is a teenager, is angry, has just cried), and pick the closest-fitting reference tag from this person's pack; if nothing fits, pass none, and `dub` uses the default segment of the language of the line.

   Pass what the user specified and what you picked to `dub` with `--reference-tag <pack>=<tag>`, where `<pack>` is the pack name or pack ID, written once per pack; when several packs want the same tag you may also pass a single `--reference-tag <tag>` without a pack name, and then every pack must have it; do not mix the two forms. In a merged scene each speaker uses only one reference segment for the whole scene: for each of his turns first take one segment in the order above, and use the segment used most often in the whole scene (on a tie, the one that appeared first). So a person's emotional ups and downs within a scene come from the cue of each turn; a square-bracket cue does not change the reference. Done when: for each speaker you can say which tag (or the default segment) is used and why.
6. **Look at the plan first.** `node cli.mjs dub --pack <pack dir> --pack <pack dir> <script file> --out <output dir> --dry-run`, with the `--reference-tag` from step 5, the `--setup <pack>=<name>` to use, `--no-scene` from step 2 when separate is wanted, and `--min-similarity <number>` when segments with a drifted timbre are to be flagged (step 8). Expressiveness: when the voice has a fixed value (from the setup, or the voice's global value, visible in the plan as `pack.expressiveness`, and for several packs as `packs[i].expressiveness`), by default do not pass `--expressiveness`; pass it only with a reason, and move about 10 from the fixed value. When it is not fixed (neither place has one), by default pass `--expressiveness`, choosing the value by `models/scene3.md`「Expressiveness」›「How to choose the value」. When several voices are such that some are fixed and some are not, do not use `--expressiveness` (it overrides the fixed ones) and write it, following `models/scene3.md`「Expressiveness」›「How to choose the value」, only on the items of the voices that are not fixed. When several voices have different fixed values, lines with different values are not merged into one request; to merge them, give one value explicitly and do not average. Within one scene the value does not change; for different scenes with different values use the per-item fields of a `.json` script (where the value changes, a scene is cut, `references/dub.md`「One request per scene」). Write the number in that one place only. This only plans; it does not synthesize and costs nothing. Look at three things: which lines were merged into a scene; which reference segment each speaker uses, and whether `by` is the kind you decided (for each separate sentence it is in `units[i].pick`, for a merged scene in `scene.speakers[i].pick`; `by` is one of `reference-tag`, `setup`, `default`; for cross-language cloning `crossLanguage` is `true`: for a whole line in another language it appears only when `--allow-cross-language` was added; a block where another language is inserted inside a line (`followsLine`, or the pack has no such language) is marked `true` even without it, and this does not stop); and whether the pauses and speaker changes are where you want them. If not, go back and change the script or the options.
   If the plan reports `dub_cross_language` (someone's reference segment is not in the language of his turn), nothing has been dubbed: do not ask the user and do not add a reference; write the lines in the target language, write the name pair `[name in the reference language|name in the line's language]` at the start of this turn, add `--allow-cross-language`, and dub again (`references/character-voice.md`「Language and accent」). If the report says his pack actually has this language (only that a merged scene uses one reference segment for the whole scene), then dubbing separately (`--no-scene`) makes each line use the reference of its own language: ask the user whether to separate, and state the trade-offs of separating (the "Merging and splitting" section below); if the report says this language has no such tag, or the language given is not the language of the lines, follow `scenes/one-line.md` step 6.

   Done when: the merged scene is not cut unexpectedly (count the `units` in the plan: one more than you wanted means it was cut at one place; check the cut points one by one, with the details in `references/dub.md`「One request per scene」›「Where to split」: a written pause longer than the limit (`[pause …]`, a round-bracket stage direction that reads as a pause such as `（沉默）`), a chapter change (`# title`; the items of a `.json` script are cut between items anyway, count by the number of items), a change of speed or expressiveness, speakers exceeding the limit the environment declares, a `dub` script in the pack; the first three kinds are not a real wish to separate, so change the script or the options; for the last two, and for several voices whose settings or global values each fix a different expressiveness value (a fixed value is by default not passed again, and this scene is cut by value), these are set by the environment and the pack and cannot be changed by the script; a scene that does not fit and that `dub` itself cuts between lines is another matter, step 2); a voice with a fixed expressiveness has none passed, unless there is a reason and it moved about 10 from the fixed value.
7. **Dub the scene.** Remove `--dry-run` and run the same command.
8. **Read the report, then hand it back.** Do not check separately after dubbing: do not transcribe the audio and compare with the script, do not check the words after an ellipsis, do not switch tags and redo by similarity, and do not make "a sentence was skipped, it got stuck, or repeated, so redo the whole scene" a step that is done by default. The failure and bad-output signals that `dub` reports itself (`failed`, `speech_maybe_unfinished`, `target_duration_missed`) are not covered by this: handle them by `references/dub.md`「Failure and redo」「Whether it was read in full」, because those are things that cannot be handed over; `speech_maybe_unfinished` is the exception: it only reports which segment may have been cut, does not redo automatically, and you tell the user as it is and the user decides. In the note handed back, write which places this run are worth the user's listening:
   - Dubbed separately: when the runtime environment has the speaker similarity capability (`speaker-verification`), `dub` measured it, and `units[i].speakerSimilarity` of each sentence records the similarity to the reference `similarity` and which segment it was compared with `segmentId`; the top-level `speakerSimilarity` records whether it was measured this run. If `--min-similarity <number>` was given when dubbing, a sentence below it has `drifted` set to `true`; without it there is only the number. The numbers and `drifted` stay in `dub.json` as they are, and are not a reason to redo it yourself. When the user asks whether the timbre is stable, say the numbers as they are; when he hears that someone drifted, switch that person's pack to another reference tag (`--reference-tag <pack>=<tag>`), add `--only` to redo only those sentences, and keep the output directory as before. When the setup names a default reference it can be changed too, the default reference is not tied down; the reason in the report is then specified by the caller (`reference-tag`). For the details see `references/dub.md`「Comparing timbre」.
   - A merged scene: in `speakerSimilarity.speakers` of that scene every speaker is written as "unmeasurable" (cannot be measured: a request has only one audio and the boundary of each person cannot be told apart); it can only be heard, so whether to separate is the user's decision. After dubbing, say one sentence: "These were dubbed together; if a timbre does not sound like the character, the lines can be redone one by one separately." Then tell the user which scenes were merged and what to listen to: whether each voice is always himself, whether voices crossed or were swapped (the more people, the more it needs special listening), and whether the loudness of each person is even. If the user says who is wrong, or wants it separated, add `--no-scene` and redo that scene, and state the trade-offs: each person goes back to his own voice, and the acting may be a bit worse (inference, see "Merging and splitting" below). In a merged request every person may sound less like himself (`models/scene3.md`「Speaker markers」, the 2026-11-06 readings), so say this sentence every time and do not wait for the user to ask. `--no-scene` applies to the whole `dub` run: to keep the other merged scenes in the script, split this scene into a separate script and dub it. When no one can be asked at the end of a round, hand over the merged version, and write in the note handed back which scenes were merged, what to listen to, and that if someone is wrong they can be dubbed separately.
   - Sentences that use an ellipsis: say so when handing back, that the words after an ellipsis are occasionally lost (model-judged, nobody has checked, `models/scene3.md`「Punctuation」), and ask the user to listen to these sentences.
   - The user hears a skipped sentence, a stuck place, or a repeat: a merged scene is one take, so redo the whole scene: `--only <index of this scene>`, with the output directory as before (if you run the same command without `--only`, the unchanged scenes are reused as they are and not synthesized again). When the runtime environment accepts a seed, the scene that `--only` points to gets a different seed, and the same script may come out as a different take (the platform declares the same result for the same seed as far as possible, the program compared only one pair, and a different seed was also compared on this one pair only; `references/dub.md`「Failure and redo」).

   Done when: the note handed back says where to listen: for every merged scene, the user was told (or it is written into the note handed back) that several people were dubbed together, what to listen to, and that if a timbre does not sound like the character the lines can be redone one by one separately; for sentences that use an ellipsis it says the words after may occasionally be lost (model-judged, nobody has checked); when `dub` reported a failure or bad-output signal, it was handled as `references/dub.md` says; you did not transcribe, check ellipses, or redo by similarity yourself.
9. **Stitch the pieces together.** To get one finished file: `node cli.mjs mix <dub output directory> --out <file.wav>`; for the silence at speaker changes, the pauses, and the speed see `references/dub.md`「Stitching」. When it was split into several `dub` runs, give `mix` all the output directories in the order of the script: `node cli.mjs mix <dir 1> <dir 2> … --out <file.wav>`, which joins them into one file in the order given, and the joins between directories are made the same way as between two adjacent sentences inside one directory.

## Merging and splitting

| | Merged: one request per scene | Separate: one request per line, then stitch |
|---|---|---|
| Gain | Better acting and more natural replies (inference: one person listened blind on the first page, a merged scene is smoother for a steady scene, and for a scene with emotional ups and downs the separate version was the best): the gap at a speaker change is decided by the model | Each person is his own voice; there is a file for every line and only one line can be redone; the pauses are exact |
| Cost | May swap someone's timbre; each person has only one reference segment for the whole scene; the pauses inside a request are short (`models/scene3.md`「Pause between lines」); there is no file for each line, and redoing one line cannot be done (`--only` goes by unit number and a scene is one number); one take for the whole scene, so an error drags down the whole scene | The acting may be a bit worse (inference: one person listened blind on the first page, a merged scene is smoother for a steady scene, while for a scene with emotional ups and downs the separate one was the best instead): the model cannot hear the previous and next sentences, and the following of replies and the continuity of emotion rely only on the cue of each line and on stitching |
| Timbre similarity | Written per speaker as "unmeasurable" (cannot be measured) | When the runtime environment can, every segment is measured |

How to read the first-page audition (one person listened blind to two scenes of two people, see the readings in `models/scene3.md`「Speaker markers」): in a steady scene, the whole merged piece is smoother, but in the merged version one person's timbre changed; in a scene with emotional ups and downs, the separate version was the best. The comparison of the two-person scene of 2026-11-06 (the same readings, only one scene, four sentences): in the merged request both people's similarity to their own references was clearly lower than with one request per sentence. So the default is to merge, and after dubbing the user is told it can be redone separately (step 8); if the user hears that someone's timbre is wrong, or the merged version of a scene with large emotional swings does not act well enough, dub separately.

## One person playing several roles

In this version a pack has only one speaker in one `dub` run; `dub` does not accept the same pack twice (passing `--pack` twice for the same pack reports `dub_input_invalid`).

1. **One `dub` per pack; several characters are told apart by cues.** Give each role a role cue: what this role's voice is like in concrete terms (pitch, throat, speed), two or three words, for example `[low, gravelly]` for an old person and `[clear, bright]` for a teenager (an example of the notation, not tested); do not write names of identity like "old person" or "teenager", because the model does not know how to say that concretely (`models/scene3.md`「What to write」 first item). Write it at the start of every line of this role, and put each role on a new line. Writing it only the first time is not enough: a sentence with no new cue continues the earlier delivery, and if the next line does not change the cue it still sounds like the previous role. When the delivery changes inside a line, write another one at the place of the change, as step 4 says, with this role's role cue in it (the role cue is included in every new cue; why, and how it differs from a pack that plays only one role, is in the item about fine acting in `models/scene3.md`「What to write」; how to include it is in the same document's 「Where a cue is written and how far it reaches」). A momentary sound such as a sigh or a laugh gets its own square bracket (`[sighs]`), and is not piled together with the role cue and the emotion. For example (an example of the notation, not tested):

   ```
   [low, gravelly, unhurried]孩子，天黑了，别往林子里去。
   [clear, bright, urgent]我就看一眼，[clear, bright, guilty]马上回来！
   [low, gravelly][sighs]……去吧。[low, gravelly, softer]记得带灯。
   ```

   When this pack is in the same scene as other packs, all the roles it plays write the same `[voice:<this pack>]` and are told apart by cues. The roles share one reference segment of this pack, and the timbre base is the same person: it may sound like one actor playing several roles (inference, not tested).
2. **Several characters need different reference tags** (for example the old person uses the "aged" segment and the teenager the "teenager" segment): at the place where the role changes, split the script into several files; for each file run `dub` once, with its own `--reference-tag <tag>` and `--out <dir>`; then use `mix` to join the directories in the order of the script into one file (step 9). Before and after the split there are two requests, and they are no longer acted together, and `mix` adds no pause either (for a breath, write `[pause 0.5s]` at the start of the second script); if the roles switch back and forth often, it has to be split into many pieces, and then use the previous item first.

## Common pitfalls

- **Merging swapped a voice.** In a first-page audition of a scene of two people, in the merged version one person's timbre was not the same person at all as in the separate version; in a scene of three people, with the voiceprint measured on a sliding window of 1.5 seconds, each person's own share in his own time span was 0.60 to 1.00, and some windows were measured as another person (readings, not counted sentence by sentence into a conclusion); the model judge also once reported a male voice swapped with another male voice, not verified (`models/scene3.md`「Speaker markers」). The more people, and the more alike the voices, the more it needs listening.
- **One take per scene.** A stuck place, a skipped sentence, or a repeat drags down the whole scene (inference: the whole scene is one request); if the user hears it, the only way is to redo the whole scene.
- **A scene does not fit in one request.** When it is longer than the default of about 1000 characters, `dub` has already cut it between lines into several scenes (step 2). If the platform still says it does not fit after cutting, that scene is recorded as a failure (`scene_too_long`) and the other scenes are dubbed as usual: add a chapter marker (`# title`) in the middle of that scene to cut it into two scenes (for what to watch when adding a title, see `references/dub.md`「How long text is split」›「A piece cannot hear the previous one.」), or use `--no-scene`. Whether it fits depends on how long the reference and the text are (`models/scene3.md`「Limits of one request」).
- **Separate dubbing makes speaker changes too even.** The gap at a speaker change is given by stitching, and the model judged it sounds mechanical and even (a lead, nobody has listened): mark a pause before a turn that is reluctant, a rebuttal, or hesitant (step 3).
- **The name is read aloud and the words in brackets are lost.** Replace a "name: line" prefix with `[voice:<pack name or pack ID>]` (step 3). Write stage directions as square-bracket cues: words in round brackets that are handed directly to the model are still read aloud (`models/scene3.md`「Text in round brackets is read aloud」); through `dub`, every bracket of 30 characters or fewer is treated as a stage direction, so the words in brackets that were to be read are lost; write them without brackets (commas, dashes). An onomatopoeia inside a cue (the 「嘿嘿」 of `[嘿嘿地笑]`, "chuckles heh-heh") may also be read aloud (transcription, model-judged, nobody has checked): for a laugh, write it at the place of the laugh (`[small laugh]`) or write the delivery (`[smiling voice]`) (`models/scene3.md`「What to write」「Sudden sounds and pauses」).
- **The cue was written as a sentence.** What this turn is responding to and why it is said this way written as one sentence and put into the square brackets (`[被这句话刺到，冷冷地回]`, "stung by this sentence, answers coldly"): write the two or three words that land on the voice (`[cold, clipped]`); who it is said to and what you want the other to do are also not written into the square brackets, see step 4.
- **One person has only one reference segment in a scene.** If his emotion changes in this scene, write it into the cue of every turn; a square-bracket cue does not change the reference.
- **One person must change reference tag midway** (for example the "ordinary" segment for the first half of the scene and the "angry" segment for the second half): in this version the script has no marker to change the tag, `--reference-tag` is given to one pack in one `dub` run, and `dub` does not accept the same pack twice. Split the script into two files at the place of the change, run `dub` twice with its own `--reference-tag` each, then join them with `node cli.mjs mix <previous run's directory> <next run's directory> --out <file.wav>`. `mix` adds no pause at the split; for a breath, write `[pause 0.5s]` at the start of the second script.

## Model notes used

All in `models/scene3.md`:

- "Cues": where each of the several control forms is used; where a cue is written and how far it reaches; what to write (first item: write concrete words, not summary labels such as accent or identity, step 4 and "One person playing several roles"; one per place, or two short ones side by side, two or three words; an onomatopoeia may be read aloud (transcription, model-judged, nobody has checked)); sudden sounds; paired tags; language tags; phoneme tags; words in round brackets are read aloud (a platform declaration); good examples; cue strength (on the first page one person listened blind, one group heard the strength, one group sounded about the same);
- "Cues", under it "Add a few more things when dubbing.": how to write a short stop or a sigh inside one person's lines, and the readings; listened to only on one person's lines, not in a scene of several people (step 4);
- "Cross-language and accent": a character's accent or dialect, with the lines written as the words of this dialect, and the name of the dialect not written (step 4);
- "Reference segments": the acting style follows the reference (one person listened blind on the first page, the reference the character himself had acted was clearly better, with the timbre slightly off; the other voices are inference);
- "Speaker markers": the speaker marker, one reference segment per person (matched in order), the cue of each turn and the paired tags written after the marker, and each turn on a new line being more stable (a measurement noted in a comment in the inference code, not verified), and the merged readings;
- "Pause between lines": the longest a pause inside one request can be kept, why a longer one must be cut and inserted by stitching, and how a pause written as an acting note at a speaker change in a merged scene turns out;
- "Punctuation": how to write ellipses and repeated words, and the tested punctuation for being interrupted all showed nothing (step 3), and the words after an ellipsis are occasionally lost (model-judged, nobody has checked; write it in the note handed back in step 8);
- "Limits of one request": how the default of about 1000 characters per request was set, and whether one scene fits.
- "Expressiveness": a control parameter, the higher the value the more drama; the order of the three layers (global, setup, at `dub` time); a voice with a fixed value gets none passed by default, one that is not fixed can get a value, and the starting point and how to adjust up and down are there (step 6).
