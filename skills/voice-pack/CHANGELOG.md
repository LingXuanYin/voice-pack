# Changelog / 更新记录

Each version of the base part, newest first. The top entry is the version in `manifest-fields.json`; the release notes on GitHub are the entry of that version.
基础部分每个版本改了什么，新的在前。最上面一条就是 `manifest-fields.json` 里的版本；GitHub 上的发布说明取该版本这一条。

Versions 1.0.0 to 1.0.9 were released under the product's earlier names (the skill was `cohub-voice-studio`, the release files `cohub-voice-studio-<version>.voicepack.zip`), except 1.0.3, which was never published: what it changed first shipped in 1.0.4. 1.0.0 到 1.0.9 是用产品原来的名字发的（skill 叫 `cohub-voice-studio`，发布文件叫 `cohub-voice-studio-<版本>.voicepack.zip`），只有 1.0.3 没有发布过：它改的东西第一次发出去是在 1.0.4。发布过的文件名不变，仍然列在版本索引里。

## 2.0.12 — 2026-10

A designed voice has no real recordings, so its fidelity report now says what its numbers mean. The baseline is how alike the voice is to itself across several syntheses, not how alike it is to a real person; the three readings of "judged the same speaker" do not apply to it, so the report gives the count and the number of valid listenings and draws no conclusion; and when there are fewer than five valid held-out recordings, the hint says how many more to synthesize (the count the pack needs, from the same rule the pack uses to choose its holdouts). A pack counts as designed when its manifest has a design source; a pack without one is read as before, with real recordings. The design vocabulary also gets three timbre tags for voices that do not sound human (robotic, metallic and growling); they say how a voice sounds, and a design written with one is not guaranteed to come out that way.
设计出来的声音没有真人录音，它的还原度报告现在写明这些数是什么意思。基线是这个声音自己几次合成之间的一致程度，不是它和某个真人有多像；「判成同一人」的三档读法对它不适用，报告只列次数和有效的条数，不下结论；有效的留出录音不到 5 条时，提示写明再合成几句（按做包选留出录音的同一条规则算出要几段）。清单里有设计来源的，才算设计出来的声音；没有的，照旧按真人录音读。设计词表还加了三个说非人类声音的音色标签（机械感 robotic、金属感 metallic、低吼 growling）；它们说的是声音听起来怎样，写进设计描述不保证合成得出来。

- **A designed voice's fidelity is read as its own consistency.** The report says the material is a design source, and gives the baseline and the ratio as the pack's consistency with the design, not a likeness to a real person. The tiers are not applied. / **设计出来的声音，还原度照它自己的一致程度读。** 报告写明素材是设计来源，基线和比值都是包和这个设计声音的一致程度，不是和真人像不像；三档不读。
- **The hint says how many more to synthesize.** When a design-sourced pack has fewer than five valid held-out recordings, the missing-material hint gives the number of clips to add, computed from the same holdout rule the pack uses. The default settings are unchanged. / **提示写明再合成几句。** 设计来源的包留出不够 5 条时，缺素材的提示给出要再合成几句，按做包用的同一条留出规则算。默认设置不变。
- **Nothing changes for a pack with real recordings.** Without a design source, the report and the hint read as before. / **真人录音做的包不变。** 没有设计来源的，报告和提示照旧。

## 2.0.11 — 2026-10

The description and the sample text of the default voice, and the design step of section 2, now follow the voice-design and reference guides of the model. The default voice is described as a neutral young adult talking slightly slowly and calmly in everyday conversation, and its sample is several connected lines of about 75 characters. Section 2 gives the seven-dimension table of the design guide once, and step 3 asks for several connected lines of plain talk, read aloud in 10 to 20 seconds, not one sentence. Every clone made from the default voice still takes the same sample. No program logic changed.
默认声音的描述和样本，以及第 2 节的设计步骤，现在照模型的设计和参考的官方要求写。默认声音的描述是一个中性的青年平常跟身边的人说话的声音，语速稍慢，情绪平静，用在日常对话里；样本是几句连贯的平常话，约 75 个字。第 2 节只在一处写设计描述的七个维度表；第 3 步的试听文本改成几句连贯的平常话，读出来 10 到 20 秒，不再是一句。从它做的每一段克隆，仍然都以同一个样本为参考。程序的逻辑没有改动。

- **The default voice's words follow the guide.** Its description names the speed as slightly slow and says what the voice is for, and its sample is long enough to read well above the shortest reference the clone model takes. / **默认声音的用词照官方的写法。** 描述里语速写稍慢，用途写日常对话；样本够长，读出来远超克隆模型的参考下限。
- **The design table is written once.** The seven dimensions (gender, age, pitch, speed, mood, trait, use) and their values are in section 2, step 2, and nowhere else. Values outside the table, such as "natural" or "pleasant", are not used. / **维度表只写一处。** 七个维度（性别、年龄、音高、语速、情绪、特点、用途）和取值只在第 2 节第 2 步；表外的评价词（「自然」「好听」）不用。
- **The audition is several connected lines.** Plain talk, said face to face in the register of speech, with one meaning across the lines, the same speed from start to end, and no long pause. / **试听文本是几句连贯的话。** 仍是当面对人说的平常话，用说话的口气；几句意思连贯，语速前后一致，中间没有长停顿。

## 2.0.10 — 2026-10

The Cohub adapter puts `[shouting]` in front of a line whose style is `shout` again. It is the one emotion or style tag that stays: laughing and sighing are unchanged, and sad, excited, sarcastic, surprised, angry and whispering still come out without a tag. This time the sound was measured, not a listening model's answer: for each tag, eight pairs of a tagged clip and a plain clip of the same sentence and voice, judged by a rule written before the run. Shouting moved the expected way in all eight pairs: loudness rose 1.30 dB (two plain generations of the same settings differ by 0.08 dB) and the median pitch rose 3.31 semitones (they differ by 0.29). Each line in `cue-tags.mjs` has its tag's numbers.
Cohub 适配器：`[shouting]`（大喊）重新出标签，是情绪、风格里唯一留下的。笑、叹气不变；悲伤、兴奋、讽刺、惊讶、生气、耳语仍然不出标签。这次量的是声音本身，不问听音模型：每个标签的八对（同一句、同一个声音的标签段和普通段）按开跑前定好的规则判。大喊八对全部朝预期方向变：响度上升 1.30 dB，同样设置生成两遍之间的差是 0.08 dB；音高中位数上升 3.31 个半音，两遍之间的差是 0.29 个。每行注释里有各个标签的数。

The integrated loudness that the loudness check and the loudness normalizer both measure with no longer slows down on a clip that ends in digital silence. The K-weighting filter now sets its state to zero once that state has decayed to almost nothing, instead of running on through the very small numbers a processor handles slowly. The loudness of every clip tested is the same as before, to the last digit, with or without digital silence at the end.
响度检查和响度统一量的整体响度，碰到末尾是数字静音的段不再变慢。K 计权滤波器的状态衰减到几乎为零以后直接置零，不再在处理器算得很慢的极小数里继续算。测过的每一段，响度都和以前逐位一样，末尾有没有数字静音都一样。

- **A clip that ends in silence is measured as fast as any other.** A long digital silence after the words made the loudness measurement many times slower, and the synthesis check, which measures every clip, waited on it. / **末尾是数字静音的段，和别的段量得一样快。** 字后面接着很长的数字静音，以前让响度测量慢很多倍；合成时每段都要量，检查就等着它。
- **The values do not change.** The loudness of each clip tested is the same as before, to the last digit, and so is the normalized output on the clips checked. / **值不变。** 测过的每一段，响度逐位一样；统一响度后的输出，检查过的几段也一样。
- **Callers see no difference.** Callers of the measuring and normalizing functions get the same results; only the filter's internal state is handled differently. / **调用的一方看不出区别。** 量和统一响度的函数，拿到的结果都一样；只是滤波器内部的状态处理不同了。

## 2.0.9 — 2026-10

A designed voice's first pack can now have its sample lines cloned from its locked audition, once the user has agreed to how many clones it takes: one voice-cloning call per line of the set in `vocab/design-sample-lines.json` (Chinese and English, seven lines each), with the audition as the reference and its words as `ref_text`. The clones go into the pack as material beside the audition, so it has several references and a held-out recording to measure the fidelity on. Section 7 says how an agent does the same. The sample lines are a vocabulary file, read by the app and by the agent alike. No program logic in the library changed.
设计出来的声音第一次做成音色包时，可以用锁定的试听克隆示例台词：先说清要调几次，使用者确认后，每句调一次 voice-cloning，参考是试听，`ref_text` 是试听的原文。句子在 `vocab/design-sample-lines.json`，中文、英文各 7 句。克隆出来的几段和试听一起当素材，包里就有几段参考和留出录音，留出录音用来量还原度。第 7 节也写了 agent 怎么做。这份句子是词表，app 和 agent 读的是同一份。程序的逻辑没有改动。

- **Asked before anything is spent.** The app says how many clones it takes and asks first. A no makes the pack from the audition alone, as before. / **先问再花。** app 先说要克隆几句、花几次；使用者不要，就只用试听做音色包，和以前一样。
- **The sample lines are written for holding out.** Seven a language, each with a feeling of its own, two or more of them a question, a reply or an aside, and each long enough to be a held-out recording. / **句子是按留出录音的要求写的。** 每种语言 7 句，每句一种情绪，至少两句是问句、回答或插话，每句够作留出录音的字数。
- **A refused line is left out.** A line the service refuses for its own text is not in the pack and the others go on. Three refusals with none made stop the make, because the reference itself may be what is refused. / **被拒的一句不进包。** 服务商因为这一句的文字拒了，它不进包，别的照常。拒了三句、还没有一句成功，就停下，因为可能是参考本身被拦了。

## 2.0.8 — 2026-10

The default voice, which is used when no voice is chosen, is now described as a neutral adult talking to the people around them, not as someone reading aloud, and its sample text is several plain lines said face to face, not a welcome or the opening of a story. Every clone made from the default voice still takes the same sample. Step 4 of section 2 no longer asks the listening model whether a candidate sounds like a real person, because its answers do not tell real recordings from synthesized ones. The user or the agent chooses the candidate, and at most one more batch is designed. No program logic changed.
没有选声音时用的默认声音，描述现在写的是一个中性的成年人平常跟身边的人说话的声音，不是朗读；它的样本文字是几句当面说的平常话，不是欢迎词，也不是故事的开头。从它做的每一段克隆，仍然都以同一个样本为参考。第 2 节第 4 步不再让听的模型判候选像不像真人，因为它的回答分不开真人录音和合成的声音。候选由使用者或 agent 挑，挑不出满意的，再设计最多一批。程序的逻辑没有改动。

- **The default voice talks, it does not read.** Its description is a neutral adult's voice in ordinary talk with the people around them: pitch, timbre, pace and manner. Words for reading and performing are left out, negated phrases included. Its sample text is several plain lines (a greeting, an answer, a small request), long enough to be read well above the shortest reference the clone model takes. / **默认声音说的是平常话，不是朗读。** 描述写的是一个中性的成年人跟身边的人说话的声音（音高、音色、语速、说话的样子）；朗读、表演这类词不用，否定的说法也不用。样本文字是几句平常话（打招呼、回答、小请求），读出来远超模型的参考下限。
- **The listening model does not judge candidates.** Step 4 of section 2 no longer asks `audio-text-to-text` whether a candidate sounds like a real person, and its answers are no longer shown to the user. Three ways of asking were tried with the listening model the Cohub adapter uses, on real human recordings (Mandarin read speech from FLEURS, CC BY 4.0) and on clips of two earlier synthesized voice packs that people had found not lifelike enough. None of them tells the two apart the right way round: on the first and the third, the earlier packs were more often judged to sound like a person; on the second, both groups were mostly judged not to. The answers say nothing about whether a voice sounds like a person, so the 2.0.7 rule that two "not a real person" answers keep a candidate from being locked is gone too. / **听的模型不替候选判真人。** 第 2 节第 4 步不再让 `audio-text-to-text` 判候选像不像真人，它的回答也不再写给使用者。用 Cohub 适配器接的听音模型，在真人录音（FLEURS 的普通话朗读，CC BY 4.0）和两个早先合成、听的人觉得不够像真人的音色包（下面叫旧包）上试过三种问法，都没有分对方向：第一种和第三种里，旧包反而更多被判成像真人；第二种里两组几乎都被判成不像。这些回答说明不了一个声音像不像真人，2.0.7 里「两次都说不像真人的候选不锁定」也去掉了。
  - Question 1, 「这像个真人吗？哪里像，哪里不像？」, each clip asked twice. Real recordings, 20 answers (10 clips): 2 say it sounds like a person, 16 say it does not, 2 cannot tell. Earlier packs, 16 answers (8 clips): 9, 5 and 2. / 第一问，「这像个真人吗？哪里像，哪里不像？」，每段问两次。真人录音 20 次回答（10 段）：2 次说像，16 次说不像，2 次说不准。旧包 16 次回答（8 段）：9 次说像，5 次说不像，2 次说不准。
  - Question 2, 「这段声音是真人说的吗？哪里像真人，哪里不像？」, each clip asked twice. Real recordings, 20 answers: 1 says it sounds like a person, 19 say it does not. Earlier packs, 16 answers: none says it sounds like a person. / 第二问，「这段声音是真人说的吗？哪里像真人，哪里不像？」，每段问两次。真人录音 20 次回答：1 次说像，19 次说不像。旧包 16 次回答：没有一次说像。
  - Question 3, two clips side by side, one real and one earlier pack, each pair asked in both orders: 「这两段录音，哪一段更像真人说话？」 16 answers, 13 pick the earlier pack. / 第三问，两段一起听，一段真人、一段旧包，每对两个顺序各问一次：「这两段录音，哪一段更像真人说话？」16 次回答，13 次选了旧包。

  Candidates are chosen by the user or the agent, not by these answers. / 候选由使用者或 agent 挑，不由这些回答决定。
- **One more batch at most.** If none of the candidates is satisfying, the description or the sample text is changed and one more batch is designed. If that batch is not satisfying either, the user is told so. / **再设计最多一批。** 挑不出满意的候选，改描述或试听文本，最多再设计一批；这一批还挑不出，照实告诉使用者。

## 2.0.7 — 2026-10

The design steps in section 2 now say how a designed voice should sound. The description is how the person talks to the people around them on an ordinary day, not how they read. The preview text is one ordinary sentence said face to face, and every clone made from the designed voice takes it as its reference. Where the environment can listen to audio, each candidate is heard twice with the audio only and asked plainly whether it sounds like a real person, and where it does and does not; a candidate both answers say does not is not locked. The question is written once, in step 4. Section 7 points back to section 2 for the sample lines of a designed voice. Only the documents changed; no program did.
基础部分第 2 节「设计」现在说清了设计出来的声音该是什么样子：描述写这个人平常跟身边的人说话的声音，不写朗读；试听文本是一句当面对人说的平常话，之后所有克隆都以它为参考。环境能听音频时，每个候选只给音频，直接问两次像不像真人、哪里像哪里不像，两次都说不像的不锁定；问法写在第 4 步，只写一处。第 7 节指回第 2 节，设计出来的声音的示例台词照它写。只改了文档，程序没动。

- **The description is how the person talks.** It gives the age, gender, job, pitch, timbre, pace and manner of someone talking to the people around them. Words for reading and performing (read aloud, narrator, announcer, performing, dramatic) are left out, even in a negated phrase such as "not a broadcast voice", unless the person's job is one of those. / **描述写人平常说话的样子。** 写年龄、性别、做什么的、音高、音色、语速和说话的样子，写的是他跟身边的人说话时的声音。朗读、旁白、播音、表演、戏剧性这类词不用，连「不是播音腔」这样的否定说法也不用，除非这本来就是他的工作。
- **The preview text is one ordinary sentence.** A sentence said face to face to someone (a greeting, an answer, a small request), in the register of speech: no semicolons, sayings, parallel structure, scenery, or a narrated past. Every clone copies it, so it stays calm and plain. / **试听文本是一句平常话。** 当面对人说的一句（打招呼、回答、一个小请求），用说话的口气，不用分号、格言、对仗、景物描写，也不用旁白式地讲过去的事。之后的克隆都以它为参考，所以要平静、普通。
- **Several candidates, heard blind.** Design three candidates and lock one. Where `audio-text-to-text` is available, each candidate is heard twice with the audio alone, and the question is in step 4 of section 2. The question gives the listener no options and no hints. A candidate both answers say does not sound like a real person is not locked, and if none is locked, a new batch is designed. / **设计几个候选，盲听后再锁定。** 设计三个候选，挑一个锁定。环境有 `audio-text-to-text` 时，每个候选只给音频，问两次，问法在第 2 节第 4 步，不给听的一方选项和提示。两次都说不像真人的不锁定；都不锁定，就再设计一批。
- **Sample lines of a designed voice.** Section 7 points back to section 2: the sample lines of a designed voice follow the preview text, each line a different feeling, and at least two of them are a question, a reply or an aside. / **设计出来的声音的示例台词。** 第 7 节指回第 2 节：示例台词照试听文本的写法，每句一种情绪，至少两句是问句、回答或插话。

A line's own stage directions can reach the voice model as names, not only as the pack guidance. `voice-cloning` and `text-to-speech` take an optional parameter `cues`: the canonical names for this line's emotion and style: the emotion and style the caller gives the item in its labels when it gives them, otherwise those its stage directions set. Speed and pauses are not in `cues`: they stay on the unit (`unit.speed`, `unit.pauseBeforeMs`, `unit.pauseAfterMs`). It is sent only to an environment that declares `style-cues`. The pack guidance never goes into `cues`: it says how the voice usually talks, not what one line asks for.
一句自己的舞台提示，现在可以以名字的形式交给语音模型，不只是配音指引。`voice-cloning`、`text-to-speech` 加一个可选参数 `cues`：这一句的规范名字（情绪、风格）：情绪和风格调用方在 labels 里给了就用给的，没给才用舞台提示定的。语速和停顿不在 `cues` 里，它们留在 unit 的字段上（`unit.speed`、`unit.pauseBeforeMs`、`unit.pauseAfterMs`）。只传给声明了 `style-cues` 的环境。配音指引永远不进 `cues`：它写的是这个声音平时怎么说，不是这一句要什么。

- **Each line's own names go to the environment as `cues`.** `unit.cues` says what was sent, or why nothing was (`style_cues_missing`, `nothing_to_send`). A line split into parts sends its emotion and style with every part; a one-shot sound (laughing, sighing, marked `oneShot` in `vocab/cues.json`) goes only with the first part. An environment ignores any other key in `cues`: it adds no tag for it and raises no error, so a key added later does not make an older adapter's synthesis fail. / **每一句自己的名字随段以 `cues` 传给环境。** `unit.cues` 写明传了什么，或者为什么没传（`style_cues_missing`、`nothing_to_send`）。一句分了段，情绪、风格每段都带；一下子的声音（笑、叹气，在 `vocab/cues.json` 的 `oneShot` 里标着）只跟第一段。环境忽略 `cues` 里别的键：不出标签，也不报错，所以以后加的键不会让旧适配器的合成整次被拒。
- **The protocol core is 2.1.0.** It declares one more name, `style-cues`, next to `style-instruction` (`protocol/lib/env.mjs`). An environment that does not declare it is unaffected. An adapter that declares it does not pass `adapter check` with the 2.0.0 core on the 2.0.6 vocabulary (`capability_unknown`, the name is not in that vocabulary); it needs this core and this vocabulary. / **协议核心是 2.1.0。** 多认一个声明 `style-cues`，和 `style-instruction` 并列（`protocol/lib/env.mjs`）。不声明它的环境不受影响。声明了它的适配器，用 2.0.0 核心配 2.0.6 词表过不了 `adapter check`（`capability_unknown`，那份词表里没有这个名字）；要用这份核心和这份词表。
- **The guidance is never in `cues`, and `style-cues` is its own declaration.** It is separate from `style-instruction`: the free text the environment reads itself, against the few names the library has already recognised. Declared in `vocab/capabilities.json`, described in `vocab/capability-signatures.md`「怎么念」. / **配音指引永远不进 `cues`，`style-cues` 是自己的声明。** 它和 `style-instruction` 分开：后者是环境自己读的自由文字，前者是库已经认出来、规范化过的几个名字。声明在 `vocab/capabilities.json`，约定写在 `vocab/capability-signatures.md`「怎么念」。
