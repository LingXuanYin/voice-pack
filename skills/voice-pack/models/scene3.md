# scene3

Every dubbing job uses it: one person speaking (cloned from one or several reference segments, or with no reference, using its built-in voice), or a scene with several people. This file covers only how to use the model itself and is not tied to a platform: it applies wherever the same model is called. Limits that a platform adds (how long to wait, how to upload, what the command line can pass) go in that platform's adapter. When a scene sub-skill or the dubbing flow needs one of the entries here, write this file's path and the section name; do not write the entry again.

**How the source is written.** Each entry ends with its source; anything not tested is marked "not tested". The kinds of source:

- **Platform statement**: a platform's statement about this model, read on 2026-11-04; the recommendation quoted for `drama_value` in "Expressiveness" was read again on 2026-11-08.
- **Vendor documentation**: the model vendor's documentation and this model's technical report (called "the technical report" below), a local copy read on 2026-11-03; the cue-writing styles (section "Cues") were checked against the model page again on 2026-11-06, and the technical report was read again on 2026-11-08.
- **Vendor official pages**: the vendor's official web pages, the source code of the demo program, and the technical report of the vendor's previous model, read on 2026-11-08. Short names used below: "the launch blog" (the blog that announced this model), "the Halloween blog" (the blog about Halloween voice-over cues, whose demos use this model), "the previous report" (the previous model's technical report; the technical report says its training cue style is the same as that one), "the demo program" (the source of the vendor's official demo program).
- **Inference code**: the code that runs this model on the platform, the version read on 2026-11-02 (commit `d953ab70`); the model-side code was checked once more on 2026-11-05, and entries that say so refer to that check. This is a layer wrapped around the model and may differ in another deployment, so it is listed separately.
- **Measured**: give the date, how many clips, and who judged. When a person listened, write "one person, blind listening"; when a model that can listen to audio judged, write "model judged", and a "no effect" from a model judge can only be read as "not detected", not as "no effect". Model judging comes in two kinds. Judging whether it sounds natural, whether it sounds put on, whether the emotion and the acting came through, whether it was acted well, gives leads, not readings: calibrated against real human recordings, this kind of judge also mostly calls a real person "clearly acting" and cannot tell a real person from synthesis (2026-11-09, two real recordings, 5 of 6 passes said "clearly acting", 1 said "slightly put on"); a rule that rests only on it is written as an inference. Judging which language or dialect was heard, which characters were read, which person it is and how old, was outside that calibration, so it is still written "model judged", and where no person has checked it, say so; it can also transcribe wrongly (the Cantonese entry in "Cross-language and accent": in two of three passes the opening was transcribed as other characters).
- **Requirement**: a requirement set for how to write; give who raised it, the date, and the original words. It is a requirement, not a measurement.

## What it accepts and what it does not

- Accepts: the text to speak (cues are written inside it); 0 to 16 reference audio segments, each of which can carry its text; with several speakers, the speaker markers in the text; two parameters: `drama_value` (controls expressiveness, see "Expressiveness: `drama_value`") and `seed` (sampling, see "Sampling: `seed`"). Source: platform statement; for the 16 segments see "Limits of one request".
- Does not accept: whole-passage instructions (`instructions`), a speech-rate parameter, names of built-in voices, a description for designing a voice. So it cannot design a voice (use another model for voice design); how each part is said can only be written in the text; how much drama the whole passage has is controlled by `drama_value` (see "Expressiveness: `drama_value`"). Source: platform statement.
- Languages: about 80. Source: platform statement.
- No reference: it speaks in its built-in voice (platform statement: in a built-in voice). Whether the voice stays the same when the same character gets a different line: not tested.
- Cloning from a passage it generated earlier (platform statement: clone prior generated audio): a designed voice is made this way: dub an acted passage from the design audition text, then use that passage as the pack's reference (`references/make-pack.md`「Making a pack from a designed voice」). Done once on 2026-11-06: a generated passage (11.3 seconds) was used as the reference to dub the audition line, and it produced sound as usual. How well it was acted and how close it is to the designed voice: nobody listened to it, and the effect is not tested.

## Cues

The vendor documentation lists the six control styles below; all can be used, each where it fits; they can be mixed within one line (vendor documentation: you can mix them freely in the same line). For each style, write first when to use it, how to write it, and how far it reaches; the examples follow the vendor documentation; readings come after. A reading is only a reading: "not tested" or "not detected" is not a reason to leave a style out. Source: requirement, raised on 2026-11-06 by the author of the "Good examples" below, in the words "what I said is not whether it was tested" and "use the model's abilities 'fully!!!'".

- **Delivery direction** (square brackets): how this spot is said, the emotion and the manner. Write it before the words it governs; it governs from there onward. See 「Where a cue is written and how far it reaches」 and 「What to write」.
- **Sudden sounds and pauses** (square brackets): a sigh, a laugh, a breath in, a short pause. Write it at the position where it happens; it is just that one moment. See 「Sudden sounds and pauses」.
- **Paired tags**: a few words or one sentence said differently (whisper, softer, stressed, forceful, slower, faster); `<whisper>…</whisper>` wraps those words and governs only the wrapped words. See 「Paired tags」.
- **Language tags**: a sentence with a few words in another language; `<french>…</french>` wraps them and governs only the wrapped words. See 「Language tags」.
- **Phoneme tags**: a word that must be read with a given pronunciation; `<|phoneme_start|>phonemes<|phoneme_end|>` replaces that word (for Chinese, one tag per character); for a word whose pronunciation is written in the pack's pronunciation lexicon, `dub` writes it for you. In the few lines tested, a reading that the context cannot guess followed the tag (transcription, model judged, not checked by any person, see 「Phoneme tags」); do not use it to spell a dialect pronunciation (「Cross-language and accent」). See 「Phoneme tags」.
- **Speaker tags**: a scene with several people; `<|speaker:N|>` is written at the start of each turn and governs until the next speaker tag. Do not write it in the script; write it into the request following the script's `[voice:]`. See 「Speaker markers」.

The two square-bracket styles are cues and the three angle-bracket styles are text (`references/markup.md`「Angle-bracket tags」): `dub` hands them all to the model as they are, by position. The pronunciation lexicon does not change the tag names or phonemes inside angle brackets; when splitting a line that is too long it does not cut between a pair of tags (for a pair longer than one request, it cuts inside and adds this pair of tags at both ends of each piece); and when it detects the language it does not count the letters inside tags, nor the words in another language wrapped by a language tag.

### Put the character name first

Every dubbed line starts with the character's name in square brackets, ahead of all other markup: `[甘雨][calm, gentle voice]……`. Write the name in the language of this line: for a Chinese line write `[甘雨]`, for an English line write the character's name in English (`[Ganyu]`; if there is none, the romanization of the name), for a Japanese line the Japanese name, and so on. It is the only square bracket not written in English; it is not a direction for acting and does not stand for any voice. A scene with several people is the same: each line starts with the name of the character who says it. When the reference is in another language, write a name pair at the start, `[name in the reference language|name in the line language]`, each language once (「Cross-language and accent」). Examples elsewhere mostly leave it out; when you write a script, always write it.

When `dub` sees a square bracket at the start of a line, it does not add the setup's opening cue (`references/dub.md`「Opening cue and speed」); the character name counts too: if the setup fixes a tone, write the tone after the name.

When a line is cut into several requests (cut at a long pause, cut because it does not fit), `dub` repeats the line's first square bracket at the start of the later requests, so every request starts with the name and you do not need to write it again. For an old script whose first square bracket on a line is not the name, what is repeated is that cue.

The reference side gets the name too: in a same-language request of one line, when the line opens with this pack's name (the manifest's `name`), `dub` writes the same name at the start of the reference text (`[沈迟][calm]门响我就听见了。……`); for cross-language, write the name pair as in 「Cross-language and accent」. For a line in the pack's own language the name has to be the pack's `name` exactly (`pack.name` in the plan of `dub --dry-run --json`): `dub` compares the start of the line with it, and a different one (for example the pack's `name` has a suffix and the line does not) gets no name on the reference text, which is the case below with the name only on the line. With the name only at the start of the line and not on the reference, scene3 sometimes voices the whole line several semitones to an octave below the reference. Readings: 2026-11-12, 3 designed voices (two female, one male), 3 versions each, the acted passage dubbed from the audition (expressiveness 80), 30 seeds per version, 270 clips per group, measured by program (Praat, median fundamental frequency, compared with the reference; two other ways of reading checked it, no octave jump): with the name only on the line, 19 clips 3 or more semitones low, 6 clips 5 or more semitones low (at most 21 semitones low); with the name on both sides, 3 and 0; with the name on neither, 3 and 0. Each group is those 270 clips, in two batches of 135, and the two batches go the same way. Once the acted passage is dubbed low, it is the only reference of the formal pack: dub the audition line with it, and changing the seed, the expressiveness or the reference text, or removing the cue, all stay low (one pack, 28 of 30 times), and so does writing the name on both sides (5 of 5 times). Nobody has listened to whether it is still the same person. Source: measured; that the two sides match is a requirement, raised on 2026-11-10 in the words "The annotation must be symmetric. The character name must also be marked".

Source: requirement, raised on 2026-11-10 by the author of the "Good examples" below, in the words "all scene3 synthesis must start with [character name] first" and "this requirement must go in the skill". The same day one person listened to the cross-language dubbing of four characters (an English reference speaking Chinese) and compared with and without the name; in the words "much better" (one round); it has not been compared separately for dubbing in a single language.

### Where a cue is written and how far it reaches

- A cue is written in square brackets, before the words it governs, and takes effect from where it is written. Source: vendor documentation (Put a direction in square brackets before the words it applies to); platform statement (Square-bracket cues act where placed).
- Several can be written in one sentence, at the points where the manner changes; each later one continues from the one before. Source: launch blog (Add new direction where the mood changes, and the read changes there; New direction partway through changes the read from that point); "Good examples" below.
- Where a cue stops (at the end of this sentence, at the end of this line, or all the way to the next cue): the technical report says a cue at the start of a sentence governs the whole line; whether it still governs across lines and passages is not tested.
- Cues are not only for the start; write another one when the manner changes; if the two halves of a sentence are said differently, write one for each. Source: launch blog (same as the previous entry); Halloween blog (To take the same line further, direct its two halves separately); previous report (rather than relying on lengthy global prompts, we inject descriptive instructions at specific word or phrase positions); requirement, raised by the author of the "Good examples" below (the words are under 「What to write」). The demo program has a comment saying that the reference's acting overrides one short cue at the start (A single short prefix is often drowned out by the reference performance.): it is used only when re-acting (dubbing another version with one instruction), by repeating the same instruction before every sentence, with no measurement attached, so it is not used as a source.
- **Set the state first, then write the cue.** Do this step in the writer's own draft, not in `dub`.
  1. Once the lines are written, lay them out by clause (a short stretch separated by punctuation; a question mark or exclamation mark also counts as a boundary). Write a state for each clause: how the person is here and how the voice is, two or three words; what is still lasting from before (a lowered voice, a tearful tone, guilt) is written in as well, for example "guilty, quiet".
  2. If a clause's state is the same as the previous clause in the same line, write no cue; if it differs, write a cue before this clause, and what is written is the whole state of this clause, so the lasting part comes along naturally. If a state is longer than 4 words, put two square brackets side by side. The first clause of a line (a turn, a passage) has no earlier clause in the same line, so write one there (whether the previous line's cue reaches here: see the entry 「Where a cue is written and how far it reaches」 on where a cue stops; where a setup was chosen and `dub` adds the setup's cue at the start, do not write one if it is the same as the setup, `references/dub.md`「Opening cue and speed」). Also write one for the first clause after a request split, whether or not its state equals the previous clause's: at a long pause or where a passage does not fit, `dub` cuts one request into two there, and the later request does not carry the earlier one's cue (`references/dub.md`「One request per passage」).
  3. A sudden sound (a sigh, a laugh) is not a state; write it at the position where it happens (「Sudden sounds and pauses」); something that governs only a few words, wrapped in a paired tag (「Paired tags」), is not a state either.

  Why each cue writes the whole state: after a later cue is written in a line, whether the manner in the earlier cue stays on, the vendor does not say and it is not tested; treat it as replaced. Source: launch blog (New direction partway through changes the read from that point, same as the previous entry); the steps above are a procedure, not a reading.

  Example (a writing example, not tested; the states were worked backward from the cues of that line in 「Good examples」): three clauses, three states, three cues. `我不是不想留下来……` is sad and surprised, write `[sad and suprise]`; `我只是，` is crying and quiet, write `[crying quietly]`; `没有办法再假装一切都很好了！` is crying and angry (the crying is still lasting from before), write `[crying and angry]`. (The three Chinese clauses are example lines and stay Chinese; the spelling "suprise" is as in the source.)
- **Add a few more things when dubbing.** Write the lines first as in 「Where a cue is written and how far it reaches」›「Set the state first, then write the cue」 above, then add the few items in the table below. Do not change the words or the punctuation; only insert square brackets and pauses. This is a way to write "the features of the person speaking at each point" into the lines; when marking a reference's text while making a pack, use the same idea (「Reference text and cue annotation」 below).

  | Wanted | Script writes | Basis |
  |---|---|---|
  | A pause | `，[pause 0.6s]`, written after the comma. `dub` writes it into the request as `，[pause]`. A bare `[pause]` is 350 milliseconds, and the closest thing after a comma is to add nothing (about 325 milliseconds), which is the same as writing nothing | Reading: in 5 of 6 cases longer than writing nothing, the longest 0.59 seconds, short of the about 0.73 seconds measured in 「Pause between lines」 below |
  | A sigh | `[sighs]`, written where it happens | Reading: the pause before it got longer for all 3 seeds; whether the sigh itself came out was not measured |
  | The emotion changes | Same as 「Where a cue is written and how far it reaches」›「Set the state first, then write the cue」 | Reading: emotion words have the largest effect on speed |

  Do not add speed here: a separate speed cue written to adjust the speech rate dropped words when listened to (「Speed and pauses: conclusions from listening」 below). This table used to have two more rows, `[fast, rushing]` (reading: in 5 of 6 it was slower instead) and `[slow, drawn out]` (reading: in the line that had it, characters per second dropped for all 3 seeds); the version listened to under "Scope" below had them, kept as a record.

  The readings in the table were all measured on the same voice and say what happened, not whether it is good. `，[pause 0.6s]` writes 0.6 seconds, which does not exceed the limit for one pause within a request (750 milliseconds by default; for where it comes from see the last entry of 「Pause between lines」 below), so it is written into the request and the request is not cut (`references/dub.md`「One request per passage」).

  Where to pause (inference; the writer does it as written, without asking a person): after a form of address (「师父，」, "Master," in Chinese); before an emotional turn; where something is held back in a sentence and a harsh word is about to be said. At most one place per clause.

  Do not write: `。[pause]`, `[long pause]`, a lone `……` (these have been measured to drop the next sentence; for the counts see 「Pause between lines」 below). `<slow>` measured by duration did not slow down, and `<fast>` is not tested (「Paired tags」); write them if you like, just do not treat them as ways to slow down or speed up.

  Scope: one person listened, to a Chinese-speaking voice, the same passage dubbed in two versions, one with a few items from this table added and one without. The version with them added was clearly better overall; only the closing sentence was worse than the one without; the two versions differ on that sentence only by a `[slow, drawn out]`, and whether it caused this, the listener did not say and no one listened to it separately (reading: characters per second in that sentence dropped for all 3 seeds, from 7.0, 6.1, 7.7 to 5.4, 4.8, 6.0). The items in the table were added together, and which one worked has not been listened to separately. Other voices and other languages were not listened to, nor were default segments and audition lines. These items were listened to only on lines spoken by one person: in a scene merged from several people, write pauses following `scenes/a-scene.md`, and do not write a `[pause …]` that would cut the request.

### What to write

- Write specifics, at the position where they happen. For the control you hand to the model, write the concrete way this spot lands in the voice: which words are read how, where the pitch goes, whether the end of the sentence rises or falls, fast or slow, which words to use, written before the words where it happens. Summarizing labels such as "带一点四川口音" (with a slight Sichuan accent), "新闻播报的口吻" (a news-broadcast tone), "像刚睡醒" (like just woke up) only give a name to a kind of delivery; the model does not know which words change and how, so do not hand them to the model: first work out what it is concretely like, then write it at the position where it happens following the entries below in this section (for accents and dialects see 「Cross-language and accent」). Model notes for other models follow this entry: a model that takes a whole-passage instruction also gets specifics in the instruction; a description for designing a voice is the same. Source: requirement, raised on 2026-11-08 by the author of the "Good examples" below, in the words "What concrete features does that accent have? How do the tones change, and how do you write that? If you just write a label saying accent, how would the model know?" "If you write a generalized accent in, haven't I told you not to treat the model as a trash can???" "And aren't all the other model skills the same logic???". How to sort: look at what the word is saying.
  - If it says how this spot sounds, how the voice changes, it can be written as a short cue: the state that can be heard at this spot (emotion, state of the voice: `[angry]`, `[tired]`, `[crying quietly]`), or a concrete change in the delivery of this spot (volume, speed, which way the pitch goes, the throat: `[hushed voice]`, `[slowing down]`, `[rising tone]`, `[raspy]`). These are examples for classifying; for the effect see the readings in the entries below.
  - If it is the name of a whole kind of delivery, break it into concrete features and then write them: accent, dialect ("带一点四川口音", with a slight Sichuan accent), genre or occasion ("新闻播报的口吻", a news-broadcast tone; "讲故事", telling a story), tone or manner of telling ("播音腔", announcer voice; "娓娓道来", telling it in a flowing, unhurried way), identity or persona ("老人", an old person; "少年", a youth; "讲述人", a narrator), sentence type ("反问", rhetorical question; "疑问", question; "感叹", exclamation), and comparisons to other people or other occasions ("像刚睡醒", like just woke up; "聊天似的", as if chatting). Break it into states and changes as in the previous entry, each written at the position where it happens. Sentence type is the same: if the line itself is a question, the cue writes how the voice concretely changes at this spot (the end of the sentence rises, `[rising tone]`; for the word to be stressed, wrap that word in `<emphasis>…</emphasis>`, see 「Paired tags」), and does not write `[反问]` or `[疑问]`; the writing here is an example, not tested.
  - If it is about the content of the words or how they are phrased (`口不择言`, speaking without thinking; `搬出师父`, bringing up the master): this is what the line is written as, not the state of this spot and not a change in the voice, so do not write it into a cue; write how it lands in the voice, for example for the line that speaks without thinking, write `[angry, rushed]` (a writing example, not tested).
- Do not write what cannot be heard. A cue writes only the emotion and voice state that can be heard with eyes closed (`[crying quietly]`, `[angry]`, `[hushed voice]`). Do not write either of these two kinds: body movements, looks, what is in the hands, the scene (`[瞪他一眼]` glares at him, `[把碗推过去，声放软]` pushes the bowl over, voice softens); what the sentence is doing (`[招呼，利落]` greeting, brisk; `[嘴上嫌]` complaining in words; `[亲热，表功]` affectionate, claiming credit). Attitude, intent, and who is being spoken to are the same: write what is heard as it sounds (`[cold, clipped]`), and do not write what cannot be heard. The remaining entries in this section and the excerpted vendor documentation all follow this entry. Source: requirement, raised on 2026-11-09 by the author of the "Good examples" below, in the words "this wrong way of writing has to be explicitly forbidden, or whatever you write in is useless".
- Write what is to be heard, not what is not wanted: no negation such as `no`, `not`, `without` appears in the square brackets (write `[calm]`, not `[no anger]`). Source: requirement, raised on 2026-11-10 by the author of the "Good examples" below, in the words "isn't it the case that square brackets are not for writing what not to do?".
- Free natural language. Source: vendor documentation (Write it the way you'd brief a voice actor: emotion, intent, pacing, or who the character is talking to). The examples in the vendor documentation and the technical report (`[softly][to herself]`) also list intent and who is being spoken to as acting direction; here they are only excerpts, and whether to write them follows 「What to write」 "Do not write what cannot be heard" above. Do not write full sentences and do not write cause and effect (what this sentence is responding to, why it is said this way); write how it lands in the voice. "Do not write full sentences, do not write cause and effect" is how the requirement in the next entry reads when read this way. For how long to write, see the next entry.
- One per spot, or two short ones side by side; each short and precise: no more than 4 words (aim for two or three; over 4 words, `dub` warns in `long_cues`), making clear the emotion or manner of this spot (`[crying quietly]`, `[hushed voice]`), not written as a sentence. Two side by side are for layering manner and emotion (`[hushed voice][cold]`), not tested. Also do not write too few: write whenever the manner changes, and several are fine in one sentence. Source: technical report (A control is a short span in square or angle brackets, typically a few words); previous report (rather than relying on lengthy global prompts); for two side by side, Halloween blog (pair a delivery with a feeling, like [whispering][menacing]) and the technical report's examples `[clears throat][serious]`, `[softly][to herself]`; requirement, raised on 2026-11-06 by the author of the "Good examples" below, in the words "full, fine-grained, concise control; the control tags are not for writing a little essay, and the point is not to write nothing or to write little", and on 2026-11-08 the same person asked again "why put such a long thing in [] instead of several [] controlling fine points one by one???", which follows 「Good examples」. Length was compared only on the first page, in two groups (one person, blind listening): `[气得发抖，压着嗓子质问对方]` (shaking with anger, interrogating the other with a pressed voice) against `[生气]` (angry); in one group the acting was fiercer, in the other the two sounded about the same (「Readings from the first-page audition」 below); it was not detected that short is better than long.
- Always write cues in English, whatever language the line is in. Two or three words, only emotion and voice state that can be heard, and they can carry the direction of pitch; write at every place where the manner changes, do not cut them down. For example `[happy, bright voice]`, `[enthusiastic, hurried]`, `[displeased, hushed voice]`, `[mock anger, loud]`, `[gentle, slowing down]`, `[casual, rising tone]`: words about volume can be used; words about speed go together with the emotion only when the manner of this spot itself changes (gets hurried, slows down), like `hurried` and `slowing down` in these, and are not written separately to adjust the speech rate (「Speed and pauses: conclusions from listening」 below). When making a pack, the text of the references marked by the program is also written in English (「Reference text and cue annotation」), and when `dub` replaces stage directions in the script with cues it also writes them in English (`references/dub.md`「How a line becomes synthesis」 step 2). Source: requirement, raised on 2026-11-09 by the author of the "Good examples" below; these examples come from the entry where one person listened and said "a cliff-like improvement" (「Good examples」 third example below), in the words "d is the best and is a cliff-like improvement over the other cases, mainly because the voice was not affected, and it is natural"; the comparison was the same recording dubbing the same line, changing only the square brackets: English at 9 spots (this entry) beat Chinese at 9 spots, English at 4 spots, Chinese at 4 spots, writing none, and the wrongly written version. The vendor documentation says any language can be used for writing (Directions can be in English or your own language, and they don't have to match the language of the script; example `[像是在强忍着眼泪，却努力笑着] I'm fine. Really. Go on without me.`); here it is only an excerpt, and this entry governs. Readings: the Chinese `[生气]` can be heard in the first-page audition (「Readings from the first-page audition」 below, which also has a longer version for comparison); for the English ones see 「Good examples」.
- Speed follows the manner: when the manner of this spot itself changes and it gets hurried or slows down, write speed and emotion together in one direction (`[nervous, hurried]`, `[gentle, slowing down]`); when the character always speaks fast or slow, or you want to speed up or slow down the whole sentence, do not write a speed cue (it dropped words when listened to, 「Speed and pauses: conclusions from listening」 below). Source: vendor documentation (Write it the way you'd brief a voice actor: emotion, intent, pacing…; the scene example `[fast, nervous, stumbling over words]` (a quotation, longer than the 4-word limit; take its direction, not its length, same as the previous entry), `[slow, dangerously quiet]`). Readings: writing "非常慢" (very slow) at the start of a sentence measured by duration did not slow down (the `<slow>` entry in 「Paired tags」 below); `[fast, rushing]` did not speed up either: one dubbing voice, two places, in 5 of 6 readings it was slower instead (「Add a few more things when dubbing」 after 「Where a cue is written and how far it reaches」›「Set the state first, then write the cue」); to get fast, rely on emotion words and write fewer pauses; other ways of writing hurry and fast are not tested. To make a whole sentence faster or slower by an exact multiple, use the setup's speech rate instead, changing speed after synthesis (`references/dub.md`「Opening cue and speed」).
- Onomatopoeia in a cue may be read aloud, so treat it as read aloud. To get a laugh, write it at the position of the laugh (`[small laugh]`, `[laughs]`, 「Sudden sounds and pauses」 below) or write the manner (`[smiling voice]`, not tested), and do not write the laugh as characters (`嘿嘿`, "hehe"; `哈哈`, "haha"; these are Chinese-only examples). Source: measured, 2026-11-05, two items, judged by transcription (model judged), no person listened to this spot specifically: for `[小声，嘿嘿地笑，有点不好意思]` (quiet, laughing "hehe", a bit embarrassed), one transcription had an extra "嘿嘿" and the other transcription had "哎呀" at that spot, so it cannot be told whether it was laughed out or the characters in the cue were read aloud; for `[眼珠一转，凑近了，嘿嘿笑着，讨好地商量]` (eyes dart, leans in, laughing "hehe", wheedling), across two transcriptions three times in all, none had "嘿嘿".
- Fine acting (throat position, tightness, breathiness, huskiness, pressed voice and the like): write it as one short cue for this spot, two or three words, together with the emotion or manner of this spot (`[raspy, tired]`, `[tight throat]`, `[hushed voice]`; in the vendor examples `low, gravelly`, `voice breaking`, `almost a whisper`), written before the words that should be voiced this way. Write another where the manner changes; a voicing that must still continue in this stretch (lowered voice, tearful tone) is also part of the state, so write it in; for how, see 「Where a cue is written and how far it reaches」›「Set the state first, then write the cue」 above. Do not write one sentence describing the part of the vocal tract, and do not pile several items into one square bracket at the start of the sentence. A character's usual voice relies on the reference and the design description and is not written at each spot (readings below); the exception is several characters sharing one reference (one pack playing several characters): the reference cannot carry each person's voice, and each person's voice is the manner that is still lasting from before, carried in every new cue; whether this way of writing tells them apart is not tested. The few written here by hand are writing examples, not tested. Source: technical report (typically a few words, see the previous entry); previous report (rather than relying on lengthy global prompts, same as above); launch blog (Add new direction where the mood changes, and the read changes there; example `[choked up, crying quietly] … [voice breaking] …`); requirement, raised on 2026-11-08 by the author of the "Good examples" below, in the words "why put such a long thing in [] instead of several [] controlling fine points one by one???". In the vendor examples, the only words about the throat in the acting direction are a few like `low, gravelly`, `voice breaking`, `almost a whisper`, all written together with the emotion or manner; there is no way of writing that talks about vocal parts such as throat position or tightness. A character's usual voice is written in the character description (the technical report's example `Mr. Carter: steady male voice, about 40, formal.`), and this model does not accept a description on the platform (「What it accepts and what it does not」). Neither reading was measured with the writing above: the "压着嗓子" one was a long square bracket at the start of the sentence (`[气得发抖，压着嗓子质问对方]`); the 2026-11-07 one measured whether different characters can be told apart and whether it resembles the designed audition, not whether this kind of voicing comes out. Whether one short cue per spot, written before the words to be voiced this way, makes it come out is not tested.
- Cues about volume and force (the `[quietly]` kind) may make this sentence breathy, softer, and flatter in pitch; cues about manner and attitude (`[calm]`, `[warm, relaxed]`) do not. ### Sudden sounds and pauses

- When to use: a sigh, a laugh, a breath in, a short pause; sounds that are over in an instant.
- How to write: square brackets, written at the position where it happens, and you can say what kind of one it is. Source: vendor documentation (Put a sound or pause in brackets exactly where it should happen, such as a sigh, a laugh, a breath, or a short pause; example `I'm fine. [shaky breath] Really. [small laugh] Go on without me.`, two in one line).
- Pause: write `[pause …]` in the script; it is a script marker, and `dub` writes it into the request the way measured in 「Pause between lines」 below, cutting the request there if the pause is long (`references/markup.md`).
- Lead: 2026-10-30, 8 seeds paired, model judged whether it came out: the point-style `[sighs]` reached the threshold in all 8; the point-style `[laughs]` in only 1; the point-style `[pause]` did not reach it (the judging threshold was changed after the measurement, so this entry is weaker). No person listened; that `[sighs]` works is an inference, and `[laughs]` can only be read as not detected. Reading: measured by silence, a `[pause]` mid-sentence gives about 0.8 seconds of silence, see "Pause between lines". One voice, 3 seeds: the pause before the position where `[sighs]` was written got longer (whether the sigh itself came out was not measured); for a pause after a comma, the script writes `，[pause 0.6s]`, see 「Add a few more things when dubbing」 after 「Set the state first, then write the cue」. The vendor's own forms `[shaky breath]` and `[small laugh]`, and the breathing kind, are not tested.

### Paired tags

- When to use: a few words that need a different manner while what comes before and after stays as is. `<whisper>` for words said in a hush; `<soft>` for words made softer and gentler (comforting, coaxing); `<emphasis>` and `<stress>` for words to be bitten down on (the vendor does not say how the two differ); `<forceful>` for words said with force (a rebuke, an order); `<fast>` and `<slow>` for a few words sped up or slowed down. A whole sentence that is all whispered or all slowed can also be wrapped whole (the vendor's example `<whisper>Go on without me.</whisper>` wraps a whole sentence); a manner that spans sentences or a whole passage is written as acting direction.
- How to write: `<tag>…</tag>` wraps those words. The vendor lists the tags by name only: `<whisper>`, `<emphasis>`, `<soft>`, `<fast>`, `<slow>`, `<stress>`, `<forceful>`; the usage in the previous entry follows the meaning of the names. It can be written together with acting direction. Source: vendor documentation (Wrap words in a paired tag … to change the delivery of those words only; example `I'm fine. Really. <whisper>Go on without me.</whisper>`, and one turn in a scene `[voice breaking, close to panic] It is going to <emphasis>blow</emphasis>.`).
- How far it reaches: only the wrapped words. In a scene with several people they can also be used inside each turn (vendor documentation: Directions and paired tags from this page work inside each turn). Whether they can be nested and whether they can span lines, the vendor documentation does not say. Write a pair of tags in one line, with no `[pause …]` in between: the base part may cut the request at those places, the tags would be split across two requests, and the plan's notes have an entry `tag_pair_split` (`references/markup.md`「Angle-bracket tags」).
- Readings:
  - `<whisper>` works: 2026-11-06, one English sentence, one seed, measured by program. In the wrapped half sentence the voiced part dropped from 54% to 22%, loudness about 6 dB lower, no stable pitch; the transcription still produced those words (model judged, not checked by any person).
  - `<emphasis>` may work: the same day, one sentence, one seed, measured by program. The wrapped word had pauses of about 0.5 and 0.4 seconds before and after it, a peak more than 2 dB above the other words, and the pitch was not higher.
  - `<slow>` measured by duration did not slow down (2026-10-30, 8 seeds paired, the difference smaller than the fluctuation between seeds). The same for "非常慢" (very slow) at the start of a sentence and for "非常慢" written as acting direction on a line of its own. No way of writing a slowdown that works has been found on this model. For an exact multiple, use changing speed after synthesis instead (`references/dub.md`「Opening cue and speed」); speed words in acting direction and `<slow>` can still be written.
  - `<fast>`, `<stress>`, `<forceful>` are not tested. `<soft>` on a Chinese-speaking voice did not measure as heavier breathiness, and in the same group `<whisper>` did not bring it down either, see 「Breathy voice, whispering and gasping」.
  - In the 4 sentences of 2026-11-06, not one tag name was read aloud (transcription, model judged, not checked by any person).

### Language tags

- When to use: a sentence with a few words in another language, for example a French sentence quoted inside an English one. A whole sentence in another language is not a matter for here, see 「Cross-language and accent」.
- How to write: the English name of the language, lowercase, as the tag name, wrapping only the words that changed language. Source: vendor documentation (Wrap a phrase in a language tag to switch language for those words only; Wrap only the words that change language; example `She looked at the menu and said <french>Je voudrais une table pour deux, s'il vous plaît.</french> The waiter smiled.`). The vendor's examples include `<french>`, `<spanish>`, `<german>`, `<japanese>`, `<chinese>`, `<korean>`, `<italian>`, and do not say these are the only ones; the main sentence of the examples is always English. The vendor has no `<english>` example and no example of switching language inside a Chinese sentence; write them the same way (a few English words in a Chinese sentence are written `<english>…</english>`).
- The vendor's caution: this is experimental; the voice has to be cloned from a recording of someone who speaks both languages; how accurate it is depends on the language and the voice; when the text already mixes several languages, the model may switch language by itself.
- Reading: 2026-11-06, one English sentence with a French phrase wrapped in `<french>`, one seed, the reference a recording in English. Both transcriptions (model judged, not checked by any person) did not write it as English words (one wrote it correctly in the French original); there were pauses of about 0.4 and 0.9 seconds before and after the phrase, and the later one was much longer than usual (measured by program). Other languages, and switching language inside a Chinese sentence: not tested.

### Phoneme tags

- When to use: a word that must be read with a given pronunciation and whose reading the context cannot guess: proper names, rare words, loanwords. For a polyphonic character in a common word, tagging may not change it (see "How far it reaches" below). Do not use it to spell a dialect pronunciation, see "How far it reaches" and 「Cross-language and accent」.
- How to write: `<|phoneme_start|>phonemes<|phoneme_end|>` replaces that word, and the original characters are not written any more. It is the same form as the phoneme tags of other models. The phonetic notation for each language (vendor documentation):
  - English uses CMU Arpabet, one space between phonemes, the digit after a vowel is stress (1 is primary stress, 0 is unstressed), and one tag replaces one word: `I am an <|phoneme_start|>EH1 N JH AH0 N IH0 R<|phoneme_end|>.`
  - Chinese uses pinyin with a tone number, one tag per syllable, tones 1 to 5 (5 is the neutral tone), lowercase, with punctuation, brackets and spaces written outside the tags: `我是一个<|phoneme_start|>gong1<|phoneme_end|><|phoneme_start|>cheng2<|phoneme_end|><|phoneme_start|>shi1<|phoneme_end|>。`; you can also tag only the ambiguous character: `请把这个字读作<|phoneme_start|>hang2<|phoneme_end|>。`
  - Japanese uses OpenJTalk-style romaji with pitch numbers, one tag replacing a short word or phrase: `<|phoneme_start|>ha0shi1ga0<|phoneme_end|>見えます。`
  - The pinyin ü is written `v` (`lv4`), and the neutral tone is also written with the number 5 (`ma5`). Writing 5 for the neutral tone is what the vendor documentation says; the vendor documentation does not say anything about ü, and here `v` is written following the default of pypinyin (the vendor says training used its tone3), not tested.
- The pronunciation lexicon writes it for you: for words whose reading the pack's pronunciation lexicon (`lexicon.pls`) writes with `<phoneme>` (Chinese `x-pinyin`, English `x-arpabet`, Japanese `x-romaji`), when the environment declares `phoneme-markers`, `dub` replaces the word with phoneme tags in the form above, and in a scene with one request each turn is also replaced (`references/dub-details.md`「Pronunciation lexicon」; for how the lexicon is written see `references/make-pack-details.md`「Pronunciation lexicon」). Where the lexicon does not reach, write it yourself in the script.
- How far it reaches: in the few lines tested, a reading the context cannot guess followed the tag; when the reading the tag gives conflicts with a common word in the context, the common word's reading wins, and tagging may not change it (the readings below, two sentences). So tags are for fixing the readings of names, rare words and loanwords, and are generally not used to change a common word to another sound; and each tag costs money (next entry), so try on a few sentences first, write further only after listening confirms it can be changed, and do not tag what cannot be changed.
  - Do not write a dialect's pronunciation this way. Write the dialect as its own words, and write a common character whose reading differs as the character that reads that sound (`去` written as `切`), see 「Cross-language and accent」. Where every syllable of a whole sentence was written as a phoneme tag (the Chengdu readings and tones), the syllables changed (model judged, not checked by any person), and one person listening to seed 1 did not hear Sichuanese (the 2026-11-08 reading below).
  - This is a different case from "银行" ("bank", read yín háng; a Chinese example that stays Chinese). "银行" is a tag placed inside a common word: the tag conflicts with the characters, and the common reading overrides the tag; in that whole sentence there are no characters and every syllable is a tag, and the syllables were read following the tags (model judged, not checked by any person), but the tune is still Mandarin (only one person listened to seed 1 and did not hear Sichuanese; the tune was not measured separately; the 2026-11-08 reading below).
- Cost: the platform charges by the number of characters sent, and the characters of the tags count too. A pinyin tag is 32 characters from its two ends alone, one tag per syllable; in the "曾小雨" group below, the sentence with the lexicon sent 116 characters (10 without), 0.01624 US dollars each time, more than 11 times the one without (0.0014 US dollars). So write phonemes only for words that really would be misread.
- Readings:
  - 2026-11-06, 12 runs (6 sentences, one each for seed 1 and 2), judged by transcription (model judged, not checked by any person) and acoustics measured by program. A reading the context cannot guess followed the tag: English `The name on the door was <|phoneme_start|>Z AO1 R B IH0 K<|phoneme_end|>.` was read as Zorbek, `M EH0 L AH0 F UW1 N` as Melaphone, and penguin, written only inside a tag, was also read right, and the stress digits were not read aloud; Chinese `门上写着<|phoneme_start|>zhua1<|phoneme_end|>。` was read as zhua. One that conflicts with a common word did not follow the tag: `我们明天去银<|phoneme_start|>xing2<|phoneme_end|>办事。` was read yín háng both times, the same as without the tag. An English sentence from earlier the same day (one seed) that tagged tomato with the other reading was also read with the common reading (also a transcription, not checked by any person).
  - 2026-11-06, a polyphonic character in a name: `曾小雨曾经来过这里。`, the pronunciation lexicon writes `曾小雨` as `zeng1 xiao3 yu3` (`dub` writes three phoneme tags), dubbed with and without the lexicon, each with seed 1 and 2, 4 runs in all; the platform returned audio every time, for the cost see "Cost" above. What "曾" was read as, and whether "曾经" changed with it, nobody has listened to yet.
  - 2026-11-08, every syllable of a whole sentence written as a phoneme tag, with no characters in the sentence: a designed voice (the reference in Mandarin), one Sichuanese sentence, using the Chengdu readings and tones (`wo4 men3 jin1 tian1 qie3 ci3 fan3…`, one tag per syllable), with `[尾音往上挑]` ("the end of the sentence tilts up") at the end of the sentence; two seeds, one version each. The readings changed following the tags (`qie` and `ci` came out, model judged, not checked by any person), but it still sounded like Mandarin: the listener was the author of the "Good examples" above, she listened to seed 1 and did not hear Sichuanese; the model that can listen to audio, judging three times for each clip, was inconsistent on seed 1 (two Mandarin, one Southwestern Mandarin), and all three for seed 2 were Mandarin (not checked by any person). Only this one voice and one sentence, a small sample. For the other ways of writing compared with this group see 「Cross-language and accent」.
  - Not tested: where the model would have misread it and the tag gives the right reading (the "曾" group above has not been listened to); tags inside one request for a scene (not dubbed on the platform); the neutral tone written 5 and the tag with ü written `v`; Arpabet's secondary stress 2; Japanese tags (only one vendor example).

### Text in round brackets is read aloud

- Text in round brackets is read aloud all the same. Source: platform statement. So stage directions (`（耳语）`, `*笑*` and the like; Chinese examples meaning "whispers" and "laughs") are replaced, before sending, by cues in square brackets, and are not left in round brackets.
- For lines dubbed through `dub`, a bracket in the script of 30 characters or fewer (round brackets, full-width or half-width both count, and also `【…】` and `*…*`; the asterisks must be tight against the text, `* 笑 *` is body text, `**…**` is emphasis and with the asterisks removed the text is read as usual) is always treated as a stage direction: it is replaced by a cue in square brackets, the text in the bracket is not read, and the same applies to what the lexicon does not recognize (`references/dub.md`「How a line becomes synthesis」 step 2; the plan's `notes` has an entry `unrecognized_directions` that lists the ones not recognized; one whose bracket carries a word from the lexicon is likewise not read, and is in it only when it is not in English: `（笑话比赛）` has "笑" in it and goes out as a Chinese cue, so it is listed; `(he smiles at her)` is not). So do not use round brackets in the script for text to be read: for body text in the original's brackets that must be read, first change it to a form without brackets (commas, dashes).
- Whether the Chinese full-width brackets are also read: not tested separately; treat them as read aloud.

Second example: one line of dialogue; a person listened to two versions (2026-11-09).

Original: [平静，克制]我已知晓，这是你自己选定的路。[低声，难过]只是……[嗓子发紧]再也不回来，这话听来，比我想的要沉得多。[shaky breath][稳住声音，坚定]罢了，永恒不会因一次别离而动摇，你且去。

When you write a line like this, write these two cues as in the trimmed version, and do not carry in the sadness that is still going on.

### Cross-language and accent

When a reference in one language is used to speak another language (cross-language cloning), the result often carries the accent of the reference's language (inference; one person listened in two cases: 2026-11-05, an English reference speaking Chinese, no cue written, 1 of 4 voices had it audibly; 2026-11-06, a Japanese reference speaking English, "just a slight accent"), and the timbre may also be unstable (so for the few voices listened to; for other voices it is inference); the two kinds of cue that were listened to (`[language: zh]`, `[native English pronunciation]`) and `<english>` all failed to remove the accent. The current practice (requirement, raised by the author of 「Good examples」 above on 2026-11-10, her words: "Didn't we already do the no-accent path before? Write it inside [], then use the target language for the text; with an accent it is the same operation"): the language of the voice follows the language the user chats in, not the reference. When the reference is in another language, do not ask and do not add another reference: write the lines in the target language, still pass `--allow-cross-language`, write a name pair at the start of each line, and `dub` writes the names and languages of both sides into the request (「Names and language cues」 below). The readings of the several ways of writing tried below are kept; none that was listened to removed the accent. If you leave out this option, `dub` still stops before spending money (`references/dub.md` step 3「No accent by default.」). When the user wants to add a reference in this language and has no recording in that language (also true for designed voices), the default is to have scene3 dub a passage in this language, cross-language, with the pack's existing reference, and use it as the reference; one clip is dubbed and used, the user does not pick; first use flash (`models/qwen-audio-3.1-tts-flash.md`) to read a passage following the original reference, and use it together with the original one as the reference in this language (the original language first, joined into one segment, see 「Reference segments」), kept as an option, listed only when the platform lets you specify the model (`references/character-voice.md`「Add a reference segment in this language」). **Names and language cues.** When the reference and the lines are not in one language, write a name pair `[name in the reference language|name in the line language]` at the start of every line of the script, followed by the direction for this moment and the line (take the two names from the pack's dubbing guidance, the item 「换语言时怎么说」›「名字」 (how to speak when the language changes › name), `references/make-pack.md`「The five sections of the dubbing guidance」):

```
[Harry Potter|哈利·波特][firm, low, quick]听着，罗恩……
```

The language cues and the names on both sides are written by `dub`; what is sent to the model is:

- Line: `[Harry Potter][firm, low, quick]听着，罗恩…… [language: zh]`. It starts with the name in the reference language and ends with the language of the line.
- Reference text: `[哈利·波特]full annotated text [language: en]`. It starts with the name in the line language and ends with the reference's language.

Do not write a leading language cue such as `[standard Mandarin]` any more. When a line is split into several requests, every request has the name at the start and the language cue at the end; when one request merges several lines, there is one name per line and the language cue only at the end; when a scene is one request, the language cue is at the end of the last turn, and the reference of each cross-language speaker is written separately.

Write the language as an ISO two-letter code, taking the primary language of the language tag (`zh-CN` is written `zh`). The reference's language is read from the manifest. The language of the lines is given with `--language`; if it is not given, it is recognised from the text: text that can only be one language is written as that language, Han characters count as `zh`, Latin letters count as `en`, so for other Latin-letter languages (`fr`, `es`) you must give `--language`. If a cross-language line has no name pair at its start, `dub` stops before spending money and reports `dub_cross_language_unnamed` (step 3 of `references/dub.md`). A same-language line carries no language cue, and its name follows 「Put the character name first」.

For a dialect, the line itself has to be written in this dialect, not by adding a cue and not by writing pronunciations. Write it in the following two steps:

1. **First find out how this dialect speaks for itself**, and record it in the pack's dubbing guidance (the dialect item of `### 台词` (lines), `references/character-voice.md`「Features of an accent」):
   - its own vocabulary and modal particles (Sichuan dialect `噻`, `巴适得板`, `莫得啥子`, `要得不`);
   - common characters whose pronunciation differs from Mandarin, written as the character that reads with that sound (`去` written as `切`);
   - for a dialect that has its own written form, record that form (Cantonese `我哋`, `今日`, `食饭`, `唔`);
   - how the tones change, whether the end of a sentence rises or falls, rhythm and speed: these may also be recorded, to be used in the short cues of step 2 below, not for spelling out the pronunciation of a whole sentence.

   If you don't know, look it up or ask the user; do not make it up from impressions.
2. **Write the script in this order**:
   - Write the line itself in this dialect: write the line the way a speaker of this dialect would say it, with every clause written the way speakers of this dialect say it themselves (vocabulary, modal particles, sentence patterns), not a Mandarin sentence sprinkled with one or two dialect words (characters with a different pronunciation written as the character that reads with that sound, and modal particles that Mandarin also has, do not count as its own words; why this is required: see the group 2026-11-08 "How densely the dialect is written in the line" below, which is inference). Where the character's materials state that the accent is not strong, follow the materials: use few dialect words and do not fill the line with them: this is the user's requirement, not a reading. Common characters with a different pronunciation are written as the character that reads with that sound (`今天中午我们切吃火锅噻，巴适得板！`); a dialect with its own written form is written in it (Cantonese: `我哋今日去食饭……你去唔去啊？`). Do not write phoneme tags. When the line is in another language (Cantonese) and the reference is not in this language, `dub` stops by default; to dub it, add `--language yue --allow-cross-language` (above).
   - Then use a short cue for the manner of speaking at this spot: written before the words at this spot, two or three words saying how it is said (`[casual, lazy]`); changes in tone, final sounds and rhythm are written the same way (`[rising tone]`, an example of the way of writing, not measured). ## Reference segments

- **How many segments.** 0 to 16 segments. When no speaker marker is written, all the segments are combined into one voice (platform statement).
  - What the inference code does: after each segment is tidied up, the segments are joined in order into one clip with 0.3 seconds between them. If the joined clip is over 20 seconds, it is cut at the quietest point between second 12 and second 20, so what remains can be much shorter than 20 seconds. When it has been cut, the text you supplied is not used; the transcribed text is used instead.
  - One segment versus all the reference segments in the pack: lead, whether the model could tell the difference (another set of measurements from before 2026-11-04); for the reading see the next item.
  - Measured 2026-11-06: one 344-character Chinese narration, one voice, four ways of supplying the reference, 16 seeds each, 64 clips in all, measured by program (voiceprint model, compared with 30 clips of the person's own recording that were not used as references). The four ways: the default segment alone (8 seconds), three segments picked in order (about 20 seconds), the default segment plus the segment most like it, and all 16 segments.
    - Result: all of them produced sound and read the whole text (how this was checked is not recorded), but none was clearly more similar, and none was steadier. The mean for three segments was only 0.04 higher, not significant after correction.
    - Changing the seed makes a much bigger difference: with the same way of supplying the reference, the most similar and the least similar clips differ by 0.14 to 0.23.
    - For the 16-segment case, by the inference code only the first two segments (about 15 seconds) are kept, and each clip takes about twice as long to wait for on the platform.
    - So normally give one segment. Several reference segments work, but do not use them on purpose to get a closer likeness.
- **How long each segment is.** 1 to 20 seconds per segment is appropriate (platform statement). The longer the references and the more segments there are, the less one request can speak (see 「Limits of one request」).
- **Acting style follows the reference (inference; only the cases below were listened to).**
  - First-page audition (above): a reference the character acted themself is clearly better, and the timbre drifts a little.
  - Another set of measurements from before 2026-11-04: the reference was replaced by an original line the character themself had acted, and the model judged whether the acting was good: 20 wins, 4 losses, 16 draws (p≈0.0015). - **Reference text and cue annotation.** Each reference segment can carry its text (platform statement: optional transcript), handed to the model together with that segment.
  - With or without the verbatim transcript: actually tried on 2026-11-01 on scenes with several people, 3 scenes with and 3 without, 2 runs each; all 12 runs produced sound as usual; the two-person scene could be measured line by line, and the speaker similarity was the same on both sides (measured); the transcription was the same on both sides (model judgment, nobody has checked); the three-person scene could not be counted line by line into the conclusion. The acting was not listened to.
  - Cue annotation (marking in the verbatim transcript how each spot in the recording is said): the vendor's only example is the one in 「Good examples」 above, which is marked coarsely (`[normal]`, `[laughs]`, `[happy]`). Making a pack now annotates point by point: in front of each clause, write what the person is like in that clause, where they pause, and whether they speak fast or slow, without changing a single character. Write only what is heard; write nothing for what is not there; do not invent detail for the sake of being detailed.
    - Who does what: a program cuts the audio, transcribes each piece, aligns the transcription to the characters of the verbatim transcript, and measures how long the pause was before each piece and how many characters per second each clause is spoken at. A model that can listen to audio says, clause by clause, the emotion (one or two words chosen from a fixed vocabulary of about 30 words), whether the ending is drawn out or rising, and whether there is laughing, sighing, inhaling, or choking up; it only describes, and does not judge good or bad. The same passage is asked 3 times, and a word for the same clause is used only if it is the same at least 2 times; if no emotion word for a clause reaches 2 times, take the one with the most votes, and on a tie take the first word of the first answer (the ending and the sudden sounds are not filled in this way). The vocabulary (always English, whatever language the line is in): calm, earnest, happy, smug, excited, delighted, surprised, puzzled, hesitant, unsure, sweet, syrupy, sincere, gentle, aggrieved, disappointed, sad, resigned, wistful, sighing, complaining, displeased, sulky, resolute, angry, anxious, afraid, nervous, teasing, sarcastic, proud.
    - Converting to markers:

      | This spot | Written as |
      |---|---|
      | A pause of 0.40 seconds or longer after comma-type punctuation | `[pause]`, written after the punctuation |
      | A pause of 0.20 seconds or longer where there is no punctuation | `[short pause]`, written there; that spot also counts as a clause boundary |
      | End of a sentence | Not written; the end-of-sentence punctuation carries its own pause |
      | Characters per second in the clause at least 1.2 times the median of the whole passage | `[faster]` |
      | Characters per second in the clause at most 0.85 times the median of the whole passage | `[slower]` |
      | Laughing, sighing, inhaling, choking up, heard | `[laughs]`, `[sighs]`, `[inhales]`, `[choked up]`, as a separate cue, written before that character |
      | The emotion of each clause | `[word, word]`, written before the clause; if it is the same as the previous clause and has no ending, it is not written; a drawn-out or rising ending is merged in, for example `[sulky, drawn-out ending]`, `[sulky, rising tone]` |

      Order at one spot: pause, sudden sound, emotion (with ending), fast or slow, all right in front of this clause.
    - Example (one reference segment of a voice speaking Chinese; the characters are as in the original text, the positions of the cues were marked by the program, and the words were replaced by English according to position; the one a person listened to below is this one):

      ```

A failure to measure (no transcription, the audio cannot be decoded, transcription failed, the transcription does not align with the verbatim transcript) does not block annotation: that segment uses only the cues that were heard, and does not write pauses or fast or slow.
    - Listened to by one person: the same Chinese-speaking voice, the same line, the same pack, only the reference text changed; the reference with point-by-point annotation was significantly better than the one without, closer to the voice and also more like a real person. Other voices and other languages were not listened to. The annotation that was listened to was written by hand according to this table (the pauses and fast or slow were worked out by hand from the measured numbers and match the table; two emotion words used near-synonyms, falling endings were not written at all, and for clauses that were both drawn out and rising only one of the two was written), not produced by the program. For Chinese annotated by the program, one person listened over two rounds, and the results were inconsistent: in one round, one scene was clearly better, one voice slightly better, and one narration showed no difference (that one had no pauses or fast or slow measured); in the other round, with the same recording compared three ways, the English annotation (`[cheerful]`, `[laugh]`) came first, no cues second, and the program's Chinese annotation last, the difference being the emotional tone at some points, and on a designed voice swapping the annotation made no great difference. So it is now always written in English (requirement, raised on 2026-11-09 by the author of 「Good examples」 above): for one recording, the annotation is only replaced by English according to position (the example above), and one person listened and said "the spacing is much better". There are very few passages, not enough to draw a conclusion; English annotation marked by the program itself has not been listened to.
    - Reading: for the same pair, the length of the silence in the middle of a sentence is not consistent across 3 seeds. When the reference text is changed, the same seed dubs a completely different clip, so in this reading the difference at this spot cannot be separated from changing the seed.
    - The thresholds (0.40 seconds, 0.20 seconds, 1.2 times, 0.85 times, and the -30 dBFS (the level after the loudness is set to −20 LUFS: at the original level, in a quiet recording the gaps between characters are all taken as pauses) and 0.05 seconds used to measure pauses) were all set from one reference segment of one voice; they are inference and have not been tried on other voices. The sighs, laughs, emotion words, and endings were heard by a model and have not been checked item by item.

## Speaker markers

- Before each speaker's line in the text, write `<|speaker:N|>`, with N starting from 0 and going up to 15 (the tokenizer's own limit, checked in the model-side code on 2026-11-05). Do not write it in the script: when a scene is one request, `dub` works out who each turn belongs to from the script's `[voice:]`, and the adapter writes it as a speaker marker; the character's name is not sent. Source: vendor documentation (names such as `Narrator:` in a script are only for people to read, and are replaced by speaker tags in the request).
- When speaker markers are written, `<|speaker:0|>` uses the first reference segment, `<|speaker:1|>` the second, and so on down, one segment per person. Source: vendor documentation (references correspond to speakers in order); the inference code matches them one to one. The model itself was trained with several reference segments for one speaker (the technical report has an example), but the inference code we read does not expose that way of writing.
- Write each turn's cue after that turn's marker and before the line; square-bracket acting direction, sudden sounds, and paired tags can all be used inside each turn. Source: vendor documentation (Directions and paired tags from this page work inside each turn; example `<|speaker:0|>[calm, measured storyteller voice] The ship had been silent for three days.<|speaker:1|>[low, gravelly, tired but in control] Status report.`); the technical report's example `<|speaker:0|> [whispering] …`. The "storyteller voice" in the vendor example is the name of an identity, so following the first item of 「What to write」 we do not write it this way.
- Starting each turn on a new line is more stable: with two people, a line break was correct 24 times out of 24 and a space 17 out of 24; with four people, a space was correct 2 times out of 12. Source: the 2026-10-29 measurement recorded in a comment in the inference code (that code itself puts each turn on one line; the comment does not say how "correct" was judged, and nobody has checked). In the vendor documentation's example, the turns are joined end to end without line breaks; the two do not conflict.
- One request produces only one audio, with no boundary or timestamp for each turn. Source: platform statement, inference code.
- Reading:
  - 2026-11-01, a two-person scene of 32 lines (measured by this machine's voiceprint model): each line's similarity to the person's own held-out recording is higher than its similarity to the other person's. The three-person scene could not be counted line by line into the conclusion; measured in a sliding window of 1.5 seconds, in each person's own time spans the share of that person is 0.60 to 1.00, and nobody is absent from the whole scene.
  - First-page audition (2026-11-04, one person listening blind, two two-person scenes): in the steady scene, merging into one request made the whole clip smoother, but in the merged version one person's timbre was "not the same person at all" as in the one-line-per-request version; in the emotionally varying scene, one request per line and then joining worked best. Merging may swap out someone's timbre.
  - In one real call on 2026-11-03, the model judge's answer mentioned once that a male voice had been replaced by another male voice; not verified.
  - 2026-11-06, one scene of two people with four lines (two lines each, English), dubbed once as one request for the whole scene and once as one request per line, two seeds; each line was cut out of the finished product and compared with that person's own reference for speaker similarity (measured by this machine's voiceprint model, averaged over the two seeds; independently re-checked). Merged into one request, both people were clearly less like themselves than with one request per line: one person (reference in Japanese, cross-language) 0.29 against 0.67, the other (reference in English, same language) 0.48 against 0.70. ## Pause between lines

The short pause between two lines in one request is written as in the table below. The table gives the silence that comes out between the two lines (milliseconds), the median over several voices and several lines together. The same way of writing varies by a few hundred milliseconds (different voices differ the most), so take it as approximate only. Source: measured, 2026-11-05, measured by program; the method of measuring is below the table.

| How the previous line ends | What to write (attached after the previous line) | Silence that comes out |
|---|---|---|
| No punctuation | Add nothing (Chinese joins directly, English with one space) | about 115 |
| No punctuation | `，` (English `, `) | about 325 |
| No punctuation | `[pause]` (English: one space before and after) | about 780 |
| Punctuation inside the sentence (，、；：) | Add nothing more | about 325 (this is the comma reading above; the dash `——` joining two half-sentences is about 365; in another round on 2026-11-07 it was about 0.13 seconds longer than a comma, see it together with the one in stuttering in 「Punctuation」) |
| Punctuation inside the sentence | `[pause]` (`，[pause]`) | about 730 |
| Punctuation at the end of a sentence (。！？) | Add nothing more | about 605 (Chinese 460 to 840, English 270 to 330) |

- Other ways of writing, measured and not chosen: `[short pause]` about 355; `[停顿]` about 780, but for the same voice across three lines it ranges from 190 to 790; the ellipsis `……` about 670. `……`, `[long pause]`, and adding `……` or `[pause]` after a full stop give a somewhat longer silence (about 0.7 to 0.8 seconds), but they cause the following line to be dropped entirely (only the previous line is in the finished product): `[long pause]` 2 times out of 8, `。[pause]` 2 out of 6, `。……` 1 out of 6, `……` 1 out of 8. The ways of writing in the table have never dropped one.
- Pauses written in square brackets (`[pause]`, `[停顿]`) are not read out: those words are not in the transcription (model judgment, nobody has checked; the transcription itself misses sentences, so take this item only as corroboration).
- In a scene merged from several people, writing the pause at a change of speaker as acting direction (`[停了一下，压低]`, `[沉默片刻]`): inference that the pause is not stable, nobody has listened to it, and the pause was not measured; the lead is that the model mostly judges the pause as not long enough. The readings in the table above were all measured within a line spoken by one person, and for changes of speaker there is only the one scene below. 2026-11-08, a Chinese scene of two people (11 turns), the whole scene as one request, these two cues each written at the start of a turn (followed by `……`), 5 clips dubbed with different seeds; a model that can listen to audio listened to each clip three times and judged whether the cue for that turn was carried out. Over the two spots there were 30 judgments in all: carried out 9 times, partly carried out 14 times, not carried out 7 times; the judgments mostly said that the pause before speaking was not long enough or absent. Item by item: one where both spots were mostly judged carried out; one where only one spot was judged carried out on all three listens; two where both spots were judged not long enough or absent on all three listens; one where the judgments disagreed. Comparison: for the same scene with a revised script, with these two spots changed to acting direction that does not mention a pause, 5 clips were also dubbed, and 3 of 28 judgments said carried out. For the same scene with one request per line and `[pause …]` written at the change of speaker, one clip was judged to have paused on all three listens at both spots. The amount is small and no test was done; what was judged is whether the cue was carried out, and all of it is lead. `dub` does not treat this kind of cue as a pause and hands it to the model as it is (`references/dub.md`「One request per scene」).
- Silence at the start and end of the finished product: median 30 milliseconds, longest 237 milliseconds (86 finished products, one spot at the start and one at the end each).
- Method of measuring: scene3 was run on one platform, one request at a time, not in parallel; the readings use 86 runs (a few trial runs not counted), all of which came back from scene3. Three voices: no reference (the model's own voice) speaking Chinese; and the base part's `lib/adapter-check-voice.wav` (a piece of English) used as the reference, speaking Chinese and speaking English. Three Chinese lines and two English lines, each line in two halves, with the ways of writing above swapped in between, once per way of writing per line. After the finished product is decoded, one frame is 10 milliseconds, and below −40 dBFS counts as silence (the same threshold as the one used to trim silence when joining); the silence between two lines is the longest stretch within 20% of the speech duration on each side of the seam position worked out by character count (at least 50 milliseconds). Clips that dropped the second line were not counted in the median.
- The inference code keeps at most 0.75 seconds of each silence in the finished product; a silence of 4 seconds or more in a row is treated as stuck and is also kept to 0.75 seconds. So a pause longer than 0.75 seconds cannot be written inside one request; for a long pause, cut there and let the joining insert it. Source: inference code (not the model itself).

## Punctuation

The model is sensitive to punctuation (words from the requirement, not a measured conclusion): pauses and durations change with the punctuation, measurable by program; sentence-final pitch is measurable in English, while in Chinese only some sentences showed a consistent difference; emotion is only judged by a model (lead). For the lines you write for it to read, set the punctuation according to the effect you want to hear, not according to written grammar. Source: requirement, raised on 2026-11-07 by the author of 「Good examples」 above, in the words "The model is actually sensitive to punctuation, consider optimizing it. Not for standard grammar, but for the speech effect."

Reading: measured on 2026-11-07, one request per line, lines without cues, only the punctuation changed; 3 designed voices each in Chinese and English, 3 seeds per way of writing, 9 clips, with all 549 clips dubbed successfully. A program measured pauses, durations, and sentence-final pitch; a model judged how it sounded (each clip asked 3 times, taking what 2 of 3 agreed on). If 7 or more of the 9 clips went the same direction it is written "effective", and 5 or 6 is written "weak"; "effective" and "weak" are written only on the basis of what the program measured and what a person listened to; the model-judged sound (hesitant, fast, playful, asking, rising, surprised and so on) is a lead, and the table writes it as "model judgment" as it is; a way of writing with only that is not counted as effective, and a way of writing held up only by it is written as inference. Of these, three pairs were listened to by one person (marked in the table; each pair is the same voice and the same seed with only the punctuation changed); the others have only what the program measured and the model judged.

| Want | Chinese | English | Reading |
|---|---|---|---|
| Take a breath | `，` | `,` | about 0.3 seconds (same as 「Pause between lines」 above) |
| Say it hesitantly | Write `……` between words | `...` | Effective: about 0.2 seconds longer than a comma (about 0.3 seconds in English), measured 8/9; the model judged clearly hesitant, 6/9 in Chinese and 9/9 in English. For excitement or shouting, write a cue.
- `——`: in stuttering one person cannot hear a difference from a comma (table above); a mid-sentence beat (`我觉得——也不是不行`) is about 0.13 seconds longer than a comma (7/9), and the model's judgments of hesitation are scattered (slight 4, clear 3, none 2); placing it before a turn was not tested. For a stable, short beat in one place, use a comma (inference, stability was not compared).
- Interrupted, cut off abruptly: none of the ways tested (Chinese sentence-final `——`, English sentence-final `—`, sentence-final `……`) was detected (the measured duration and sentence end are about the same; whether it was judged cut off abruptly is only model judgment, lead): for Chinese sentence-final `——` the model judged hesitant 8/9 and cut off abruptly 3/9; for English `—` the model judged cut off abruptly 0/9; nobody has listened to it.
- Avoid: an ellipsis in the middle of a word (`秘……密`; the model judged that 2 of 9 times in Chinese the word was broken apart, nobody has checked); Chinese `！！！` (the sentence end is about 2 semitones lower than a single `！`, relative to the median of the whole sentence, 8/9; no difference in duration was detected; in 1 of 9 times an extra sound appeared before the sentence and left 0.8 seconds empty (heard by a model; the report records that it was indeed extra and does not say how it was checked; nobody has listened to it)); English `??` (not detected; the model heard an extra laugh before the sentence in 1 of 9 times, nobody has checked).
- Where there is more speech after an ellipsis, in 72 clips the model judged that 1 dropped the whole following sentence (`I... I didn't lie to you.` read out only the first I, nobody has checked), which looks like the same fault as `……` 1 time out of 8 and `。……` 1 time out of 6 in 「Pause between lines」 above (inference). That clip came out at 0.85 seconds, longer than the length estimated by character count (about 0.75 seconds), so `dub`'s `speech_maybe_unfinished` (reported only when under half the estimate) cannot catch it. So when writing the script, avoid the ways of writing that lose speech (in 「Pause between lines」 above: `……` alone as a pause, `。……`, `。[pause]`, `[long pause]`, and, from the previous item, an ellipsis in the middle of a word); for the `……` wanted for acting, put it between words, though it will occasionally still lose the speech after it, so when handing back, ask the user to listen to the lines where an ellipsis was used (the "Read the report, then hand it back." step of each scene sub-skill). If the user hears that something was lost, redo that segment with `--only <that segment's index>` (for a merged scene it is the whole scene, `references/dub.md`「Failure and redo」).
- When `dub` writes a short pause into a request, it does not treat `～` or `~` as end-of-sentence punctuation (`lib/pause-in-request.mjs`): after a line ending in `～` with `[pause …]` written after it, the request becomes `～，` or `～[pause]`, which was not tested.
- Full-width against half-width: no difference was detected, only one line was tested, and the pause and the time spent saying the characters were the same.
- A very short line (5 characters): whatever is written at its end, 6 of 63 clips were more than 30% longer than other seeds of the same voice, and occasionally had an extra sound (heard by a model, nobody has checked): this looks like a problem of short lines, not of any one punctuation mark (inference, the 6 clips are spread over 5 ways of writing).
- Not tested: how much punctuation still matters when several lines are in one request, in a scene with several people, or in long narration; punctuation used together with cues (`[犹豫]` plus `……`); `吗？`, `呢？`, `；`, `：`, `、`, quotation marks, `!?`, `～` in the middle of a sentence, `？？` written on a line without a question word, `——` before a turn, a stutter written with the enumeration comma (`我、我`); Japanese; voices made from recordings and voices from the library.

## Expressiveness: `drama_value`

A control parameter: the higher the value, the bigger the swings in tone and the wider the variation in how each spot is said, so the more dramatic it is; the lower the value, the steadier it is. Source: requirement, raised on 2026-11-08 by the author of 「Good examples」 above, at 21:13 (UTC+8) in the words "Consider making full use of this parameter to improve expressiveness / fit to the situation / context / timbre and so on. It is a model-level control parameter", and at 21:3x again "the effect is just what the name says, drama value"; platform statement, original text below.

- Scale: see `vocab/capability-signatures.md`. The platform itself writes 0 to 1 with a default of 0.5 (platform statement); the conversion is dividing by 100: the original text quoted below is as it is, and its numbers are not converted. `dub` does not make up a default; for the order in which the value is taken see `references/dub.md`; if there is none, it is not passed, the environment uses its own default, and what it uses is written in the environment adapter's notes.
  - Mapping (the version of the inference code read on 2026-11-02): temperature = 0.8 + 0.4 × value / 100, top_p = 1.0 − 0.2 × value / 100, top_k unlimited. Value = 0 is temperature 0.8, top_p 1.0; value = 50 (the default) is 1.0, 0.9, which is the officially given sampling; value = 100 is 1.2, 0.8.
  - The platform's stated recommendation (original text): `0 to 1, default 0.5. Higher gives more varied intonation, lower a steadier read; the effect is subtle, so use text cues for a clear change. Lean higher (e.g. 0.7-0.8) for dialogue and emotional scenes, lower (e.g. 0.3) for calm narration.` Converted: 0.7-0.8 is 70 to 80, and 0.3 is 30.
  - Parameter sweep at deployment (2026-10-28, measured by program, three seeds, 72 clips per level): as the value goes from 0 to 100, the 5% to 95% range of pitch widens by 0.9 semitones; the share taken by pauses falls from 0.159 to 0.136; the loudness variation falls from 9.76 dB to 9.30 dB, all three roughly monotonic; the error rate and the timbre similarity to the reference stay flat across the levels.
  - Beyond the ends of the mapping (temperature and top_p past the two sets for value = 0 and value = 100): swept only once on 2026-10-28 with seed 1, 24 clips per level, measured by program. Below 0.8 / 1.0 there are more errors, and above 1.2 / 0.8 the timbre drifts (the timbre similarity to the reference drops to 0.31 to 0.42).
  - How it sounds: tested once on 2026-10-30, 0 and 100 each compared with 50, 8 seeds paired, judged by a model. The judge did not pass the trap (a trap is a control with a known answer used to test the judge), so this reading is not used: it can only be read as not detected, not as having no effect. No one has listened with their ears.

### How to choose the value

The value has three layers, each optional, with the later ones overriding the earlier ones: the whole voice's (the top-level `expressiveness` of the manifest, called the global value), the setup's (`setups[i].expressiveness`), and the one at `dub` time. The value finally used for a line is, in order: the `.json` entry's own > `--expressiveness` > the value of the setup used for this line > the pack's global value > if none of these, it is not passed (`dub` has no default of its own). The global value is the value of the whole voice, not a setup: `--no-setup` does not use the setup's value, and the global value is still used. Below, "fixed" means the pack gives a value (the setup's or the global one), and "not fixed" means neither has one. Within a scene, the value does not change. Source: requirement (three layers, later overriding earlier, the global value being the whole voice's value, the value not changing within a scene); for how the order is written, see `references/dub.md`.

When adjusting the value (making a setup, helping the user tune, declaring it yourself at `dub` time), move it up or down by about 10 from the value of the layer above: when making a setup start from the global value, and at `dub` time start from the value the pack gives. If there is no value in the layer above (the pack gives nothing at all), follow the "A voice with no fixed value" item below. Source: requirement (move by about 10).

For a designed voice or a voice from the voice library, for the acted passage dubbed for it (`references/make-pack.md`「Making a pack from a designed voice」step 2): take the value according to this character, not one fixed number: look at whether this character's usual speech has big swings and what emotion this passage acts, then start from the approach in the "A voice with no fixed value" item. It covers only this passage and is not written into the pack's global value; the same value is written into the default preset when making the pack (`references/make-pack.md` step 3), and is used afterward when dubbing and the audition line are given no expressiveness. Which value is better has not been compared. Source: requirement, the author of 「Good examples」 above said on 2026-11-10 "Drama cannot be hard-coded. It still has to be tuned per character, the preset included, and a value that fits the character needs to be tuned out first.", replacing the fixed 80 that this passage used to say; carrying this value into the default preset is also a requirement of the same day.

- The voice's setup has the value fixed (the manifest's `setups`, the user tuned it for this setup), or the whole voice has a global value (the manifest's top-level `expressiveness`): every line follows it, a script's defaults do not give another one, and `dub` uses the value the pack gives (`references/dub.md`). Giving another needs a reason; the other value moves by about 10 from the value the pack gives. When making a setup, do not declare a value by default, and declare one only when this setup really has to differ from the global value (for example, furious); the set of presets with `default` when making a pack is the exception, and it carries a value that fits the character (the item above). Source: requirement, the author of 「Good examples」 above said on 2026-11-08 23:2x (UTC+8) "every line follows this"; not giving another by default, giving another needing a reason, and not declaring in a setup by default are requirements; the exception of the default preset carrying a value is a requirement of 2026-11-10.
- A voice with no fixed value: do not hard-code a starting point, and do not give a default. The starting point is set by the person writing the script according to this character and the situation at this spot (whether the character's usual speech has big swings, whether this spot is dialogue, an emotional scene, or calm narration), given with `--expressiveness` when dubbing and with `--card-line-expressiveness` for the audition line; then adjust carefully from there: move up and down in small steps according to the situation at this spot, about 10 per step, and do not jump to the extremes at once. The platform's stated default is 50 (above), which is a fact about the platform and is not taken as the starting point here; the platform's stated recommendation (70 to 80 for dialogue and emotional scenes, 30 for calm narration) is only a statement and has not been compared. If the user fixed the value, follow the item above. Source: starting from the character and not hard-coding is a requirement, the author of 「Good examples」 above said on 2026-11-10 "Drama cannot be hard-coded. It still has to be tuned per character", replacing the default 70 written before; adjusting in small steps is a requirement, the author of 「Good examples」 above said on 2026-11-09 00:1x (UTC+8) "Can the drama value be adjusted carefully?"; about 10 per step is a requirement.
  - Then adjust up or down according to the situation at this spot, the surrounding context, and this voice's timbre: the more intense the scene, the higher; the calmer, the lower; within a scene the value does not change. Different scenes need different values, and in a `.json` script each entry writes its own (`references/dub.md`). Source: giving the value by situation, context, and timbre is a requirement, the sentence of 2026-11-08 21:13 (UTC+8) quoted above; which direction to adjust, by how much, and how to keep it coherent across what comes before and after are inference, not tested.
  - Timbre (inference, not tested): for a voice that is steady and cool by itself, to act out swings you can take a higher value. The deployment sweep within 0 to 100 did not lower the timbre similarity to the reference (the reading above), so there is no need to press it down in order to keep the timbre. Outside 0 to 100 it goes out of shape ("Beyond the ends of the mapping" above), and `dub` does not accept it either.
  - Division of labor with cues: a cue writes how this spot is said (the 「Cues」 section), and this value governs how dramatically the whole passage is acted. Give both. Source: the platform statement says the effect of this value is subtle, and for a clear change you rely on the cues in the text (the recommendation quoted above: `the effect is subtle, so use text cues for a clear change`); giving both is a requirement, the sentence of 2026-11-06 quoted at the start of the 「Cues」 section, and the sentence of 2026-11-08 21:13 (UTC+8) above; how much better using both together is than using one alone has not been tested.
- In one `dub` where some voices are fixed and some are not: do not use `--expressiveness`, since it overrides the setup's value on every line and would change the fixed voice too. Use a `.json` script and write `expressiveness` only on the entries of the voices that are not fixed, and do not write it on the entries of the fixed voices (do not mix the words of a fixed voice into one entry); they then follow their setups (where a setup gives no value, the global value). The whole voice's global value is overridden in the same way. Which voice is fixed, what it is fixed at, and whether it is the setup's or the global one can be seen in the plan of `--dry-run` (`pack.expressiveness`, and for several packs `packs[i].expressiveness`, which is `{ value, from }`, where `from` is `setup` or `global`; it costs nothing). When several voices have different values, lines with different values are not merged into the same request (`references/dub.md`「One request per scene」); to merge them, explicitly give one value when you `dub` (`--expressiveness`, used for every line), and do not take an average. Source: the order in which `dub` takes the value, `references/dub.md`; lines with different values not entering the same request, explicitly giving one value to merge, and not taking an average are requirements.

## Sampling: `seed`

- `seed`: the same seed and the same input should give the same result as far as possible (platform statement). Measured on the dev platform, two sets of runs. First: the same request with the same seed gave more than one clip: one request at seed 1 gave two different clips (pitch 215 Hz and 119 Hz); 18 requests resent one by one all gave clips different from the ones made for the same requests earlier; of 45 pairs of the same request sent in two batches at different times, 25 pairs were identical sample by sample; it could not be told what decides which clip comes back (a request sent alone also gave the 119 Hz one). Second: one case (seeds 1 to 3) was run in three rounds, once while 7 cases ran at the same time and twice alone, and the decoded audio of every clip was identical in all three rounds; only this case was run this way. Whether using the same seed for the several pieces cut from a long text makes the pieces closer to each other: not tested.

## Limits of one request

- **Dubbing defaults to about 1000 characters per request.** By default `dub` keeps one request to no more than about 1000 characters (what is to be read; cues and tag names are not counted, consecutive whitespace counts as one, English about 170 words, for how it is counted see `references/dub.md`「How long text is split」); anything over is cut at paragraph, change-of-speaker, and sentence boundaries, and within each request the merging is done as usual, the same for narration and for a scene with several people. This is the default way dubbing is cut, not the model's limit: the model can fit much more into one request (the items below). Source: requirement, raised on 2026-11-06 by the author of 「Good examples」 above, in the words "In the skill, set a soft limit: anything over 1000 is split into segments, not one line at a time." The cause was that she listened to an English narration (2763 characters counting spaces, dubbed in two requests) and said of the second half "the timbre is not great. It seems to have suddenly changed." Whether 1000 is better than other numbers was not tested and it was decided not to test it, in her words "no need to test this, just set it like that"; the reading in 「Speaker markers」 for the 2026-11-06 two-person scene compares merged against separate, and that scene was far under 1000 characters and is not the basis for this number.
- There is no fixed limit on the number of characters. There used to be a limit of 900 characters, removed on 2026-10-29; now 400 is returned only when "one request cannot hold it" (checked in the model-side code on 2026-11-05).
- Speaker numbers 0 to 15 and at most 16 reference segments: the tokenizer's own limit (same as above).
- Whether it fits: the prompt (the system turn, the frames of each reference segment, the text) and the speech to be generated share 32768 positions, and at most 18950 frames are generated (about 14.7 minutes). When the prompt takes no more than about 3700 positions, the limit is 18950 frames; when the prompt is longer, fewer positions are left and the limit drops to "32768 minus the prompt". Calculated with the longest prompt, it is about 14365 frames (about 11.1 minutes). So the longer and more numerous the references and the longer the text, the less one request can speak; this is not a fixed number. Source: the version of the inference code read on 2026-11-02 (the comment records a measurement of 2026-10-29), in which there is also no character limit, matching the check of 2026-11-05; the platform statement says "at most about 14 minutes per request".
- When it does not fit, 400 is returned, with the exact words being one of the two below (inference code, the version read on 2026-11-02). The second is reported only after generating up to the limit and is not blocked in advance.
  - `the text and references are too long for one request: they leave no room for speech; split the text into several requests, or send fewer or shorter references`
  - `the speech for this text did not fit one request, which can speak at most {frames} frames, about {minutes:.1f} minutes, with this text and these references; split the text into several requests`
- Measured (2026-11-05: requests spoken by one person, the text one paragraph per line, with line breaks between paragraphs; whether it was finished was checked by comparing the transcription with the original text (model transcription, nobody has checked; a transcription can only be shorter than what was spoken), then looking at the length of the audio). Each length was measured only once or twice, and the edge is not an exact number:
  - With one 19.5-second reference segment: 2906 Chinese characters were finished (11.3 minutes); 3014 characters failed both times: once it stopped after reading to character 1316 (audio 5.1 minutes), and once the task did not finish running (a failure reported by the platform, see the platform's adapter). 10644 English characters were finished (12.5 minutes): the text was only written this long, and the English edge was not reached.
  - With three reference segments, 50.2 seconds in all: 2734 Chinese characters were finished (10 minutes), and 2906 characters stopped after only the first 98 characters (21 seconds); 8621 English characters were finished (8.5 minutes), and 10025 stopped after reaching character 5549 (6 minutes).
  - None of the runs that went over returned the 400 above: they stopped without finishing and gave no error, which can be seen only from the length of the audio and the transcription.
  - A text with a large repeated part (a 730-character text joined more than twice, with only "第二天，" and "第三天，" added at the start of the second and third passes) stopped earlier: 1620 characters were not finished either time, once stopping after the first pass (3 minutes) and once after reaching line 3 of the second pass (3.6 minutes); 1610 characters without repetition were finished.
  - Speaking speed: Chinese 4.2 to 4.7 characters per second; English with one reference segment 14.2 to 15.3 characters per second, and in the three-segment run 17 per second (spoken by the references above; with other references it will differ).
- For the time limit that the platform adds in front of the model, see the platform's adapter.

## Breathy voice, whispering and gasping

The things adult content (`scenes/nsfw.md`) uses most: whispering, breathy voice, gasping. Below is a set of measurements from 2026-11-12, some of which were made to check statements read elsewhere earlier and never checked: that whispering paired tags, ellipses at the end of a sentence, and very high expressiveness (0.94 and above) swallow half a sentence or run words together; that a comma every two or three characters makes it stop and start on every character; and that `<soft>` cannot produce a breathy voice.

Method of measuring: one voice from a voice library (an adult female character, the reference being a 9.1-second piece of Chinese spoken calmly), one ordinary Chinese line (two sentences, 33 characters, starting with `[calm, gentle]`), one clip per way of writing for each of seeds 1, 2, and 3, expressiveness 70, except where stated otherwise; dubbed through `dub`, and the model that came back on the platform was this one. Measured by program: the finished product is cut into 10-millisecond frames, and below −40 dBFS for 0.15 seconds or more counts as one silence; what share of the audible frames have a fundamental frequency (the voiced share, the lower the more like whispering or breathy voice); H1-H2, CPPS; each block cut by the silences was computed separately. Whether words were swallowed was judged with this machine's small transcription model (model judgment, nobody has checked). Nobody has listened to this set. Only one voice and one line, so the sample is small.

- **Swallowed half-sentences and run-together words: not measured.** Wrapping the whole line, one sentence, or half a sentence in `<whisper>`, acting direction `[whispering]`, `……` written at the end of two sentences (`我在窗边坐了很久……你回来的时候……别弄湿了地板……`), expressiveness 95 and 100, and the three stacked together (expressiveness 95, the whole line wrapped in `<whisper>`, `……` at the two sentence ends), 24 clips in all: the characters are all in the transcription, and only individual characters are wrong (`窗` transcribed as `床`, the opening `今天` transcribed wrongly, which also happens in one clip of the comparison where none of these is written); whole sentence 7.6 to 10.5 seconds, against 8.0 to 9.3 seconds for the three where none is written; silences at 3 to 4 spots, against 4 to 5 spots where none is written.
- **Whispering: not pushed down on this voice.** Wrapping one sentence (`<whisper>今天的雨下了一整天，我在窗边坐了很久。</whisper>`, with no acting direction before it), half a sentence, the whole line, and acting direction `[whispering]`: in the wrapped block (for unwrapped, the whole sentence is looked at) the voiced share is 0.60 to 0.87, against 0.62 to 0.95 where none is written; the loudness difference is 0 to 5 dB. This does not match the English item in 「Paired tags」 (the voiced part falling from 54% to 22%); whether the cause is the language, the voice, or the reference was not tested separately.
- **`<soft>`, `[breathy, soft]`: breathiness did not measurably increase.** Wrapping the whole line in `<soft>`: 2 of 3 clips are the same as where none is written (voiced share 0.79, 0.79, against 0.76 to 0.77 where none is written; H1-H2 12.4, 13.1 dB, against 12.2 to 13.1; CPPS 5.41, 5.68, against 5.34 to 5.61); 1 clip was about 6 dB softer, with voiced share 0.68 and H1-H2 14.6. Acting direction `[breathy, soft]` in place of `[calm, gentle]`: voiced share 0.75 to 0.79 and CPPS 5.43 to 5.57, the same as where none is written; H1-H2 15.2 dB in one clip and 12.7, 12.8 in the other two.
- **A comma every two or three characters: stop-and-go.** With the same characters but the commas changed to one every two or three characters (`今天的雨，下了，一整天，我在，窗边，坐了，很久。……`): whole sentence 13.2, 18.4, 18.3 seconds, which compared at the same seed is 1.7 to 2.2 times the one where none is written; silences at 11, 13, 15 spots (4 to 5 where none is written), totaling 2.8, 7.9, 7.6 seconds (2.2 to 3.1 seconds where none is written); with the silences removed, the speaking time is also longer. The characters are all there (transcription).
- **Gasping: 2 of 3 produced long stretches of breath sound.** Another ordinary line: `[breathless, panting]我一路跑过来的，[shaky breath]等我一下，[panting]让我喘口气。`: 2 clips have voiced share 0.49 and 0.42, with 63 and 67 per minute of audible segments with no fundamental frequency of 0.15 seconds or more; 1 clip has voiced share 0.95 and no such segment at all, and its whole sentence is also short (3.6 seconds, against 5.0 and 5.5 seconds for the other two). The characters differ from the line above, so it is not a comparison on the same line; whether what came out is an audible gasp has not been listened to by anyone.
